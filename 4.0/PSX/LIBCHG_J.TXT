ライブラリバグ情報および使用上の注意
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
・libcd において、CdRead()を発行する前に必ずCdlSetlocを発行して、読みだ
  し位置を確定して下さい。何も設定せずにCdRead()を連続的に発行しても
  必ずしも連続的に過不足なくデータを読み出せるとは限りません。

・今回の libds のリリースより、libcd.lib を使う場合にも libds.lib が必要
  になりますので、libds.lib も必ずリンクして下さい。 
  なお、今回の psyq.ini ではこの対応が取られています。

・libgs において、GsSortObject4J の下位関数に GsA4div を使用して分割を
  行なった場合、attribute に設定された TMD の半透明情報が反映されませ
  ん。半透明を利用する場合は、TMD データに含まれる半透明フラグを ON 
  にして下さい。これは関数の仕様によるもので、変更の予定はありません。

・libgte の VectorNormal,VectorNormalS において、v0 の各成分の下位 
  16bit を符号つき 16bit 整数として切りだしたものの 2 乗和が 2^31-1 を
  超えるとオーバーフロー例外を発生します。これは関数の仕様によるもので、
  変更の予定はありません。

・libgte の VectorNormalSS において、v0 の成分の 2 乗和が 2^31-1 を超
  えるとオーバーフロー例外を発生し、正しく計算出来ません。
  これは関数の仕様によるもので、変更の予定はありません。

・libgun においてバッファに格納される水平方向のカウンタ値は、システ
  ムクロックの値で、H-BLANK毎にクリアされています。実際に利用する場合
  は、画面サイズに対応した補整をかけて下さい。

・libsnd において、SEQ の NRPN データによる MIDI チャンネル毎のリバー
  ブの ON/OFF は、サポートされていません。このような動作をさせたい場合
  は、 VAB の中にリバーブ有り・無しのプログラムを用意し、それを切り替
  えて使って下さい（違う楽器として用意して下さい）。ただしこの方法は、
  VH が増えてメモリを圧迫してしまいますが、リバーブ ON/OFF をする音色
  の種類が少ない場合は有効です。これは関数の仕様によるもので、変更の予
  定はありません。

・libsnd において、SEQ などでノイズ音源を利用すると、予期しない場面で
  ノイズが発生してしまうことがあります。ノイズを利用する場合は、プロ
  グラマツール(PC)上で libspu/libsnd の関数を直接利用するか、ノイズ音
  自体をサンプリングし、通常の波形と同様に扱って下さい。
  これは次回リリースで修正予定です。

##関数の追加
~~~~~~~~~~~~
・高速メモリ管理関数群の追加

これまで、メモリ管理関数には、ROMルーチン版(malloc系)とオンメモリ版 
(malloc2系)の２系統が存在しました。今回、高速オンメモリ版として以下の
関数を追加しました。

	      InitHeap3
	      malloc3
	      calloc3
	      realloc3
	      free3

malloc系には「freeで完全に領域が開放されない」というバグがありますが、
ROM ルーチンなので修正ができず、互換性維持の為に残しているものです。ま
た、malloc2 系は速度の面で改善の余地がありました。
今回、malloc3系を加え、メモリ管理関数は 3 系統になります。以下に一覧を
挙げます。

  -----------------------------------------------------------
   名称                      LIBAPI所属     LIBC/C2所属
  -----------------------------------------------------------
   ROMルーチン呼びだし版     InitHeap()     malloc()
   (malloc系)                               realloc()
                                            calloc()
                                            free()
  -----------------------------------------------------------
   オンメモリ動作版          InitHeap2()
   (malloc2系)               malloc2()
                             realloc2()
                             calloc2()
                             free2()
  -----------------------------------------------------------
   高速オンメモリ動作版      InitHeap3()
   (malloc3系)               malloc3()
                             realloc3()
                             calloc3()
                             free3()
  -----------------------------------------------------------

また、3 系統のメモリ管理関数のパフォーマンス比較の目安は、以下のように
なります。

     速度   |  遅い ---------------------  速い
   サイズ   |
  -----------------------------------------------------------
   大きい   | malloc2系
            |
      |     |                        malloc3系
            |
   小さい   |            malloc系


以下の関数の詳細については、関数リファレンスを参照して下さい。

        InitHeap3       ヒープ領域の初期化
        malloc3         主記憶を割り当てる
        calloc3         主記憶を割り当てる
        realloc3        ヒープメモリの割り当てを変更する
        free3           割り当て済みのメモリブロックを開放する


##ライブラリのバグフィクス
~~~~~~~~~~~~~~~~~~~~~~~~~~
・format 関数の以下の不具合を修正しました。

	1)format 関数実行途中にメモリカードが抜かれた場合でも正常終了
          の戻り値を返していた。

	2)format 関数実行途中に抜かれた、初期化の未完全なメモリカード
          が _card_load 関数などで「初期化済み」のカードと判断されてい
          た。

・Release 3.7 で libapi に追加された realloc2() において、「realloc2()
  をした後で、malloc2() を呼ぶとハングする場合がある」という不具合があり
  ましたが、これを修正しました。

##ヘッダファイルの修正
~~~~~~~~~~~~~~~~~~~~~~
・kernel.h 中で EnterCriticalSection()が void として宣言されていました
  が、実際には EnterCriticalSection() 呼び出し時にすでにクリティカルセ
  クションに入っていたかどうかが戻り値として返るので、宣言を int に変
  更しました。

##ファイルの追加
~~~~~~~~~~~~~~~~
・psx/lib に、noheap.obj を追加しました。noheap.obj は、2mbyte.obj等と
  同様、スタートアップルーチンの代替 OBJ ですが、起動時に InitHeap() 
  をコールしません。その他の動作は通常と変わりません。
 「main 関数より以前にヒープ領域が設定される」事に不都合がある場合に 
  noheap.obj をリンクして下さい。
  尚、スタートアップルーチンについて最新の情報をまとめましたので、詳し
  くは以下を参考にして下さい。


＜スタートアップルーチンについて＞       
ここでは、LIBSN.LIB に含まれるスタートアップルーチンの動作と、各代替 
OBJ noheap.obj, 2mbyte.obj, 8mbyte.obj, none2.obj, none3.obj の説明を
行ないます。

ライブラリ Release 3.1 以前の libsn.lib には一部問題があり、スタート
アップルーチンの代わりにリンクする代替OBJが必要でした。それが 2mbyte.obj,
8mbyte.obj です。

Release 3.1 以降では 2mbyte.obj, 8mbyte.obj は特に必要ありません。
Release 3.1 以降では2 つの変数、 _ramsize と _stacksize をプログラム中で
以下のように定義することによって、SP初期値や起動時のヒープ領域を設定でき
ます。 ただし、これら2つの変数を定義する場合は、必ず 両方の変数を定義して
下さい。どちらか片方のみを定義すると、リンク時にエラーが発生します。

    int _ramsize = 0x00200000;      /* RAM SIZE */
    int _stacksize = 0x00008000;    /* STACK SIZE */

上の定義では、

    SP初期値      0x801ffff8
    ヒープ領域    bssセクションの直後から 0x801f8000 までを確保

となります。また、Exec() や LoadExec() で起動する子プログラム用のスター
トアップルーチンとして、none2.obj, none3.obj を配布しています。子プロ
グラム用のスタートアップルーチンは、SPの設定を行ないません。これは、子
プログラムのSP初期値を、親プログラム側から LoadExec() の引数等によって
設定できるようにする為です。none2.obj は、sbss,bss領域のクリアを行なわ
ない為、 Release 3.7 で削除されました。none3.obj を使用して下さい。

以下、スタートアップルーチンのデフォルト動作と、各代替OBJをリンクした
場合の動作を挙げます。

<A>デフォルトの動作
	1. sbss, bss 領域をゼロクリアする。
	2. SP 初期値をセットする。
	   ( ( _ramsize - 8 ) | 0x80000000 )  の値がセットされる。
	   プログラム中で _ramsize を定義していない場合は、
	   _ramsize としてデフォルト値 0x00800000 が使用されるので、
	   SP 初期値は 0x807ffff8 となる。
	3. GP 初期値をセットする。
	   sdata セクションの最初のアドレスがセットされる。
	4. InitHeap() をする。
	   bss 領域の直後のアドレスから、( _ramsize - _stacksize ) のア
           ドレスまでをヒープ領域に設定する。
          （この時、ヒープ領域の一部にメモリ管理情報が書き込まれます）
           尚、プログラム中で _stacksize を定義していない場合は、
	   _stacksize としてデフォルト値 0x00008000 が使用される。
	5. main 関数にジャンプする。

<B>noheap.obj をリンクした場合の動作
	<A> のデフォルト動作とほぼ同じだが、4. の InitHeap() を行なわ
        ない。

<C> 2mbyte.obj をリンクした場合の動作
	1. sbss, bss 領域をゼロクリアする。
	2. SP 初期値をセットする。_ramsize は 0x00200000 に固定。
	3. GP 初期値をセットする。sdata セクションの最初のアドレスがセッ
           トされる。
	4. InitHeap() をする。_stacksize は 0x00008000 に固定。
	5. main 関数にジャンプする。

<D>8mbyte.obj をリンクした場合の動作
	1. sbss, bss 領域をゼロクリアする。
	2. SP 初期値をセットする。_ramsize は 0x00800000 に固定。
	3. GP 初期値をセットする。sdata セクションの最初のアドレスがセッ
           トされる。
	4. InitHeap() をする。_stacksize は 0x00008000 に固定。
	5. main 関数にジャンプする。

<E>none2.obj をリンクした場合の動作
	1. GP 初期値をセットする。sdata セクションの最初のアドレスがセッ
           トされる。
	2. main 関数にジャンプする。

<F>none3.obj をリンクした場合の動作
	1. sbss, bss 領域をゼロクリアする。
	2. GP 初期値をセットする。sdataセクションの最初のアドレスがセッ
           トされる。
	3. main 関数にジャンプする。
