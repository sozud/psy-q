                                                     Psy-Q Programmer's Guide

 1 プログラムの構造化
======================

  メモリを構造的編成したロケータブルなプログラムセクションを作成するには、グ
  ループ及びセクションの概念を用います。

 1 ディレクティブ
------------------

    
=============================================================================
GROUP                                                        [ディレクティブ]
=============================================================================
        
[書式]
        <GroupName>	GROUP	[Attribute][,Attribute]...
        
[解説]
        最大７つの属性を持つグループ GroupName を宣言します。
        Attribute には、次の何れかを指定します。
        
        +------------+-------------------------------------------------+
        |属性         内容                                             |
        |BSS          初期化されていないデータのグループ。このグループ |
        |             では、初期化したデータは宣言しないでください。   |
        |             【例】                                           |
        |             Group1    group     bss                          |
        |ORG(address) グループの ORG アドレスを、他のグループのアドレ  |
        |             スを参照せずにaddress に設定します。この属性が省 |
        |             略されると、グループは直前のグループの後に続くメ |
        |             モリに配置されます。                             |
        |             【例】G1,G2,G3 の順序で配置します。              |
        |                     org    $100                              |
        |             G1     group                                     |
        |             G2     group  org($400)                          |
        |             G3     group                                     |
        |FILE("name") グループそれ自身、例えばオーバーレイのようなもの |
        |             を、バイナリファイルとしてname に出力します。    |
        |             name はダブルクォートで囲みます。他のグループ    |
        |             は、宣言されたファイルに出力されます。           |
        |             【例】                                           |
        |             Group1     group    org($400),file("charov.bin") |
        |OBJ(address) グループの OBJ アドレスを address に設定しま     |
        |             す。コードは、それがあたかも OBJ アドレスで実行  |
        |             されているかのようにアセンブルされますが、グルー |
        |             プのORG アドレスに配置されます。address が指定   |
        |             されていない場合、OBJ 値は、グループの ORG ア    |
        |             ドレスと同じになります。                         |
        |             【例】                                           |
        |             Group1     group    org($400),obj($1000)         |
        |             Group2     group    org($800).obj()              |
        |SIZE(size)   グループの最大許容サイズを size に設定します。グ |
        |             ループのサイズが指定したサイズを超える場合、エラ |
        |             ーが発生します。                                 |
        |             【例】                                           |
        |             Group1     group    size(32768)                  |
        |OVER(name)   このグループを name で指定したグループにオーバ   |
        |             レイします。２番目のグループの開始位置のコード   |
        |             は、最初のグループの開始アドレスと同じアドレスで |
        |             アセンブルされます。オーバレイされたグループの最 |
        |             大のサイズが、各グループのサイズとして使用されま |
        |             す。オーバーレイ毎に別々のファイルを出力するに   |
        |             は、FILE 属性を使用する必要があります。          |
        |             【例】                                           |
        |             Group2     group    over(Group1)                 |
        +------------+-------------------------------------------------+
        
[参照]
        SECTION

=============================================================================
 SECTION                                                     [ディレクティブ]
=============================================================================
        
[書式]
        		SECTION[size]	<SectionName>[,Group]
        <SectionName>	SECTION[size]	[Attribute][,Attribute]...
        
[解説]
        論理コードセクション SectionName を宣言します。
        size には、"b"、"h"、または"w"のいずれかを指定します。size を省略した
        場合、デフォルトのサイズはワードになります。
        グループ名 Group が省略された場合、それが前もって指定されていない限り、
        そのセクションは名前のないデフォルトグループに配置されます。
        また、２番目のフォーマットを使用することにより、そのセクションをグル
        ープ属性付きで定義することが可能です。アセンブラは、自動的に、セクシ
        ョン名の先頭に"~"（チルド）が付いた名前のグループを作成し、そこにセク
        ションを配置します。
        
[参照]
        GROUP
        
[備考]
        size が指定された場合、そのサイズへのアラインメントは、その位置で強制
        的に実行されます。セクションの開始は、リンクされたコードの場合、すべ
        てのモジュールにおけるそのセクションへのエントリの最大サイズに基づく
        境界に配置されます。
        セクションのサイズがバイト単位の場合、そのセクションで EVEN 命令を実
        行することはできません。また、CNOP 命令を使い、プログラムカウンタをそ
        のセクションのアラインメント値より大きい値に配置することはできません。
        セクションが、アプリケーションコードを構造化するために使用される場合、
        ORG 命令はすべてのセクションの定義に先行して、１回に限って使用できま
        す。グループ及びセクションを配置するには、ORG 属性が必要となります。
        リンク可能なオブジェクトを出力する場合、ORG ディレクティブ、ORG 属性
        を使用することはできません。この場合セクションは、グループ内で、リン
        カがセクション定義を発見した順に並べられます。
        
[事例]
        次の例は BSS 属性をもつ Sect1 を、~Sect1 グループ内に定義します。

    例１

        Sect1	section	bss
        また、例２は、ターゲットメモリを構造化するためにグループ及びセクショ
        ンを使用した例です。
         ・予備バージョンのチェックと、インクルード
         ・グループ宣言
         ・プログラムの開始時の変数のセクションで、絶対アドレスモードを利用す
           る
         ・アプリケーションコードのセクション
         ・未初期化データのセクション

    例２

        		opt	c-,ow+,oz+,v+
        version		equ 	0    	;0=>full version
        				;1=>demo version
        				;2=>test version
        		include	"miscmac.obj"
        		include	"rooms.obj"
        		include	"output.obj"
        		org	$100
        numvecs		equ	$100>>2
        		regs	pc=progstart
        		if	~def(amiga)
        amiga		equ	1
        		endif
        		if     ~def(ntsc)
        ntsc		equ	1
        		endif
        g_short		group	word
        g_code		group   
        g_bss		group	bss
        		section	short1,g_short
        		section	short2,g_short
        		section	shortcode,g_short
        		section	code,g_code
        		section	bss,g_bss
        firstbss	equ	*

=============================================================================
 PUSHS、POPS                                                 [ディレクティブ]
=============================================================================
        
[書式]
        PUSHS
        POPS
        
[解説]
        これらの命令を利用することにより、新たな一時セクションをオープンし、
        続いて元のセクションに戻ることができます。PUSHS で現行セクションを保
        存し、POPS でこれを復元します。
        
[例]
        この例は、システム情報を、ロケーションカウンタの形式で、セクション間
        で引き渡しするために、PUSHS と POPS を使用する例を示しています。

    例

        plotcomp	lw	r3,8(a0)
        		...
        passdl		equ	*
        		pushs
        		section	dolight
        		dw	passdl
        		...
        		pops

=============================================================================
 SECT、OFFSET                                                [ディレクティブ]
=============================================================================
        
[書式]
        SECT	(expression)
        OFFSET	(expression)
        
[解説]
        SECT は、カッコ内のシンボルが定義されているセクションのアドレスを返し
        ます。
        OFFSET は、ホストセクションにおける、カッコ内のシンボルの位置を返しま
        す。
        
[備考]
        リンクが実行されている場合、SECT はリンク時に評価されます。リンクが行
        なわれない場合は、２回目のパスが終了したときに評価されます。
        リンクが実行されている場合、OFFSET はリンク時に評価されます。リンクが
        行なわれない場合は、最初のパスの最中に評価されます。
        
[例]
        dh	sect(Table1)
        dh	sect(Table2)
        dh	offset(*)
