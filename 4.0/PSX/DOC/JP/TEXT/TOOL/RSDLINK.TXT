                                                   PlayStation Data Converter

rsdlink 
---------


 1 概要

    アーティスト向け３Ｄモデリングデータファイル(RSDファイル)を、libgsで扱え
    る３Ｄモデリングデータファイル(TMDファイル)に変換します。
    DOS版とSGI版があります。ここでは、1996/Apr/1付けの Version 3.7 に関する内
    容を記述しています。

 2 使い方


    rsdlink [options] rsd-names ...


    rsdlink [options] rsd-names [options] rsd-names [options] ....


    rsdlink [options] arg-files ...


    rsdlink [options] prj-file

    
      引数として指定した複数のRSDデータをリンクして１つのTMDファイルを作成し
      ます。各RSDデータ毎に倍率と平行移動量を設定することができます(例１参照)。
       
      引数のRSD名がパスを含まない場合、まず現在のディレクトリ(.\)を探し、次に
       .\RSD ディレクトリを探します。
      引数が多くなる場合など、引数をファイル(*.arg)に書いて与えることが可能で
      す。RSDファイル名の".rsd"は省略可能ですが、引数ファイル名の".arg"は省略
      できません(例２参照)。
      同様にプロジェクトファイル(*.prj)を直接与えることができます。この場合は、
      プロジェクトファイル中のRSDをすべて引数で与えた場合と同じになります。同
      時に-id オプションが指定されたとみなします。".prj"は省略できません。

 3 オプション


    -o  file-name

      出力ファイル名を指定します。デフォルトは"a.tmd"です。

    -s  factorまたは -sc factor

      次の引数以降(*)のRSDデータを拡大縮小します。
      倍率は２のn乗に丸められます。デフォルトは1.0です。TMDフォーマットでは座
      標値は16bit整数であるため、この座標系におさまるように、適当な倍率を設定
      しなければなりません。

    -t  x y z

      次の引数以降(*)のRSDデータの座標値を平行移動します。デフォルトは(0 0 0)
      です。

    -id PRJ-file

      モデリングデータを管理するプロジェクトファイル(model.prj)を指定すると、
      TMDファイル中に生成される各オブジェクトに対してオブジェクトID番号の配列
      を作成します。結果はC言語のヘッダファイルとして現在のディレクトリに作成
      されます。出力ファイル名はTMDファイル名の拡張子を".h"にしたものです(例
      ３参照)。

    -info

      変換中のオブジェクトの種類や頂点座標値、テクスチャ情報などの非常に詳細
      な情報を標準出力に出力します(例５参照)。

    -v

      ポリゴン数など変換に関する詳細な情報を標準出力に出力します。また、各RSD
      毎に、PS-X座標系におけるおおよその大きさ("Range : 頂点(x, y, z)の最小値
      -最大値")も出力されますので、ターゲットボックスで表示する前に、位置や大
      きさを確認することができます(例４参照)。
      
      (*)注意 -s および -t は、再度指定されない限りそれ以降に現れるRSDすべて
      に対して有効です。

 4 前バージョン(ver.3.65)からの主な改良点

         ・より多くのRSDをリンクできるようになりました。これまでは500RSD程度を
           上限としていましたが、現在はメモリの許す限りリンク可能です。DOS版
           の場合、コンベンショナルメモリの空き容量によりますが、2000RSD程度
           まで可能です。
         ・RSDファイル中に記述されたファイルが見つからない場合、まずファイル名
           をすべて大文字に変換して探します。それでも見つからない場合、すべて
           小文字に変換して探します(SGI版のみ)。

 5 制約

    現バージョンは以下の制約を持っています。
    
         ・１つのRSDデータのポリゴン数が非常に多いとき、リンクできないことがあ
           ります。ポリゴン数の上限値は、頂点数や法線数、空きメモリの容量によ
           っても変わりますが、約5000ポリゴンとお考えください(DOS版のみ)。但
           し、この制限は「１つのRSD」に対してのみ存在し、リンクするRSDの数、
           生成されるTMD全体のポリゴン数には実用上制限はありません。
         ・プロジェクトファイル中に現れないRSDをリンクすると、ヘッダファイルに
           は"-1"が割り当てられます。
         ・プロジェクトファイルを指定する場合、同じRSDを２度以上指定すると、一
           つ目のRSDに対してのみID値が割り当てられ、２つ目以降は"-1"になりま
           す。
         ・入力RSDファイルは１行1024バイト以下でなければなりません。

 6 注意

         ・アニメーションツールおよびmktodが出力するTODファイルを利用したプロ
           グラムを作成する場合、平行移動(-t)や拡大縮小(-s)オプションは使用し
           ないで下さい。TODファイルにはRSDオブジェクトに対する移動量や倍率が
           格納されているため、RSDからTMDに変換する際に移動や拡大縮小を行なう
           と、整合がとれなくなります。
         ・基本的に平行移動や拡大縮小は、dxf2rsd(-sc -t)やrsdform(-s -t)を利用
           して、RSD形式で行なうことをお勧めします。より正確で扱いやすいデー
           タになります。
         ・rsdlinkはファイル入出力を小さな単位で行います。そのため、ネットワー
           ク上のファイルを入出力ファイルに指定すると、非常に時間がかかる場合
           があります。大きなRSDデータをリンクする際には、できるだけローカル
           ディスク上で行ってください。

 7 補足

         ・.rsdファイルに記述されたテクスチャファイル(TIMファイル）は、RSDファ
           イルと同じディレクトリ(.\)、または..\TIMディレクトリになければなり
           ません。rsdlinkはこの順にTIMファイルを探します。
         ・RSDがrsdlinkによってどのタイプのTMDに変換されるのかを、以下の表に記
           します。「マテリアル」や「光源計算」の有無などの項目は、RSDのMATフ
           ァイルに記述されています(但し、「ポリゴンタイプ」はPLYファイルに数
           字で指定されています)。0x....はTMDパケットのヘッダです。なお、表で
           は、半透明でない片面ポリゴンの場合のみ記しています。半透明や両面ポ
           リゴンの場合は、ヘッダの値が変わりますが、パケットとしては同じもの
           になります。詳細は、RSDフォーマットおよびTMDフォーマットのドキュメ
           ントを御覧下さい。

        表 1 RSD->TMD変換対応表
    +---------------+------------+------------+------------+------------+
    |マテリアル+     光源計算あり 光源計算あり 光源計算なし 光源計算なし|
    |ポリゴンタイプ  Flat         Gouraud      Flat         Gouraud     |
    |C+三角形         0x20000304   0x30000406   0x21010304  (0x21010304)|
    |G+三角形         0x20040506   0x30040606  (0x31010506)  0x31010506 |
    |T+三角形         0x24000507   0x34000609  (0x25010607) (0x25010607)|
    |D+三角形        (0x24000507) (0x34000609)  0x25010607  (0x25010607)|
    |H+三角形        (0x24000507) (0x34000609) (0x35010809)  0x35010809 |
    |C+四角形         0x28000405   0x38000508   0x29010305  (0x29010305)|
    |G+四角形         0x28040708   0x38040808  (0x39010608)  0x39010608 |
    |T+四角形         0x2c000709   0x3c00080c  (0x2d010709) (0x2d010709)|
    |D+四角形        (0x2c000709) (0x3c00080c)  0x2d010709  (0x2d010709)|
    |H+四角形        (0x2c000709) (0x3c00080c) (0x3d010a0c)  0x3d010a0c |
    |C+ライン        (0x40010203) (0x40010203)  0x40010203  (0x40010203)|
    |G+ライン        (0x50010304) (0x50010304) (0x50010304)  0x50010304 |
    |T+スプライト    (0x64010305) (0x64010305)  0x64010305  (0x64010305)|
    |1x1スプライト   (0x6c010204) (0x6c010204)  0x6c010204  (0x6c010204)|
    |8x8スプライト   (0x74010204) (0x74010204)  0x74010204  (0x74010204)|
    |16x16スプライト (0x7c010204) (0x7c010204)  0x7c010204  (0x7c010204)|
    +---------------+------------+------------+------------+------------+
      
       ()内は、本来適当でないマテリアルタイプの組み合わせに対するTMDです。一
      部の指定を無視するなどして、妥当と思われるTMDにします。

 8 使用例


    例1 基本的な使い方

        > rsdlink -v -o boxes.tmd box1 -s 2.0 -t 100 100 100 box1 box2 -t 200 -200 200 box3
        
      この場合、以下の４つのオブジェクトが１つのTMDファイル(boxes.tmd)になり
      ます。
        
        box1		等倍のもの
        box1'		box1を２倍して(100 100 100)移動させたもの
        box2		box2を２倍して(100 100 100)移動させたもの
        box3		box3を２倍して(200 -200 200)移動させたもの

    例2 引数をファイルにまとめる方法

      次のように引数をファイルにまとめておくことでも同様の指定が可能です。
        > type test.arg
        box1
        -s 2.0 -t 100 100 100 box1 box2
        -t 200 -200 200 box3
        > rsdlink -v -o boxes.tmd test.arg

    例3 プロジェクトファイルの読み込みとID配列の作成

      プロジェクトファイル("model.prj")はレイアウトツールが生成する、オブジェ
      クトのIDテーブルです。
        > type model.prj
        @PRJ940701
        # Next available ID
        7
        # IDObject Name
        1	head.rsd
        2	body.rsd
        3	l_arm.rsd
        4	r_arm.rsd
        5	l_leg.rsd
        6	r_leg.rsd
        
        上のようなファイルがあるとき、
        
        > rsdlink -o robo.tmd model.prj
        
        または、
        
        > rsdlink -o robo.tmd -id model.prj body head l_arm r_arm l_leg	r_leg
        
      を実行すると、robo.tmdが生成されるとともに、下記の内容のrobo.hが生成さ
      れます。各オブジェクトについて、TMD内に現れる順に、そのIDが配列の要素と
      して記入されます。アプリケーションプログラムからTMD内の各オブジェクトに
      アクセスする際にご利用になれます。
        
        > type robo.h
        /*
         *	TMD ID List for "robo.tmd"
         *
         *	 Created by rsdlink(v3.7) at 10:10 03/16/96
         *
         *	(C) 1994-1996 Sony Computer Entertainment Inc. All Rights Reserved.
         */
        int robo_list[] = {
        	1,	/* body */
        	0,	/* head */
        	2,	/* l_arm */
        	3,	/* r_arm */
        	4,	/* l_leg */
        	5,	/* r_leg */
        };

    例5 -infoオプション使用時の出力例

      -infoオプションにより、実際にどのような内容のTMDデータに変換されたかを
      確認することができます。
        
        > rsdlink -info box
        
                Input RSDs      : 1 object(s)		TMD中のオブジェクト数
                        RSD[ 0] = "box"			各RSD名
                Total primitives:    12			合計プリミティブ数
                Total vertices  :     8			合計頂点数
                Total normals   :    12			合計法線数
         -----------------< box >-----------------
        = [  0] FLAT TEX 3-POLY(0x24000507) LIGHT: ON = 
                Vert-0: (  -150,   -150,   -150) (#2)
                Vert-1: (   150,   -150,   -150) (#6)
                Vert-2: (  -150,    150,   -150) (#0)
                Norm-0: (     0,      0,  -4096) (#0)
                UV 0-2: (  0   0) ( 47   0) (  0  47)
                Pixel mode  : 4bit CLUT : (x y)=(  0 480)
                Texture Page: 10  Texture No. :  0 
        = [  1] FLAT TEX 3-POLY(0x24000507) LIGHT: ON =
        		：
        
      各プリミティブ毎に、
        
        = [  0] FLAT TEX 3-POLY(0x24000507) LIGHT: ON =
        
      のように、[ポリゴン番号]、 フラット／グーロー(FLAT/GOURAUD)、テクスチャ
      の有無(TEX/NO TEX)、半透明処理のON/OFF(TRANS)、両面/片面(TWO-SIDED)、グ
      ラデーョン(GRADATION)、プリミティブの種類(3-POLY, 4-POLY, LINE, SPRITE）
      、プリミティブヘッダの16進表示(0x...)、光源計算のON/OFF(LIGHT: ON/OFF)
      が表示されます。
      引続き、そのプリミティブを構成している各頂点の座標値が
        
        Vert-0: (  -150,   -150,   -150) (#2)
        
      のように表示されます。(#...)はPLYファイルで用いられている頂点番号です。
      法線も同様に表示されます。
        
        Norm-0: (     0,      0,  -4096) (#0)
        
      (RSDでは、通常、法線は大きさ1に正規化されていますが(この場合、(0, 0, -1.
      0))、TMDでは浮動小数点は4096を1とした値に換算されるため、上記のようにな
      ります。)
      その後、テクスチャのUV座標や色などのマテリアル情報が表示されます。
