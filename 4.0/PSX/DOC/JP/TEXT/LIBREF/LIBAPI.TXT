DIRENTRY                                                             [構造体]
=============================================================================
                                             ディレクトリエントリのデータ構造
        
[構造]
        struct DIRENTRY {
        		char name [20];
        		long attr;
        		long size;
        		struct DIRENTRY *next;
        		long head;
        		char system[4];
        };
        
[メンバ]
        name		ファイル名
        attr		属性（ファイルシステムに依存）
        size		ファイルサイズ（バイト単位）
        next		次のファイルエントリ（ユーザ用）
        head		先頭セクタ
        system		システム予約
        
[解説]
        ファイルシステムに登録されているファイルに関する情報を格納する。
        
[関連項目]
        firstfile(), nextfile()

EXEC                                                                 [構造体]
=============================================================================
                                                     実行ファイルのデータ構造
        
[構造]
        struct EXEC {
        		unsigned long pc0;
        		unsigned long gp0;
        		unsigned long t_addr;
        		unsigned long t_size;
        		unsigned long d_addr;
        		unsigned long d_size;
        		unsigned long b_addr;
        		unsigned long b_size;
        		unsigned long s_addr;
        		unsigned long s_size;
        		unsigned long sp,fp,gp,ret,base;
        };
        
[メンバ]
        pc0		実行開始アドレス
        gp0		gpレジスタ初期値
        t_addt		テキストセクション＋初期値ありデータセクションの先頭アドレス
        t_size		テキストセクション＋初期値ありデータセクションのサイズ
        d_addr		システム予約
        d_size		システム予約
        b_addr		初期値なしデータセクション先頭アドレス
        b_size		初期値なしデータセクションサイズ
        s_addr		スタック領域先頭アドレス（ユーザ指定用）
        s_size		スタック領域サイズ（ユーザ指定用）
        sp,fp,gp,base	レジスタ退避領域
        
[解説]
        実行ファイル（PS-X EXE形式）の先頭の2Kバイト中に配置され、ファイルに
        格納されたプログラムのロードと実行のための情報を保持する。スタック情
        報を追加してExec()関数に引き渡すことでプログラムを起動する。
        
[関連項目]
        Exec()

calloc2                                                                [関数]
=============================================================================
                                                           主記憶を割り当てる
        
[形式]
        #include <stdlib.h>
        void *calloc2 (
        size_t n,
        size_t s
        )
        
[引数]
        n		個数
        s		区画の大きさ
        
[解説]

        失敗するとNULLを返す。
        
[関連項目]

Exec                                                                   [関数]
=============================================================================
                                                           実行ファイルの実行
        
[形式]
        long Exec ( 
        struct EXEC *exec,
        long argc,
        char **argv
        )
        
[引数]
        exec		実行ファイル情報
        argc		引数の数 
        argv		引数
        
[解説]
        exec の指定する実行ファイル情報に従ってメモリ上にロード済みのモジュー
        ルを実行する。
        exec->s_addrが0の場合、スタックおよびフレームポインタを設定しない。
        動作内容は以下の通り。
        (1)初期値なしデータセッションをゼロクリア。
        (2)sp,fp,gpを退避後、初期化。（fpはspと等しい値とする。）
        (3)main()の引数を設定。（a0,a1レジスタにて。）
        (4)実行開始アドレスをコール。
        (5)リタン後、sp,fp,gpを復帰。
        
[返り値]
        成功すると1を、失敗すると0を返す。
        
[備考]
        クリティカルセクションで実行すること。
        
[関連項目]
        EXEC構造体, Load()

        )

InitPAD                                                                [関数]
=============================================================================
                                                         コントローラの初期化
        
[形式]
        long InitPAD (
        char *bufA,
        long lenA, 
        char *bugB,
        long lenB
        )
        
[引数]
        bufA, bufB	受信データバッファ
        lenA, lenB	受信データバッファ長（バイト単位）
        
[解説]
        コントローラの受信データバッファを登録する。内部でChangeClearPAD()は
        実行しない。
        
[返り値]
        常に１
        
[備考]
        受信バッファ長は、予期せぬコントローラを接続された場合に、不具合が起
        きる可能性がありますので、必ず34バイト確保しておいて下さい。
        受信バッファに格納されるデータ形式は以下の通りです。
         
        +------+------------------------------------+
        |バイト 内容                                |
        |0      受信結果  0x00:成功、0xff:失敗      |
        |1      上位4ビット：端末種別               |
        |        0x1:マウス                         |
        |        0x2:16ボタンアナログ               |
        |        0x3:ガンコントローラ               |
        |        0x4:16ボタン                       |
        |        0x5:アナログジョイスティック       |
        |        0x7:アナログコントローラ           |
        |        0x8:マルチタップ                   |
        |       下位4ビット：受信データバイト数／２ |
        +------+------------------------------------+
        
        	マウス
        +------+----------------------------------+
        |3      ボタン状態  1:リリース、0:プッシュ|
        |       第2ビット：右、  第3ビット：左    |
        |4      移動量  X方向 (-128～127)         |
        |5      移動量  Y方向 (-128～127)         |
        |6      移動量  Z方向 (-128～127)         |
        |7,8, - 移動量  ?方向 (-128～127)         |
        +------+----------------------------------+
        
        	16ボタンアナログ、アナログジョイスティック、アナログコントローラ
        +---------+----------------------------------+
        |2,3       ボタン状態  1:リリース、0:プッシュ|
        |4,5,6,7,- アナログチャネル値                |
        +---------+----------------------------------+
        
        	ガンコントローラ、16ボタン
        +---+----------------------------------+
        |2,3 ボタン状態  1:リリース、0:プッシュ|
        +---+----------------------------------+
        
        バッファの第1バイトの上位4ビットは端末種別、下位4ビットは端末からの受
        信データ（バッファの第3バイト以降に格納される。）のバイト数の半分の値、
        となります。ボタンやチャネルなどの物理的な配置や対応は各端末のドキュ
        メントを参照してください。
        
        *既存端末の型
        標準コントローラは16ボタン型端末です。
        弊社から商品化されているマウスは、XとYの２方向だけをサポートするマウ
        ス型端末。また株式会社ナムコ様の「ネジコン」は、4チャネル、つまりバッ
        ファ第1バイトの下位4ビットが3（（ボタン分2バイト＋4チャネル分4バイト）
        ÷２ ）、の16ボタンアナログ型端末です。
        マルチタップ をご利用の際は、InitTAP()を、ガンコントローラをご利用の
        際は、InitGUN()をお使いください。
        
[関連項目]
        StartPAD(), StopPAD(), ChangeClearPAD(),InitTAP(),InitGUN()

SendPAD                                                                [関数]
=============================================================================
                                     コントローラの送信データバッファの初期化
        
[形式]
        void SendPAD (
        char *bufA,
        long  lenA,
        char *bugB,
        long  lenB
        )
        
[引数]
        bufA, bufB	送信データバッファ
        lenA, lenB	送信データバッファ長（バイト単位）
        
[解説]
        コントローラの送信データバッファを登録する初期化関数で、PadInit(),
        InitPAD()の後に１度呼ぶ。以後は、垂直同期割り込み毎のコントローラとの
        通信時にバッファにセットされたターゲットデバイスＩＤおよびデータが送
        信されるので、必要な値を、バッファに書き込むことで、コントローラの振
        動等を制御することになる。
        
        
        +------+-----------------------------------------------------+
        |バイト 内容                                                 |
        |０     バッファのデータが有効か無効かを指定するフラグ       |
        |       0x00で無効、0x01で有効。その他の値での動作は未定義。 |
        |１     ターゲットデバイスＩＤ                               |
        |       (上位２ビットを利用、他のビットはシステム予約)       |
        |２～   送信データ(データ長は受信データ長と同じ)             |
        +------+-----------------------------------------------------+
        
[返り値]
        なし
        
[備考]
        振動装置搭載の新型アナログコントローラにおけるバッファ設定と注意事項
        は以下のとおり。
        
        +----------------------------+---------------------------------+
        |バイト                       内容                             |
        |ターゲットデバイスＩＤ       上位2bit：0x01                   |
        |                             下位6bit：動作未定義（振動装置） |
        |送信データ（第１バイト）     bit0:1 = 振動ON、 0 = 振動OFF    |
        |                             その他(bit7～1)：動作未定義      |
        |送信データ（第２バイト以降） 常に0x00。その他：動作未定義     |
        +----------------------------+---------------------------------+
        
        注意事項：
        振動装置へのオン操作はコントローラとの通信が行われ、次にコントローラ
        との通信が行われるまでの１垂直同期期間の間のみ有効。装置を動作させる
        期間中、垂直同期割り込み毎に送信データバッファにターゲットデバイスＩ
        Ｄおよび振動オンをセットしかつバッファを有効状態にし続けること。ター
        ゲットデバイスＩＤは上位２ビットが01のときに有効となるが、他のビット
        はシステム予約となっており、すべて0として下さい。また、送信データ第１
        バイトも下位１ビットが1のとき有効となり、他のビットは、0として下さい。
