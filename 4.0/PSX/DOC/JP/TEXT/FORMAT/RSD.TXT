			RSDフォーマット

	        アーティスト用３次元オブジェクトデータ

1. 概要
--------

RSDフォーマットはPlayStationアーティストツール群で取り扱うモデリングデータのフォ
ーマットです。RSDフォーマットは４種類のファイルで１つのモデルを記述します。その
ため、４つのファイルを合わせて、「RSD」または「RSDデータ」ということがあります。

	RSDファイル
	PLY/MAT/GRPファイル、テクスチャファイルおよび拡張ファイルの対応関係
	を記述

	PLYファイル
	ポリゴンの頂点の位置情報を記述

	MATファイル
	ポリゴンのマテリアル情報を記述

	GRPファイル
	ポリゴンのグルーピング情報を記述

また、今回のバージョンよりHMDに対応するために新たに4種類の拡張ファイルと1種類の
サブ拡張ファイルが加えられました。

	拡張ファイル

	MSHファイル
	ポリゴンの連結情報を記述

	PVTファイル
	回転中心のオフセット情報を記述

	CODファイル
	各VERTEXの持つCOORDINATE情報を記述

	MOTファイル
	アニメーション情報を記述


	サブ拡張ファイル

	OGPファイル
	VERTEXのグルーピング情報を記述

すべてのファイルの関連情報はRSDファイル内に記述されているため、RSDファイルを指定
するだけでオブジェクトを構成するファイルを知ることが可能です。(OGPファイルに関し
てはサブ拡張ファイルなので、CODファイル中でのみ指定することが可能です。)

各ファイルは同一ディレクトリに存在する場合はファイル名のみで指定することができま
す。異なるディレクトリに存在するものに関しては相対パス(あるいは絶対パス）を示す
必要があります。(TIMファイルに関しても同様です。)

RSDは全てテキストファイルであり、各データは改行文字(LFまたはCR/LF)で区切られた
行単位で処理されます。任意の場所に#で始まるコメント行を挿入することができます。
なお、この解説書での記述は各ファイルの以下に示すバージョンに基づいています。

	RSD	Version 3.0
	PLY	Version 3.0
	MAT	Version 3.0
	GRP	Version 3.0
	MSH	Version 1.0
	PVT	Version 1.0
	COD	Version 1.0
	MOT	Version 1.0
	OGP	Version 1.0

2. RSDファイル
----------------

RSDファイルはオブジェクトを構成するPLY/MAT/GRPの各ファイル、テクスチャファイル
および拡張ファイルの組合せ情報を持ちます。今回のバージョンから拡張ファイルを使
用することで１組のRSDファイルで複数のオブジェクトを記述できるようになり、キャ
ラクター単位でのデータの扱いが可能となりました。

2.1. 全体構成

                ┌─────────────┐
                │           ID             │
                ├─────────────┤
                │                          │
                │    各ファイル指定        │
                │                          │
                └─────────────┘
                  図１ RSDファイルの全体構成

2.2.  ID

RSDファイルフォーマットのバージョンを表す文字列で"@RSDnnnnnn"(nnnnnnは番号)
という形式です。バージョン3.0では"@RSD970401"です。

2.3.  各ファイル指定

	PLYファイルの指定
		PLY=PLYファイル名

	MATファイルの指定
		MAT=MATファイル名

	GRPファイルの指定
		GRP=GRPファイル名

	MSHファイルの指定
		MSH=MSHファイル名

	PVTファイルの指定
		PVT=PVTファイル名

	CODファイルの指定
		COD=CODファイル名

	MOTファイルの指定
		NMOT=MOTファイル数
		MOT[n]=n番目のMOTファイル名
			:
			:

	TIM(テクスチャ)ファイルの指定
		NTEX=TIM(テクスチャ)ファイル数
		TEX[n]=n番目のTIM(テクスチャ)ファイル名
			:
			:

2.4.  サンプル

RSDファイルの簡単な例を示します。

	@RSD970401
	PLY=sample.ply
	MAT=sample.mat
	GRP=sample.grp
	MSH=sample.msh
	PVT=sample.pvt
	COD=sample.cod
	NMOT=1
	MOT[0]=anim.mot
	NTEX=3
	TEX[0]=texture.tim
	TEX[1]=texture2.tim
	TEX[2]=texture3.tim

		図２ RSDファイルの例

3. PLYファイル
----------------

PLYファイルはポリゴン等の頂点位置を記述したファイルです。PLYファイルで扱う座標系
は拡張ファイルを使用しなければPlayStation拡張ライブラリ(libgs)での座標系と同一で
、X軸の向き(増加方向)が画面右、同様にY軸が下、Z軸が画面奥を表します。拡張ファイ
ル使用時はPVTファイル内に記述される回転移動量を考慮し、HMD変換時にCODファイルに
記述される各頂点毎のPlayStation拡張ライブラリ(libgs)での座標系に書き換えられます
。また、ポリゴンが片面ポリゴンである場合、ポリゴンの向き(表裏)はPOLYGON記述子に
おける各頂点の記述順によって決定されます。ポリゴンの各頂点の記述順序が、空間中
で時計回り(CW)になる面をポリゴンの表面とします。

3.1.  全体構成

                ┌─────────────┐
                │           ID             │
                ├─────────────┤
                │    データ長レコード      │
                ├─────────────┤
                │                          │
                │      VERTEX記述子        │
                │           :              │
                │                          │
                ├─────────────┤
                │                          │
                │      NORMAL記述子        │
                │           :              │
                │                          │
                ├─────────────┤
                │                          │
                │      POLYGON記述子       │
                │           :              │
                │                          │
                └─────────────┘
        
                  図３ PLYファイルの全体構成

3.2.  ID

PLYファイルフォーマットのバージョンを表す文字列で"@PLYnnnnnn"(nnnnnnは番号)
という形式です。バージョン3.0では"@PLY970401" です。

3.3.  データ長レコード

後続の３つの各データブロックのデータ数(行数)が記述されます。各項目は空白また
はタブで区切られます。(以下同様)

                ┌──────┬──────┬──────┐
                │            │            │            │
                │ VERTEX個数 │ NORMAL個数 │POLYGON個数 │
                │            │            │            │
                └──────┴──────┴──────┘

                  図４ PLYファイルのデータ長レコード

3.4.  VERTEX記述子

頂点の座標を表す３個の浮動小数点値で構成されます。１行で１つの頂点を表
します。

                ┌──────┬──────┬──────┐
                │            │            │            │
                │   x座標    │   y座標    │   z座標    │
                │            │            │            │
                └──────┴──────┴──────┘

                  図５ PLYファイルのVERTEX記述子

3.5.  NORMAL記述子

法線ベクトルの成分を表す３個の浮動小数点値で構成されます。

                ┌──────┬──────┬──────┐
                │            │            │            │
                │   x成分    │   y成分    │   z成分    │
                │            │            │            │
                └──────┴──────┴──────┘

                  図６ PLYファイルのNORMAL記述子         

3.6.  POLYGON記述子

ポリゴンの種類を表すフラグとポリゴンを構成する9個のパラメータ列から成
ります。パラメータの意味はフラグ中のTYPEフィールドの値によって変化しま
す。

        ┌───┬──────┬──────┬────────┬──────┐
        │      │            │            │                │            │
        │フラグ│パラメータ#1│パラメータ#2│    ....        │パラメータ#9│
        │      │            │            │                │            │
        └───┴──────┴──────┴────────┴──────┘

                (フラグのbit構成)
                 Bit7(MSB)                       0(LSB)
                  ┌─┬─┬─┬─┬─┬─┬─┬─┐
                  ｜                  ｜          ｜         
                  │                  │   TYPE   │
                  ｜                  ｜          ｜         
                  └─┴─┴─┴─┴─┴─┴─┴─┘
                        TYPE: Polygon種類定義
                               000:  3角形
                               001:  4角形
                               010:  直線
                               011:  スプライト
                               1XX:  reserved

                    図７ PLYファイルのPOLYGON記述子
        
     フラグはポリゴンのタイプを表す１６進の整数値でプレフィ
     ックス'0x'はつきません。

     [ポリゴン(3角形/4角形)の場合]

     パラメータ部にはポリゴンの各頂点に対応する頂点(VERTEX)、
     法線(NORMAL)が記述されています。
     頂点(0-3)、法線(0-3)の値はそれぞれのデータ群の中の先頭
     から何番目のデータであるかを示す整数値です(先頭を0とする)。

     フラットシェーディングを行なうポリゴンの場合、各頂点の
     法線が同じ値を持ち、第１頂点のものが採用されます。グーロー
     シェーディングを行なうポリゴンの場合は異なる値を持ちます。

     3角形ポリゴンの場合は第4頂点に対応するデータ(頂点3、法線3)
     の値は 0 に設定します。
     4角形ポリゴンの場合の各頂点の記述順は最初の3頂点が1つの
     3角形を構成し、第2,3,4頂点でもう1つの3角形を構成するよう
     に記述します。

     ┌───┬───┬───┬───┬───┬───┬───┬───┬───┐
     │      │      │      │      │      │      │      │      │      │
     │フラグ│頂点0 │頂点1 │頂点2 │頂点3 │法線0 │法線1 │法線2 │法線3 │
     │      │      │      │      │      │      │      │      │      │
     └───┴───┴───┴───┴───┴───┴───┴───┴───┘

                図８ ポリゴン(3角形/4角形)の場合のPOLYGON記述子

     [直線の場合]

      パラメータ部には２つの端点のVERTEX番号が記述されています。

    ┌───┬───┬───┬───┬───┬───┬───┬───┬───┐
    │      │      │      │      │      │      │      │      │      │
    ｜フラグ｜頂点0 ｜頂点1 ｜  0   ｜  0   ｜  0   ｜  0   ｜  0   ｜   0  ｜
    │      │      │      │      │      │      │      │      │      │
    └───┴───┴───┴───┴───┴───┴───┴───┴───┘

                        図９ 直線の場合のPOLYGON記述子


     [スプライトの場合]

     モデルデータ中のスプライトは3D空間に配置された矩形
     のイメージデータで、常に視点の方を向くテクスチャつきポ
     リゴンと考えることが出来ます。

     パラメータ部にはスプライト位置を表すVERTEXとイメージ
    (スプライトパターン)の幅/高さが記述されています。

    ┌───┬───┬───┬───┬───┬───┬───┬───┬───┐
    │      │      │      │      │      │      │      │      │      │
    ｜フラグ｜頂点0 ｜WIDTH ｜HEIGHT｜   0  ｜   0  ｜  0   ｜  0   ｜  0   ｜
    │      │      │      │      │      │      │      │      │      │
    └───┴───┴───┴───┴───┴───┴───┴───┴───┘

                  図１０ スプライトの場合のPOLYGON記述子

4. MATファイル
---------------

4.1.  全体構成

                ┌─────────────┐
                │           ID             │
                ├─────────────┤
                │     MATERIAL記述子個数   │
                ├─────────────┤
                │                          │
                ｜      MATERIAL記述子      ｜
                │           :              │
                │           :              │
                │                          │
                └─────────────┘

                図１２ MATファイルの全体構成

4.2.  ID

MATファイルフォーマットのバージョンを表す文字列で"@MATnnnnnn"(nnnnnnは番号)
という形式です。現在のバージョン3.0では"@MAT970401"です。

4.3.  MATERIAL記述子個数

後続のMATERIAL記述子の個数(行数)が記述されます。

4.4.  MATERIAL記述子

ポリゴンの指定と、そのポリゴンの持つマテリアル情報を記述します。

        ┌───────┬─────┬───────┬───────────┐
        │              │          │              │                      │
        │  ポリゴンNo. │  フラグ  │シェーディング│  マテリアル情報 ...  │
        │              │          │              │                      │
        └───────┴─────┴───────┴───────────┘

	                図１３ MATファイルのMATERIAL記述子

     [ポリゴンNo.]

     PLYファイルのPOLYGON群の何番目のポリゴンかを表します。
    レンジ指定を行なうと複数のポリゴンを１行で指定できます。

                 記述    対象となるポリゴン
                 1       1 のみ
                 0-5     0 1 2 3 4 5
                 2,4,6   2 4 6

     [フラグ]

     ポリゴンのマテリアル属性を表す１６進整数でプレフィックス '0x'
     はつきません。各bitの意味は次の通りです。

        bit0    光源計算モード
                        0：     光源計算あり
                        1：     固定色

                        光源計算ありの場合は光源とポリゴンの向きによって描画色
                        を決定しますが、固定色の場合は向きに関わらず一定の色に
                        なります。

        bit1    Back face
                        0：     片面ポリゴン
                        1：     両面ポリゴン

        bit2    半透明フラグ
                        0:      半透明処理OFF
                        1:      半透明処理ON

                        半透明処理ONの場合、テクスチャなしポリゴンは常に半透明
                        テクスチャつきポリゴンはテクスチャデータのSTPビットに
                        よって半透明/不透明/透明をコントロールします。

        bit3～5 半透明レート
                        000:   50% back +  50% polygon
                        001:  100% back + 100% polygon
                        010:  100% back - 100% polygon
                        011:  100% back +  25% polygon
                        1XX:  reserved

                        現在のライブラリではポリゴン単位で半透明レートを
                        変化させることはできません。

	bit6	reserved (must be 0)

	bit7	プリセット型HMD作成スイッチ(HMD作成時のみ)
			0:	OFF
			1:	ON

     [シェーディング]

        シェーディングモードを表す１文字のキャラクタです。

        "F"：   フラット        "G"：   グーロー(スムーズ)

        フラットシェーディングが指定された場合、PLYファイルで
        指定された法線情報のうち第１頂点のものが採用されます。

     [マテリアル情報]

        マテリアルのタイプ(テクスチャの有無等)でフォーマットが異な
        ります。

     [テクスチャなし(カラードポリゴン/直線)の場合]
            ┌──┬───┬───┬───┐
            │    │      │      │      │
            │TYPE│  R   │  G   │  B   │
            │    │      │      │      │
            └──┴───┴───┴───┘
                TYPE:        マテリアルのタイプで、値は"C"

                R, G, B:     ポリゴン色のRGB成分(0～255)

        図１４ テクスチャなし(カラードポリゴン/直線)の場合


     [テクスチャなし(グラデーションカラードポリゴン/直線)の場合]
    ┌──┬──┬──┬──┬──┬──┬──┬───┬──┬──┬──┐
    │    │    │    │    │    │    │    │      │    │    │    │
    │TYPE│ R0 │ G0 │ B0 │ R1 │ G1 │ B1 │  ... │ R3 │ G3 │ B3 │
    │    │    │    │    │    │    │    │      │    │    │    │
    └──┴──┴──┴──┴──┴──┴──┴───┴──┴──┴──┘
                TYPE:           マテリアルのタイプで、値は"G"

                Rn, Gn, Bn:     第n頂点のRGB成分(n = 0～3)
                                3角ポリゴンの場合は第4頂点の
                                RGB値は0,0,0になります。

        図１５ テクスチャなし(グーローカラードポリゴン/直線)の場合


     [テクスチャつきポリゴン/スプライトの場合]
    ┌──┬──┬──┬──┬──┬──┬──┬──┬──┬──┐
    │    │    │    │    │    │    │    │    │    │    │
    │TYPE│TNO │ U0 │ V0 │ U1 │ V1 │ U2 │ V2 │ U3 │ V3 │
    │    │    │    │    │    │    │    │    │    │    │
    └──┴──┴──┴──┴──┴──┴──┴──┴──┴──┘
                TYPE:           マテリアルのタイプで、値は"T"

                TNO:            使用するTIMデータファイルの指定
                                (RSDファイルに記述されているテクスチャの番号)

                Un, Vn:         頂点nのテクスチャ空間での位置
                                3角ポリゴンの場合は第4頂点の値(U3, V3)は
                                0になります。

                図１６ テクスチャつきポリゴン/スプライトの場合

     [カラードテクスチャつきポリゴンの場合]
  ┌──┬──┬──┬──┬──┬──┬──┬──┬──┬──┬─┬─┬─┐
  │    │    │    │    │    │    │    │    │    │    │  │  │  │
  │TYPE│TNO │ U0 │ V0 │ U1 │ V1 │ U2 │ V2 │ U3 │ V3 │R │G │B │
  │    │    │    │    │    │    │    │    │    │    │  │  │  │
  └──┴──┴──┴──┴──┴──┴──┴──┴──┴──┴─┴─┴─┘
                TYPE:           マテリアルのタイプで、値は"D"

                TNO:            使用するTIMデータファイルの指定
                                (RSDファイルに記述されているテクスチャの番号)

                Un, Vn:         頂点nのテクスチャ空間での位置
                                3角ポリゴンの場合は第4頂点の値(U3, V3)は
                                0になります。

                R, G, B:        ポリゴン色のRGB成分(0～255)

                図１７ カラードテクスチャつきポリゴンの場合

    ※ カラードテクスチャつきポリゴンは、光源計算をせずにポリゴン単位でテ
       クスチャに明るさを与えるために使います。このタイプを使えば、光源計算
       を省略しても、テクスチャつきオブジェクトを立体的に描画できるようにな

5. GRPファイル
----------------

PLYファイル中のポリゴンをひとまとめにして名称を付けることができます。
マテリアルエディタにおいて、グループ名を指定することで、複数のポリゴン
を簡単に選択できるようになります。

5.1.  全体構成

                ┌─────────────┐
                │           ID             │
                ├─────────────┤
                │      GROUP記述子個数     │
                ├─────────────┤
                │                          │
                ｜        GROUP記述子       ｜
                │           :              │
                │           :              │
                │                          │
                └─────────────┘

                図２３ GRPファイルの全体構成

5.2.  ID

GRPファイルフォーマットのバージョンを表す文字列で"@GRPnnnnnn"(nnnnnnは番号)
という形式です。バージョン3.0では"@GRP970401" です。

5.3.  GROUP記述子個数

後続のGROUP記述子の個数が記述されます。

5.4.  GROUP記述子

１つのグループの構成を定義します。複数行で構成されています。

     [先頭行]
        ┌───────┬────────┬──────┐
        │              │                │            │
        ｜ グループ名称 ｜ポリゴンNo.行数 ｜ポリゴン個数｜
        │              │                │            │
        └───────┴────────┴──────┘

        グループ名称：            グループに付けられた名前です。

        ポリゴンNo.行数：         ポリゴンNo.の記述を行なう後続行の行数です。

        ポリゴン個数：            グループに属するポリゴンの個数です。

                図２４ GRPファイルのGROUP記述子

     [後続行(ポリゴンNo.記述)]

     グループに属するポリゴンの番号を指定します。数値はPLYファイ
     ル中の何番目のポリゴンかを表します。レンジ指定を行なうと複数
     のポリゴンを１行で指定できます。

                 記述    対象となるポリゴン
                 1       1 のみ
                 3-7     3 4 5 6 7
                 2,4,6   2 4 6

5.5.  サンプル

GRPファイルの簡単な例を示します。


                @GRP970401
                # Number of Group
                2
                # Group list
                upper_part 2 5
                10-13
                25
                lower_part 3 3
                3
                5
                7

                図２５ GRPファイルの例

8. CODファイル
----------------

RSD拡張ファイルで、PLYファイル中のVERTEXにCOORDINATEの属性をつけることができま
す。これにより、複数MATRIXをもつHMDデータをRSDフォーマットより生成できるように
なります。

8.1.  全体構成
	

                ┌─────────────┐
                │           ID             │
                ├─────────────┤
                │     OGPファイル名        │
                ├─────────────┤
                │     COORDINATE数         │
                ├─────────────┤
                │                          │
                ｜       COORDINATE         ｜
                │           :              │
                │           :              │
                │                          │
                ├─────────────┤
                │                          │
                ｜COORDINATEに属する        ｜
                │     VERTEX又は、         │
                │     オブジェクト グループ│
                │           :              │
                └─────────────┘

                図３０ CODファイルの全体構成

8.2.  ID

CODファイルフォーマットのバージョンを表す文字列で"@CODnnnnnn"(nnnnnnは番号)と
いう形式です。現在のバージョン1.0では"@COD970401" です。

8.3.  OGPファイル名

OGPファイルの名前を表し、OGP=OGPファイル名と記述されます。OGPファイルを使用し
ない場合はOGP=NULLと記述されます。

8.4.  COORDINATE数

後続のCOORDINATEの個数が記述されます。

8.5.  COORDINATE

COORDINATEの構成を定義します。複数行で構成されています。

	[1～3行]
	マトリックス係数値を指定します。数値は10進数で記述されます。

			m[0][0]	m[0][1]	m[0][2]
			m[1][0]	m[1][1]	m[1][2]
			m[2][0]	m[2][1]	m[2][2]

	[4行]
	平行移動量を指定します。数値は10進数で記述されます。

			t[0]	t[1]	t[2]

	[5行]
	マトリックス係数値を生成した回転ベクトル成分を指定します。10進数で
	記述されます。

			vx	vy	vz

	[6行]
	親COORDINATEのインデックスを指定します。インデックスは記入順に0から
	始まります。親がワールド座標系の場合は自分自身のインデックスを記述
	します。

				super

8.6.  COORDINATEに属するVERTEX又は、オブジェクトグループ

オブジェクト名のところでOGPファイルを指定した場合はCOORDINATEに属するオブジ
ェクトグループが指定され、OGPファイルを指定しなかった場合はCOORDINATEに属す
るVERTEXが指定されます。

	オブジェクトグループを指定する場合

	オブジェクトグループはOGPファイル内で指定されるオブジェクトグループ
	名で表されます。オブジェクトグループはオブジェクトグループ数で指定
	した数分、横に続けて指定されます。改行はしてもしなくても構いません。

 COORDINATEインデックス  オブジェクトグループ数  オブジェクトグループ名…

	VERTEXを指定する場合

	VERTEXはPLYファイル内で指定されるVERTEXのインデックスで表されます。
	VERTEXはVERTEX数で指定した数分、横に続けて指定されます。改行はして
	もしなくても構いません。

	COORDINATEインデックス     VERTEX数     VERTEXインデックス…

	(注)同一CODファイル内で上記の2つの指定法が混在することはありません。
	OGPファイルを指定した場合はすべてオブジェクトグループで指定し、そう
	でない場合はすべてVERTEXにより指定されます。

10.2.  ID

MOTファイルフォーマットのバージョンを表す文字列で"@MOTnnnnnn"(nnnnnnは番号)と
いう形式です。現在のバージョン1.0では"@MOT970401" です。

10.3.  アニメーションタイプ

アニメーションの方法が記述されます。現状で対応しているものはCOORDINATEを変化さ
せるタイプのみです。

	(COORDINATEの場合)

				COORDINATE

10.4.  INDEX数

以下に記述される、INDEX & シーケンス数 & WORK TOPとシーケンスヘッダ情報を1組と
した要素数が記述されます。以下、ここで指定された数分、10.5、10.6の並びが繰り返
されます。

				  INDEX数

10.5.  INDEX & シーケンス数 & WORK TOP

変化させる元データのインデックスと、シーケンスグループの数及び、WORKシーケンス
のTOPポイント名が記述されます。元データのインデックスとは、例えば、アニメーショ
ンタイプがCOORDINATEならばCODファイルの中で指定されるCOORDINATEのインデックスの
ことです。シーケンスグループの数とは、以下に記述されるアニメーションパターンの
数のことです。WORKシーケンスが存在しない場合、WORK TOPにはシーケンスのポイント
名に使われていない適当な文字列が記述されます。

			INDEX	シーケンス数	WORK TOP

10.6.  シーケンスヘッダ情報

以下に示されるアニメーションパターンのヘッダ情報が記述されます。以下、予約語毎
に記述方法を示します。

			START	スタートポイント名	ストリームID

	(START)
	アニメーションシーケンスのスタートポイントを示す予約語です。

	(スタートポイント名)
	シーケンスコントロール情報部にしめされるスタートポイント名が記述されま
	す。スタートポイント名は256文字以内の文字列で表現されます。

	(ストリームID)
	16進数で記述されます。必ず0x??(7bit分)という形で記述して下さい。他のシ
	ーケンス因子とのストリームIDの一致を認識するためのビットパターンです。


			KEY2	SEQ TOP 1	SEQ TOP 2

	(KEY2)
	キーフレームのトップポイントを示す予約語です。2つまで指定することが可
	能です。

	(SEQ TOP 1,2)
	シーケンスコントロール情報部に示されるキーフレームのトップポイント名が
	記述されます。TOP1に記述されたものはHMD変換時にシーケンスヘッダ情報と
	して、下位16bitに記述され、TOP2に記述されたものは上位16bitに記述されま
	す。指定すべきポイントが存在しない場合は、ポイント名として使用されてい
	ない適当な文字列が記述されます。ポイント名は256文字以内の文字列で表現
	されます。

10.7.シーケンスコントロール情報

アニメーションの実際の動きが記述されます。構成は予約語の種類により異なります。
また、位置情報として、任意の256文字以内のスタートポイントを間に挿入することが
できます。スタートポイントは挿入された次の行のアニメーション位置を示すことに
なります。以下に予約語毎に記述方法を示します。


	SEQ   フレーム数   パケットタイプ   パケットタイプインデックス


	(SEQ)
	予約語。これを用いることでシーケンスを表現します。

	(フレーム数)
	このキーフレームまでのフレーム数。

	(アニメーションパケットタイプ)
	アニメーションの補完タイプ。(詳しくはパラメータ情報で説明

	(アニメーションパケットタイプインデックス)
	アニメーションパケット部で示されるアニメーションパケットの
	インデックス。


	GOTO  ジャンプポイント名
		  ストリームID(ジャンプ後)  ストリームID(ジャンプ前)

		※注意！！ 一行に記述して下さい。


	(GOTO)
	予約語。これを用いることでシーケンスの流れをジャンプさせる
	ことができます。

	(ジャンプポイント名)
	ジャンプするシーケンス位置を256文字以内の文字列により示します。

	(ストリームID)
	16進数で表記され、必ず0x??という形になります。他のシーケンス因
	子とのストリームIDの一致を認識するためのビットパターンです。


				END     ストリームID


	(END)
	予約語。これを用いることでシーケンスの流れを止めることができます。

	(ストリームID)
	16進数で表記され、必ず0x??という形になります。他のシーケンス因子
	とのストリームIDの一致を認識するためのビットパターンです。

10.8.パラメータ情報

移動量などのパラメータ値が記述されます。パラメータのパケットタイプはHMD内で
定められているものと同じです。パケットタイプはTYPEという予約語の後に続けて
記述されます。パケットタイプの記述例を以下に示します。

				TYPE ps0r0t0


	p	パラメータの意。現在はこのタイプ以外ありません。

	s?r?t?	?の値によりパラメータのパケットタイプが異なります。0がくる
		場合はその部分のパラメータが存在しないことになります。

現在パケットタイプは12種類がサポートされています。以下にそのパケットタイプ
と記述方法を示します。

	※ Scale	比:1 = 4096
	※ Rotation	単位:Degree, 360°= 4096

	(ps0r0t0)	Dumy Matrix

				Dx	Dy

	(ps0r1t0)	Translation linear

				Tx	Ty	Tz

	(ps0r9t0)	Translation(short) linear

				Tx	Ty	Tz

	(ps9r9t0)	Scale(one) Translation(short) linear

			Tx	Ty	Tz	Scale

	(ps1r0t0)	Scale linear

				Sx	Sy	Sz

	(ps0r0t1)	Rotation linear

				Rx	Ry	Rz

	(ps9r0t1)	Scale(one) Rotation linear

			Tx	Ty	Tz	Scale

	(ps0r1t1)	Rotation Translation linear

		Tx	Ty	Tz	Rx	Ry	Rz

	(ps9r1t1)	Scale(one) Rotation Translation linear

		Tx	Ty	Tz	Rx	Ry	Rz	Scale

	(ps1r1t1)	Scale Rotation Translation linear

	Tx	Ty	Tz	Rx	Ry	Rz	Sx	Sy	Sz

	(ps0r9t1)	Rotation Translation(short) linear

		Tx	Ty	Tz	Rx	Ry	Rz

	(ps1r9t1)	Scale Rotation Translation(short) linear

	Tx	Ty	Tz	Rx	Ry	Rz	Sx	Sy	Sz

		START TOP12 0x01
		START TOP13 0x01
		#Index, Number of Sequence
		0 3 DUMY
		#Sequence Header

		START TOP22 0x01
		START TOP23 0x01

		SEQ 0 ps0r0t0 1

		TOP11A

		TOP11B

		END 0x02
		TOP12

		SEQ 250 ps0r1t0 3
		GOTO TOP12 0x02 0x01
		END 0x02
