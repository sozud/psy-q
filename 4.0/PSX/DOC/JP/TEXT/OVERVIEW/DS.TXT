                                                 Library Overview Release 4.0

拡張CD-ROMライブラリ(libds)
============================

  拡張CD-ROMライブラリでは、既存のCD-ROMライブラリのカーネルを使用して、新し
  いインターフェイスを提供しています。なお、本章では既存のCD-ROMライブラリの
  知識を前提にして、主に既存のものとの相違点を説明しています。

 1 概要
--------

    libdsは、libcdをベースにした新しいCD-ROM制御ライブラリです。基本システム
    にコマンドキューを採用し、PlayStationのメインCPUとCDサブシステムの動作速
    度の違いを吸収します。また、CDカバーの開閉後の処理を基本システムで行うな
    ど、PlayStation特有の処理をライブラリで行います。

  1.1 ライブラリファイル

    libdsのライブラリファイルは「libds.lib」です。各サービスを呼び出すプログ
    ラムは必ずこれをリンクする必要があります。また、libdsはCDサブシステムの制
    御にlibcdを使用しているため、「libcd.lib」もリンクしてください。

  1.2 インクルードヘッダ

    libdsのインクルードヘッダは「libds.h」です。各種のデータ構造、マクロは全
    てこのファイルで定義されています。各サービスを呼び出すプログラムは必ずこ
    れをインクルードする必要があります。
    
    +----------+--------------+
    |内容       ファイル名    |
    |ライブラリ libds.lib     |
    |           （libcd.lib） |
    |ヘッダ     libds.h       |
    +----------+--------------+

  1.3 他のライブラリ

    libdsは、一部のライブラリのバージョンに依存します。以下のライブラリは指定
    のバージョンをご使用下さい。
    
    +------------+----------+
    |ライブラリ名 バージョン|
    |libcd.lib    4.0       |
    |libetc.lib   4.0       |
    +------------+----------+

 2 libdsの位置付け
-------------------


  2.1 位置付け

    libdsは、libcdのカーネルシステム上に実現された新しいインターフェイスです。
    libcdのCDサブシステムの制御ルーチンの上に独自のカーネルシステムを設け、コ
    マンドキューの制御やCDのカバーが開けられた時の処理を実現しています。libcd
    で提供されていた機能と同等の機能を新規に用意していますので、プログラムを
    容易に移行することができます。
    
    

  2.2 libcdとの関連

    libdsのカーネルシステムおよびコマンドキューは、libcdの全ての関数と排他的
    に動作します。libdsを使用中にlibcdの関数を呼び出すとlibdsのカーネルシステ
    ムおよびコマンドキューが破壊されます。よって、libds使用時はlibcdの関数（
    名前の先頭が“Cd”で始まる関数、CdInit()を含む）を使用しないでください。

  2.3 ストリーミング関数

    libdsはlibcdと同時に使用できませんが、ストリーミングは従来どおりSt*()関数
    を使用して下さい。St*()関数はlibcd.libの一部ですがCDサブシステムをコント
    ロールすることはないので、libdsの動作に影響を与えません。なお、ストリーミ
    ングを開始するための関数およびコマンドはlibdsで用意されているもの（
    DsRead2()、DslReadSコマンドなど）を使用してください。

  2.4 libapiの関数について

    libapiで用意されているCDコントロールのための関数（96_init、LoadExec、Load
    など）はlibdsのシステムが動作している時に使用することはできません。これら
    の関数を使用する場合は、libdsのシステムを終了させてから使用してください。

 3 libcdとの相違点
-------------------


  3.1 プリミティブコマンド

    プリミティブコマンドはlibcdと同じ機能が使用できます。コマンドコードは、
    libds.hで再定義され、シンボルの先頭の３文字“Cdl”が“Dsl”に置き換えられ
    ています。
    
    +------------+------+------+------------------------------------+
    |シンボル     コード タイプ 内容                                |
    |DslNop       0x01   B      NOP（No Operation）                 |
    |DslSetloc    0x02   B      シークのターゲット位置を設定        |
    |DslPlay      0x03   B      CD-DA演奏開始                       |
    |DslForward   0x04   B      早送り                              |
    |DslBackward  0x05   B      巻き戻し                            |
    |DslReadN     0x06   B      データリード開始（リトライつき）    |
    |DslStandby   0x07   N      ディスクを回転させた状態で待機      |
    |DslStop      0x08   N      ディスクの回転を停止                |
    |DslPause     0x09   N      現在位置で一時停止                  |
    |DslMute      0x0b   B      CD-DAミュート                       |
    |DslDemute    0x0c   B      ミュート解除                        |
    |DslSetfilter 0x0d   B      再生ADPCMセクタを選択               |
    |DslSetmode   0x0e   B      基本モード設定                      |
    |DslGetparam  0x0f   B      最後のstatus、動作モード獲得        |
    |DslGetlocL   0x10   B      論理位置獲得（データセクタ）        |
    |DslGetlocP   0x11   B      物理位置獲得（オーディオセクタ）    |
    |DslGetTN     0x13   B      TOCエントリ数の取得                 |
    |DslGetTD     0x14   B      TOCの取得                           |
    |DslSeekL     0x15   N      論理シーク（データセクタシーク）    |
    |DslSeekP     0x16   N      物理シーク（オーディオセクタシーク）|
    |DslReadS     0x1b   B      データリード開始（リトライなし）    |
    +------------+------+------+------------------------------------+

  3.2 構造体

    libcdで用意されていた全ての構造体については、libdsでも同じ機能を持つもの
    が用意されています。構造体についてもシンボルの先頭３文字“Cdl”が“Dsl”
    に置き換えられています。
    
    +---------+-----------------+--------------------------+
    |シンボル  libcdでのシンボル 内容                      |
    |DslATV    CdlATV            オーディオアッテネータ    |
    |DslFILE   CdlFILE           9660ファイルディスクリプタ|
    |DslFILTER CdlFILTER         ADPCMチャンネル           |
    |DslLOC    CdlLOC            CD-ROMロケーション        |
    +---------+-----------------+--------------------------+

  3.3 関数

    関数は、libcdで用意されていたものと同等の機能を持つ関数がlibdsでも用意さ
    れています。シンボルの先頭２文字を“Cd”から“Ds”に置き換えることでlibds
    で用意されている関数となります。ただし、引数や動作タイミングなど異なる場
    合があります。各関数についての詳細はリファレンスを参照してください。

  3.4 処理速度

    libdsではプリミティブコマンドの管理にコマンドキューを使用しています。よっ
    て、厳密な処理速度（タイミング）はlibcdと異なります。
    libcdでプリミティブコマンドを発行した場合、前のコマンドが実行中であればコ
    マンド発行のための関数（CdControl()など）はそのコマンドの終了を待ち、目的
    のプリミティブコマンドを発行します。この間はCPUの処理はブロックされます。
    これに対してlibdsでは、コマンド発行時に他のコマンドが実行中であればそのコ
    マンドはコマンドキューに登録され、コマンド発行のための関数はその時点で終
    了します。キューに登録されたコマンドは前のコマンドの終了時またはVSync毎に
    実行可能かどうか判定され、可能であればCDサブシステムに送られます。この方
    式のメリットは、CDサブシステムの状態に関わらずコマンド発行でCPUの処理がブ
    ロックされないところにあります。また、一度に複数のコマンドを発行する場合
    でもそれぞれのコマンドの終了を待たずに次のコマンドを発行（登録）すること
    ができます。

  3.5 互換関数

    libdsにおけるプリミティブコマンドの実行は全てノンブロック型で行われますが、
    libcdのCdControl（CdControlB）に対応する関数も用意されています。

 4 初期化と終了
----------------


  4.1 システムの初期化

    libdsを使用する場合は、プログラムの先頭でDsInit()を実行します。
    
        int DsInit( void );
    
    DsInit()はResetGraph()およびPadInit()の後でコールしてください。DsInit()実
    行後はCDサブシステムの管理をlibdsのシステムが行うため、libds以外の環境（
    libcdやlibapi）からCDサブシステムをコントロールすることはできません。
    また、DsInit()は内部でlibcdの初期化も行いますので、ストリーミングライブラ
    リ（St*()関数）を使用する場合でもCdInit()を呼ぶ必要はありません。

  4.2 初期化後のリセット

    DsInit()でシステムを初期化した後に再びDsInit()をコールすると、トラブルの
    原因となります。通常の用途でシステムをリセットしたい場合は、DsFlush()を使
    用してください。
    
        void DsFlush( void );
    
    DsFlush()はCDサブシステムをフラッシュし、コマンドキュー（後述）をクリアし
    ます。
    もし何らかの理由でシステムを最初の状態に戻したい場合は、DsReset()を使用し
    てください。
    
        int DsReset( void );
    
    DsReset()を使用すると、プログラムで設定したコールバック関数もクリアされま
    すので、リセット後に設定し直してください。

  4.3 システムの終了

    子プロセスを起動したりオーバーレイを行う場合は、libdsのシステムを一度終了
    させてください。システムを終了させるためにはDsClose()を使用します。
    
        void DsClose( void );
    
    なお、子プロセスの実行が終了し再び処理を再開する場合はDsInit()をコールし
    てください。

  4.4 注意

    DsFlush()、DsReset()、DsClose()ではデータリード（再生）動作を中止しません。
    データリード（再生）動作はプログラムからDslPauseを発行して明示的に止める
    必要があります。これらの関数を使用する前にDslPauseを発行してください。
    
        	:
        while( DsControlB( DslPause, 0, 0 ) == 0 );
        DsClose();
        	:
    
    データリード（再生）が行われたままシステムを終了し、LoadExec等を行った場
    合は誤動作する可能性があります。

 5 コマンドキュー
------------------

    コマンドキューとは、CDサブシステムの状態を監視し、プリミティブコマンドの
    発行と終了を管理するシステムです。発行されたコマンドはキューに積まれ、CD
    サブシステムがコマンドを受け付けることが可能になった時点でサブシステムに
    送られます。
    また、コマンドキューはCDサブシステムの仕様上必要な処理を自動的に行います。
    例えばカバーが開けられたときの処理は、システムで自動的に行われます。この
    間はコマンドをCDサブシステムに送ることはできませんが、キューにコマンドを
    登録しておけば処理終了後に直ちにコマンドが発行されます。

  5.1 コマンドの発行

    コマンドキューにプリミティブコマンドを発行するためにはDsCommand()関数を使
    用します。
    
        int DsCommand( u_char com, u_char* param, DslCB func, int count );
        	com		コマンドコード
        	param		コマンドに対するパラメータ（４バイト）
        	func		コマンド終了コールバック関数のポインタ
        	count		リトライ回数（-1で無限回リトライ）
    
    第３引数は、コマンド終了時に呼び出されるコールバック関数のポインタです。
    このコールバック関数はコマンド毎に設定することが可能で、対応するコマンド
    の終了時にのみ呼び出されます。
    コマンドの発行（キューへの登録）が成功すると、返り値としてコマンドID（>0）
    が渡されます。コマンドの実行状況や結果を得る場合は、このコマンドIDを使用
    します。
    なお、コマンドキューがいっぱいになった場合は０が返されます。

  5.2 終了確認

    コマンドキューに登録されたプリミティブコマンドの終了確認を行うためには、
    コマンド発行時に設定するコールバック関数を使用するか、DsSync()関数を使用
    します。
    
        int DsSync( int id, u_char* result );
        	id		コマンドID
        	result		コマンドに対する返り値（８バイト）
    
    DsSync()は呼び出された時点でのコマンドの実行状況を返します。
    
    +------------+--------------------------------------------+
    |シンボル     内容                                        |
    |DslComplete  コマンドは正常終了した。                    |
    |DslDiskError コマンドはエラーとなった。                  |
    |DslNoIntr    コマンドはまだ実行されていない。            |
    |DslNoResult  コマンドは終了しているが結果が残っていない。|
    +------------+--------------------------------------------+
    
    実行が終了していた場合（DslComplete、DslDiskError）はresultに返り値が格納
    されます。
    システムには複数の実行結果が保存されます。よって、２つ前に実行されたコマ
    ンドの結果を得ることもできます。ただし実行結果は古い順に上書きされていき
    ますので、あまり古いコマンドについてはDsSync()の返り値がDslNoResultとなり
    ます。システムで保存される実行結果の数はマクロ定数DslMaxRESULTSに定義され
    ています。

  5.3 コマンドキューの状態確認

    コマンドキューに現在いくつのコマンドが積まれているのかを得るには
    DsQueueLen()関数を使用します。
    
        int DsQueueLen( void );
    
    DsQueueLen()は現在キューに登録されているコマンドの数を返します。コマンド
    の数には現在実行中のものも含まれます。また、キューに登録できるコマンドの
    最大数はマクロ定数DslMaxCOMMANDSに定義されています。コマンドの最大数はラ
    イブラリのバージョンアップにともなって変更される可能性がありますので、必
    ずマクロ定数で参照してください。
    
    システムの状態を得るにはDsSystemStatus()を使用します。
    
        int DsSystemStatus( void );
    
    DsSystemStatus()はシステムが現在どのような状態にあるかを返します。リター
    ン値は以下の通りです。
    
        DslReady	コマンド実行可能状態
        DslBusy		コマンド実行中、もしくはコマンドが実行できない状態
        DslNoCD		CDがセットされていない
    
    DslReadyは、CDサブシステムが正常な状態にあり、何もコマンドが実行されてい
    ない場合です。この時にコマンドをキューに発行するとすぐに処理が開始されま
    す。なお、タイミングを重視する場合は念のためにキューのコマンドの数が０で
    あることをあわせて確認してください。
    DslBusyは、現在コマンドが実行中であるか、何らかの理由でコマンドが実行でき
    ない状態になっている場合です。コマンドが実行できない状態とは、カバー開閉
    後の処理を行っている、もしくはCDの回転速度が変更されて一定期間処理ができ
    ない状態を指します。この間はコマンドはキューに積まれ、状態が改善された時
    点でCDサブシステムに送られます。
    DslNoCDはドライブにCDがセットされていない場合です。カバー開閉後の処理でCD
    が認識できなかった場合にDslNoCDに移行します。この状態は再度カバーが開けら
    れてCDがセットされるまで変わりません。

  5.4 処理タイミング

    DsCommand()によって発行されたプリミティブコマンドは、実行可能であればすぐ
    にCDサブシステムに送られます。前のコマンドが終了していないなど実行可能で
    なければキューに積まれますが、コマンドが終了次第（syncコールバックの中で）
    発行されます（syncチェイン）。
    カバーの開閉など処理がブロックされた場合はsyncチェインは切れますが、この
    場合はVSyncの割込みでキューがポーリングされます。

  5.5 エラー発生時の動作

    コマンド実行中にエラーが発生した場合は、そのコマンドは再発行（リトライ）
    されます。コマンドを何回まで実行するかは、第４引数countで指定します。リト
    ライはcount回行われます。count == 0の場合はリトライは行われません。なお、
    count == -1の場合はそのコマンドが成功するまでリトライ（無限リトライ）され
    ます。指定回数だけリトライしても成功しなかった場合は、そのコマンドはエラ
    ーとなり、キューより取り除かれます。
    また、CDカバーが開けられた場合はキューに登録された全てのコマンドがキャン
    セルされます。この場合、コマンドにコールバック関数が設定されていれば各コ
    ールバック関数がキューに積まれている順番にキックされます。

  5.6 コールバック

    プリミティブコマンドが終了した場合のコールバック関数の設定方法には、各コ
    マンドに設定する方法と共通のコールバック関数を設定する方法の２つがありま
    す。
    各コマンドにコールバック関数を設定した場合は、そのコマンドの終了以外では
    関数呼出しは行われません。またコマンド終了後はコールバック関数の設定は自
    動的に解除されます。
    共通コールバックを設定した場合は、全てのコマンドの終了時と、非同期（CDカ
    バーが開けられたときなど）に発生するエラー時にキックされます。

  5.7 複数の処理について

    コマンドキューには複数のコマンドを一度に登録することができますが、これは
    複数の処理（データリードや再生）を一度に発行できるということではありませ
    ん。データリードコマンド（DslReadN、DslReadS）および再生コマンド（DslPlay）
    は、処理としてはコマンドがCDサブシステムに受理された時点で終了となります。
    コマンドキューはこの終了によってリード（再生）コマンドをキューから削除し、
    次に何らかのコマンドがあった場合はそのコマンドをCDサブシステムに発行しま
    す。次に発行されたコマンドによってはデータリード（再生）処理は中止されま
    すので、目的のデータが得られないことになります。
    よって、コマンドキューのレベルでは複数のデータリード（再生）処理を一度に
    登録することはできません。複数のデータリード（再生）処理を行う場合は、そ
    れぞれの処理に対応するコマンドを発行し、必要な量のデータを読み出して（必
    要な時間再生を行って）から次のコマンドをキューに発行してください。

 6 コマンドパケット
--------------------

    コマンドパケットとはコマンドキューにプリミティブコマンドを発行する方法の
    一つで、CDのデータリード（CD-DAの再生）のための一連のコマンドをまとめて発
    行します。データリード（再生）を行うためには、
         ・ポーズ（前の処理を確実に終わらせるため）
         ・動作モードの設定
         ・先頭ポジションの指定
         ・リード
    の４つのプリミティブコマンドを発行する必要があります。これらの４つのコマ
    ンドを１回の関数呼出しでキューに登録することができます。
    コマンドパケットとしてコマンドを発行することで、安定したCDアクセスを行う
    ことができます。コマンドパケットでは動作モードと先頭ポジションを毎回指定
    しますので、その前CDサブシステムの状態に左右されません。また、エラー時の
    リトライも先頭から行うため、リトライの成功率が高くなります。

  6.1 コマンドパケットの発行

    コマンドパケットを発行するにはDsPacket()を使用します。
    
        int DsPacket( u_char mode, DslLOC* pos, u_char com, DslCB cbsync, int count );
        	mode		動作モード
        	pos		先頭ポジション
        	com		リード（再生、シーク）コマンド
        	cbsync		コマンド終了コールバック関数のポインタ
        	count		リトライ回数（-1：無限リトライ）
    
    この関数を実行すると、キューに以下の４つのコマンドが登録されます。
         ・DslPause			0
         ・DslSetmode			mode
         ・DslSetloc			pos
         ・comで指定されたコマンド		0
    comにはDslPlay、DslReadN、DslReadSのいずれかのコマンドを指定することがで
    きます。
    また、comにシークコマンド（DslSeekL、DslSeekP）を指定すると、シークの終了
    までをパケットとすることができます。これにより、先行シークなどを行うこと
    ができます。

  6.2 終了確認

    コマンドパケットの終了を確認するためには、発行時にコールバック関数を指定
    するかDsSync()を使用します。コマンドパケットは、展開された全てのプリミテ
    ィブコマンドの実行が終了した時点で終了します。DsSync()で確認する場合は、
    プリミティブコマンドと同じようにコマンドIDで参照してください。resultには、
    最後のプリミティブコマンドの実行結果が格納されます。

  6.3 処理タイミング

    コマンドパケットは、展開されたプリミティブコマンドがコマンドキューによっ
    て処理されます。よって、処理タイミングはコマンドキューの動作に準じます。

  6.4 エラー時の動作

    パケット中のコマンドがエラーとなった場合もリトライが行われますが、普通の
    コマンド（DsCommand()で発行したもの）と異なり、リトライはパケットの先頭の
    コマンドから行われます。これは成功率の高いリトライを行うためで、データリ
    ード（再生）に関しては一つずつコマンドを発行するよりもパケットとして発行
    されることを推奨します。
    リトライを行う回数はcountで指定します。普通のコマンドと同じくcount == 0で
    はリトライを行わず、count == -1で無限リトライです。リトライ回数を超えてエ
    ラーが発生した場合はパケットはキューから取り除かれます。

 7 簡易コールバック
--------------------

    CDからデータを読み出す場合は、データリードコマンドを発行し、発生するデー
    タレディ割込み毎にデータをCDのセクタバッファからメインメモリに転送する処
    理を行いますが、データレディ割込みのハンドリングを容易に行う機能が簡易コ
    ールバックとしてライブラリで提供されます。

  7.1 簡易コールバックの機能

    簡易コールバックはデータレディ割込みにフックされます。割込みで行う処理の
    うち、データが正常に読み込めた場合はアプリケーションで記述します。ライブ
    ラリではエラーが発生した場合のリカバリー処理を行います。
    簡易コールバックを使用するには、DsStartReadySystem()を呼び出します。
    
        int DsStartReadySystem( DslRCB func, int count );
        	func		データリード成功時のコールバック関数のポインタ
        	count		リトライ回数（-1：無限リトライ）
    
    コールバック関数は、基本的にデータが正常に読み込めた場合にのみキックされ
    ます。エラー時のリカバリーはシステムで自動的に行われます。
    countはリトライの回数を設定します。count == -1で無限リトライとなります。
    リトライ回数を超えてエラーが発生した場合は、コールバック関数が
    DslDiskErrorでキックされます。
    
    DsStartReadySystem()は、対応するリードコマンド（パケット）の終了コールバ
    ック内で、コマンドの成功を確認して呼び出してください。これより早いタイミ
    ングで呼び出すと、エラーリカバリーが誤動作する可能性があります。現在の
    CD-ROMシステムではコマンドに対するエラーとそれ以外のエラーの区別がないた
    め、簡易コールバックのシステムがコマンドのエラーに反応してしまうためです。
    また、システムの開始が遅れると先頭セクタを取りこぼす可能性があります。

  7.2 リカバリー時の挙動

    リードの途中でエラーが発生すると、簡易コールバックシステムはリカバリーを
    行います。リカバリーは、システムに保存されている情報（最後に発行したコマ
    ンド、最後に設定された動作モード、最後にシークされた位置、現在の位置など）
    を元にコマンドを発行し直すことで行われます。
    
    リカバリーの際のシーク位置はシステムによって決定されます。再開されたリー
    ドは、エラーが発生したセクタの手前から行われますが、funcで設定したコール
    バック関数は前回成功したセクタの次のセクタが読み出されるまでキックされま
    せん。例えば最初のリードで４セクタ目でエラーが発生した場合、既に３セクタ
    までの処理は終了しているわけですが、リカバリーが行われて再び４セクタ目の
    データが読み出されたときにコールバック関数がキックされます。
    
        １回目	１、２、３、（４）
        	            ↑ここでエラー（コールバックはキックされない）
        	リカバリーで手前にヘッドが戻される
        ２回目	．．．．．．４、５、６
        	            ↑このセクタからコールバック関数がキックされる

  7.3 コールバック関数の記述

    データリード時にキックされるコールバック関数は、以下の書式で記述します。
    
        void function( u_char intr, u_char* result, u_long* subhead );
    
    intrおよびresultは通常のデータレディコールバック関数と同じように割込みの
    情報が参照されます。簡易コールバックでは、ほとんどの場合はintr == 
    DslDataReadyもしくはintr == DslDataEnd（DA再生時のみ）です。intr == 
    DslDiskErrorとなるのは、
         ・リトライ回数を超えてエラーが発生した場合
         ・途中でCDカバーが開けられた場合
    です。この時のリカバリーはアプリケーションで記述する必要があります。
    
    データリードが成功してコールバック関数がキックされたときには、データのサ
    ブヘッダの転送は終了しています。これは、システム側でサブヘッダを見てデー
    タの確認を行っているためですが、セクタバッファのポインタはデータの先頭に
    移っていますので、すぐにデータ本体の転送を行うことができます。データ本体
    の大きさは2048bytesです。

  7.4 システムの終了

    目的のデータがリードできた場合は、簡易コールバックを終了させてください。
    簡易コールバックを終了させるにはDsEndReadySystem()を使用します。
    
        void DsEndReadySystem( void );
    
    システムの終了は、最後のセクタを読み込んだ直後に行う必要があります。終了
    が遅れるとリードが進み、余分なコールバックが発生してメモリを破壊すること
    が考えられます。よって、最後のセクタを転送したコールバック関数の中で終了
    するようにしてください。

  7.5 注意点

    簡易コールバックを使用してデータリードを行う場合は、動作モードの設定でセ
    クタサイズを2340bytes（DslModeSize1ビットをON、DslModeSize0ビットをOFF）
    にしてください。

 8 その他
----------


  8.1 CDカバーの開閉

    PlayStationのCD-ROMドライブでは、途中でCDカバーの開閉が行われると特殊な処
    理を必要としていましたが、libdsではこの処理をシステムで行います。
    CDカバーが開けられるとシステムはビジー状態（DslBusy）に移行し、ユーザーか
    らのコマンドの発行をブロックします。カバーが閉じられるとシステムはディス
    ク再認識のための処理を行い、レディ状態（DslReady）に戻ります。
    CDカバーが開けられたとき実行されていた処理はエラーとなります。また、コマ
    ンドキューに登録されている全てのコマンドが削除されます。よって、システム
    がレディ状態となるのを待って処理をやり直してください。なお、CDカバーの開
    閉処理が終了した直後は動作モードおよびヘッドの位置は初期化されていますの
    で、これをふまえた処理のやり直しを行ってください。

  8.2 CDの入れ替えに関する注意点

    実行中にCDの入れ替えを行う場合、カバーの開閉に関する処理はシステムで行わ
    れます。ただし、セットされたCDの種類の認識は行いませんので、アプリケーシ
    ョン側で行う必要があります。
    libdsライブラリでは、libcdで提供されていたCdDiskReady()までの処理を自動化
    しています。よってシステムのステータスがDsSystemStatus() == DslReadyとな
    った後にCDの種類を認識するようにしてください。なお、libcdで用意されていた
    CDの種類を得るための関数と同等の関数DsGetDiskType()も用意されています。関
    数についてはリファレンスを参照してください。
    
    libdsで推奨されるCDの入れ替え手順は以下の通りです。
         (1) CDの回転を止める。
         (2) 入れ替えメッセージを出力する。できれば入れ替え終了時にボタン入力
             で確認を取る。
         (3) DsStatus()で最新の結果をポーリングし、カバーが開けられた（
             DslStatShellOpenビットが立つ）ことを確認する。
         (4) DsSystemStatus() == DslReadyとなるのを待つ。
         (5) DsGetDiskType()でCDの種類を調べ、PlayStationディスクであることを
             確認する。
         (6) 目的のディスク（他のゲームのディスクではないか、何枚目のディスク
             かなど）かどうかを確認する。
    手順４でDslNoCDが返された場合は、ライブラリでCDがセットされていることが確
    認できなかった（一定時間内にCDのスピンドルが回らなかった）ことを示します。
    「CDが認識できません」などのメッセージを出力し手順２に戻ってください。手
    順５でPlayStationディスクと確認できなかった場合も同様にメッセージを出力し、
    手順２に戻ります。
    なお、手順２でボタン入力で確認を取るようにした場合は手順３は省いてもかま
    いません。また、手順６の確認はディスクの特定の位置に特定のデータを書くな
    ど各アプリケーションで確認方法を設定してください。

  8.3 先行シーク

    プログラムで、次にリードするデータファイルが決まっている場合に前もってフ
    ァイルの先頭までシークを行っておくことで、データリードにかかる時間を見か
    け上短縮することができます。コマンドパケットでシークを行うとエラー時のリ
    トライも自動化されますので、メインフローの負担は最小になります。状況によ
    って異なりますが、先行シークを行えばデータリード時の所用時間は約０．４秒
    ほど短縮されます。
    またゲームの進行に合わせてXAオーディオを再生する場合などは、先行シークを
    行うことでタイミングが合わせやすくなります。

  8.4 複数ファイルの連続リード

    データの切り替えで複数のデータファイルをリードする必要がある場合、ロード
    時間を短縮するにはシークを減らすことが最も効果的です。シークを減らすには、
    データファイルを連続してCDにレイアウトし、１回のリードで複数のファイルを
    読み込みます。シークを１回減らすことで約０．４秒の短縮ができますので、５
    回減らすとロード時間が２秒短縮されます。
    各ファイルのメインメモリ上の転送先が異なる場合はリードの途中で転送アドレ
    スを切り替える必要がありますが、簡易データコールバックを使えば実現が容易
    になります。libdsのサンプルに簡易データコールバックを使用して実現したもの
    がありますので、こちらも参照してください。

  8.5 外周３分問題

    現在のCD-ROMサブシステムでは、CD-ROMの外周３分以内へシークする場合、シー
    ク開始地点によっては、正しくシークが行なわれない場合があります。
    この現象を回避するために以下のいずれかの方法をとる必要があります。
         ・最外周３分（データの最後の３分）にダミーデータを入れておく（ダミー
           データは使用しない）。
         ・BGMなどにCD-DAを使用する場合、最終曲を３分以上にする。この場合は、
           曲の途中から再生したり、曲の途中でリピートをかけない限り、最外周３
           分へのシークは発生しません。従ってCD-ROMサブシステムは正常に動作し
           ます。
         ・どうしても最外周３分をデータエリアとして使いたい場合は、外周３分以
           上は連続した１つのファイルとしてアクセスする（オープニング、エンデ
           ィングのムービに使用するなど）。
    なお、ここで言う外周とはディスクの物理的な外周ではなく、データ（DA）が記
    録された領域の最外周のことです。

  8.6 DslPlay、DslReadN、DslReadSの注意点

    現在のCD-ROMシステムでは、コマンドDslPlay、DslReadN、DslReadSはコマンドコ
    ードをCDサブシステムが受理した時点でコマンドとしての処理を終了し、
    DslCompleteを返すようになっています。ただし、実際はその後も処理を継続して
    おり、この処理でエラーが発生することがあります。
        発行．．．．成功．．．．．．．．．．シーク完了．．．．（データリード）．．．
                                      ↑この段階でエラーになることがある
    
    このエラーは割込みとして報告されますが、コマンドとの対応は取れていません
    ので（コマンドの処理としては最初のCompleteで終了したとみなされる）キュー
    のリトライ対象となりません。そのため、このエラーについてはアプリケーショ
    ン側で対応する必要があります。
    このエラーは、各コマンドに設定できるコールバック関数には反映されません。
    このエラーが報告されるコールバックはデータレディコールバック（
    DsReadyCallback()で設定）とコマンドに独立なsyncコールバック（
    DsSyncCallback()で設定）の２つです。エラーをリカバリーするためには、これ
    らのコールバックの中にエラーリカバリールーチンを用意するか、データリード
    が開始されるまでステータスをポーリングしてください。DsSync()の引数idを-1
    にすると、コマンドと対応が取れないエラーの実行結果を得ることができます。
    また、データリードが開始されたことを確認するにはDsStatus()を使用します。
    
    以下にポーリング型のエラー対応例を示します。なお、この例ではリードが開始
    されるまで処理がブロックされてしまいます。これを防ぐためにはリード開始を
    待つルーチンを１フレームに１回呼ぶなどの工夫が必要です。
    
        		:
        		:
        /* リードコマンドをパケットで発行（無限リトライ）
            これが成功するまではシステムでリトライが行われる */
        DsPacket( DslModeSpeed | DslModeSize1, &pos, DslReadN, 0, -1 );
        
        /* リード開始を待つ */
        while( ( DsStatus() & DslStatRead ) == 0 ) {
        	/* id == -1で見つかるエラーはシステムで対応されていない */
        	if( DsSync( -1, result ) == DslDiskError ) {
        		/* リトライを行う
        		   この例ではパケットの再発行で対応する */
        		DsPacket( DslModeSpeed | DslModeSize1, &pos, DslReadN, 0, -1 );
        	}
        }
        		:
        		:
    
    データレディコールバックを使用した場合は、以下のようになります。
    
        		:
        		:
        	/* パケット発行時にsyncコールバック関数を設定しておく */
        	DsPacket( DslModeSpeed | DslModeSize1, pos, DslReadN, cbsync, -1 );
        		:
        		:
        }
        		:
        /* パケットのsyncコールバック関数
           処理が成功した場合にデータレディコールバックをフックする */
        void cbsync( u_char intr, u_char* result )
        {
        	if( intr == DslComplete ) {
        		/* ここでレディコールバックをフックすることで、
        		   コマンドに対するエラーと混同するのを防ぐ */
        		DsReadyCallback( cbready );
        	}
        }
        		:
        		:
        /* レディコールバック関数
           データ転送に使うが、エラー時のリカバリーを持たせる */
        void cbready( u_char intr, u_char* result )
        {
        	if( intr == DslDiskError ) {
        		/* コールバックをクリアしておいてから・・ */
        		DsReadyCallback( 0 );
        		/* パケットを再発行する */
        		DsPacket( DslModeSpeed | DslModeSize1, pos, DslReadN, cbsync, -1 );
        		return;
        	}
        	if( intr == DslDataReady ) {
        		/* データ転送ルーチン（省略） */
        	}
        }
    
    この場合に注意すべきことは、データレディコールバックには全てのエラーが報
    告されてしまうということです。コマンド発行に対するエラーも報告されてしま
    うため、コールバック関数を割込みにフックするタイミングは気を付ける必要が
    あります。この例では、パケットの成功時にフックされるようになっています。
    また、この方式を取った場合はリードが終了した場合にすぐにデータレディコー
    ルバックを外すようにしてください。これを忘れると意図されない場所でリード
    のパケットが発行されてしまいます。
    
    なお、簡易コールバックではこのエラーについて対応を行っていますので、アプ
    リケーション側でこの対策を取る必要はありません。

  8.7 データリードの終了について

    CDのデータをリードするためにコマンドを発行し、データレディコールバックで
    データの転送を行うシステムをアプリケーションで構成する場合、リードの終了
    処理にコツがあります。
    リードを終了する場合、コマンドDslPauseを発行することで動作は停止しますが、
    コマンドがCDサブシステムに受理されて動作が停止するまでの間に１、２セクタ
    余分にリードしてしまうことがあります。データレディ割込みにフックされたコ
    ールバック関数によっては、この余分なデータをメインメモリに転送してしまい、
    データを破壊する可能性があります。これを防ぐためには、目的のセクタ数をリ
    ードしたら直ちにコールバック関数を割込みから外してください。コールバック
    関数を外すには、引数0でDsReadyCallback()を呼び出します。コールバック関数
    を外すことで、余分なセクタが読み出されても、メインメモリに転送されなくな
    ります。その後でDslPauseを発行してリード動作を停止させてください。
