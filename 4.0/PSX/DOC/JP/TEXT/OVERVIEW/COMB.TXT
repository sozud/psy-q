                                                 Library Overview Release 4.0

対戦ケーブルライブラリ（libcomb）
==================================

  2台のPlayStationを接続し、連携動作させるためのサービスを提供するためのライ
  ブラリです。データを高速に交換する通信機能によって、各種の対戦ゲームを実現
  できます。

 1 概要
--------

    「対戦ケーブルライブラリ」は2台のPlayStationの拡張SIOコネクタ間を「対戦ケ
    ーブル」で接続し通信を行なう機能を提供します。
    送受信はread()およびwrite()関数で行ないます。いずれも処理が完了するとイベ
    ントが発生する非同期モードと、通信が完了すると関数が終了する同期モードを
    サポートします。最大通信レートは2M((2073600)bps。通信形態は非同期シリアル
    通信です。通信レートの変更は_comb_control()で行ないます。

  1.1 ライブラリファイル

    対戦ケーブルライブラリのファイル名は「libcomb.lib」です。
    各サービスを呼び出すプログラムは、必ずこれをリンクする必要があります。

  1.2 インクルードヘッダ

    対戦ケーブルライブラリを使うためにはヘッダファイル「libcomb.h」が必要です。

        表 1
    +------------------+-----------+
    |内容               ファイル名 |
    |インクルードヘッダ libcomb.h  |
    |ライブラリ         libcomb.lib|
    +------------------+-----------+

  1.3 3.6からの変更点

         (1) 取りこぼしによる受信エラーを避けるため、DSR/DTR信号による受信文字
             数単位のハンドシェイクを行うようにしました。
         (2) 非同期送信に使用する割り込み信号を従来のDSRから、TXIENによる割り
             込みに変更しました。
         (3) DTR/RTSの制御に使用していた、_comb_control( 3,0,* )を、RTSのみの
             制御にしました。
         (4) DSR/CTSの取得に使用していた、_comb_control( 3,1,* )を、CTSのみの
             取得にしました。
         (5) 通信プロトコルを、キャラクタ長8ビット、ストップビット 1、パリティ
             無しに固定しました。
         (6) 相手局と垂直同期を合わせるための、垂直同期reset機能 
             _comb_control(5,0,0)を追加しました。

 2 ドライバとBIOS
------------------

    対戦ケーブルライブラリは「対戦ケーブルドライバ」と「対戦ケーブルBIOS」か
    ら構成されています。

  2.1 対戦ケーブルドライバ

    対戦ケーブルドライバはC言語標準の手順による入出力を提供します。

        表 2：対戦ケーブルドライバ
    +--------------+--------------------------------+
    |項目           内容                            |
    |デバイス名     sio                             |
    |ブロックサイズ 1,2,4,8バイト                   |
    |               非同期writeは1バイト単位        |
    |非同期モード   オープン時にO_NOWAITマクロで指定|
    +--------------+--------------------------------+

  2.2 イベント

    次のイベントがドライバによる入出力に伴って発生します。
    EvSpIOEWとEvSpIOERは非同期入出力要求発行後に発生します。EvSpERRORは同期お
    よび非同期read時に発生します。

        表 3
    +------------------+------------+----------------------------------+
    |原因ディスクリプタ イベント種別 通知内容                          |
    |HwSIO              EvSpIOEW     非同期writeの完了                 |
    |                   EvSpIOER     非同期readの完了                  |
    |                   EvSpERROR    受信関連エラーの発生（非同期のみ）|
    |                   EvSpTIMOUT   同期read/writeでのタイムアウト    |
    +------------------+------------+----------------------------------+

  2.3 組み込みと削除

    対戦ケーブルドライバの組み込みはAddCOMB()にて行ないます。同じく削除は
    DelCOMB()で行ないます。
    ドライバを組み込まない状態でのデバイスsioへのオープン操作はエラーとなりま
    す。

  2.4 ウエイトコールバック

    同期read/write中で、先行データの処理をシリアルコントローラの状態をテスト
    するソフトウェアループが実行されます。ウエイトコールバック関数はこのルー
    プ中で呼び出される関数です。
    デフォルト状態ではコールバック関数は未登録です。_comb_control(4,0,func)に
    より、関数funcをコールバック関数とすることができます。この関数は次の仕様
    を満たさなくてはなりません。また_comb_control(4,0,NULL)によりコールバック
    関数の登録を解除できます。
    
        形式	long func( void )
        引数	なし
        返り値	ウエイトループをタイムアウト終了させる場合は0、
        	ウエイトを継続する場合は1を返す。

  2.5 同期入出力の終了条件

    同期readは指定文字数が受信できると終了します。また、パリティ・オーバーラ
    ン・フレームの各受信エラーのいずれかが検出されるか、ウェイトコールバック
    関数が所定の値を返した場合に途中終了します。いずれも受信文字数を返します。
    同期writeは指定文字数を送信できると終了します。また、ウェイトコールバック
    関数が所定の値を返した場合に途中終了します。

  2.6 割り込みとread/write関数

    対戦ケーブルライブラリの殆どの関数は、クリティカルセクションに入ることの
    ないように設計されており、イベントハンドラ中での呼び出しが可能となってい
    ます。しかし、シングルスレッドでの運用が前提とされているため、マルチスレ
    ッド環境下では完全な動作は保証されません。
    現行のPlayStationライブラリをシングルスレッドで運用される場合は全く問題あ
    りませんが、オリジナルのスレッド管理を行われている場合、当ライブラリ・ド
    ライバの動作は保証できません。

  2.7 受信単位文字数

    PlayStationは8バイトの受信バッファを備えており、非同期read実装時において
    は、受信割り込みの発生を1,2,4または8バイト単位に設定することができます。
    また、同期通信時には、DSR/DTRによるハンドシェイクを行う単位数として使用さ
    れます。
    ただし、非同期writeを実装する場合は、送信割り込みの性質上、1バイト単位で
    の動作が前提となるため、このパラメータは必ず1に設定する必要があります。

  2.8 エラー処理

    非同期入出力中にオーバーラン・パリティ・フレームの各受信エラーを検出する
    と、ドライバは次の関数呼び出しにより非同期read要求をキャンセルし、続いて
    EvSpERRORイベントをデリバリします。この関数はシリアルコントローラのエラー
    フラグをクリアします
    
      _comb_control(2,3,0);	/* 非同期read要求のキャンセル */

  2.9 BIOS

    対戦ケーブルBIOSはC言語標準の関数仕様ではカバーできない詳細なドライバの制
    御と情報取得機能を提供します。インタフェース関数は_comb_control()です。
    なお、BIOSは対戦ケーブルドライバを組み込まない状態でも稼働します。
    _comb_control()が提供する機能を次に示します。
    
        形式	long _comb_control(cmd, arg, param)
        	unsigned long cmd;
        	unsigned long arg;
        	unsigned long param;
        
        引数	cmd	コマンド
        	arg	サブコマンド
        	param	引数
        

        表 4：コマンド一覧
    +---+---+-----------------------------------------------------------+
    |cmd arg 機能                                                       |
    |0   0   シリアルコントローラステータス（＊１）を返す。             |
    |    1   制御ラインステータス（＊２）を返す。                       |
    |    2   通信モード（＊３）を返す。                                 |
    |    3   通信速度（bps単位）を返す。                                |
    |    4   受信単位文字数を返す。                                     |

  2.10 シリアルコントローラ

    対戦ケーブルコネクタを駆動するデバイスは、非同期通信をサポートするシリア
    ルコントローラ（以下、単にシリアルコントローラ）です。

  2.11 バッファ

    シリアルコントローラには1バイトの送信バッファと8バイトの受信バッファが用
    意されています。

  2.12 制御線

    シリアルコントローラにはDTR/DSRとRTS/CTSの2組の制御線が用意されています。
    双方ともread() / write()時の同期用に使用されます。

        表 8：制御線
    +----------+----------+---------------------------+--------------+
    |送信側名称 受信側名称 受信側機能                  受信側割り込み|
    |DTR        DSR        通信時での使用不可          なし          |
    |RTS        CTS        OFFの場合は受信機能自動停止 なし          |
    +----------+----------+---------------------------+--------------+

  2.13 通信仕様

    通信仕様は次に示す設定から任意に選択することができます。

    |キャラクタ長     8ビット                           |
    |ストップビット   1ビット                           |
    |パリティチェック なし                              |
    |通信速度         1～2073600bps（2073600の約数のみ）|
    +----------------+----------------------------------+

  2.15 制御線遷移

    ドライバは次のようにDTR（受信側はDSR）とRTS（受信側はCTS）を操作します。

        表 11：制御線遷移
    +----------------------------------------------+----------+
    |ドライバ操作                                   DTR  RTS  |
    |パワーオン（相手局なしor相手局電源オフ）         1    1  |
    |         （相手局あり、ドライバ未＋－初期化）    0    0  |
    |ドライバ初期化                                           |
    |         AddCOMB();                              0    0  |
    |同期write                                                |
    |         open("sio",O_WRONLY) ;                  -    -  |
    |         write(...);                             -    -  |
    |         write完了                               -    -  |
    |         close();                                -    -  |
    |同期read                                                 |
    |         open("sio",O_RDONLY);                   -    -  |
    |         read(...);                              -    1  |
    |         read完了                                -    0  |
    |         close();                                -    -  |
    |非同期write                                              |
    |         open("sio",O_WRONLY|O_NOWAIT);          -    -  |
    |         write(...);                             -    -  |
    |         送信割り込み発生                        -    -  |
    |         送信割り込み完了                        -    -  |
    |         write完了                               -    -  |
    |         close();                                -    -  |
    |非同期read                                               |
    |         open("sio",O_RDONLY|O_NOWAIT);          -    -  |
    |         read(...);                              -    1  |
    |         受信割り込み発生                        -    1  |
    |         受信割り込み完了                        -    1  |
    |         read完了                                -    0  |
    |         close();                                -    -  |
    +----------------------------------------------+----------+
    

 3 プログラミングのヒント
--------------------------


  3.1 相手局接続の検出（１）

    対戦ケーブルが接続されていない場合、または接続されていても相手局の電源が
    入っていない場合は、DSR/CTSともに1となっています。これに対し、対戦ケーブ
    ルが接続され、かつ相手局の電源が入っていれば、DSR/CTSともに0となり、この
    状態はAddCOMBによるドライバの組込み後も変化しません。
    当ライブラリにおいてDSR/CTS信号はread関数を発行しない限り内部での操作は行
    われないため、
    AddCOMB実行直後の初期化プロセスにおいて、暫定的にDTRかRTSのどちらかを1に
    することで、相手局に通信準備の整ったことを通知するという方法があります。
    相手局にも同様の処理をさせることで、双方で通信準備が整ったことを確認しあ
    うことができます。ただし、RTSを使った場合は、その後のread/write関数への影
    響を防ぐため、0に戻す必要があります。

  3.2 相手局接続の検出（２）

    通信中に対戦ケーブルが外れた場合、または相手局の電源がオフになるなど、相
    手局の状態に異常が発生した場合の検出については、基本的に時間制約を設けた
    検出アルゴリズムが必要となります。
    より簡便な検出方法として、ウェイトコールバックを利用し、相手局のレスポン
    スを常に監視し、そのレスポンスの有無はまた速度によって相手局の状態を推測
    するという方法があります。
    しかし、これだけでは相手局の異常な状態が、非結線によるものなのか通信エラ
    ーによるものかのどちらかまでは判断できません。より詳細な状態を検出するに
    は、さらに再送信を行うなどの通信エラー対策を尽くした上で、それでも状態が
    改善されないならば、非結線と判断するという手段が必要となります。
    どちらにしても、相手局との接続を検出する決定的な手段はなく、時間制約ベー
    スでの検出アルゴリズムが必要となります。

  3.3 リングバッファによるバックグラウンド受信

    read関数はクリティカルセクション中で実行できます。よって、EvSpIOERイベン
    トハンドラ中でread関数を呼び出すことにより、次の非同期受信要求をドライバ
    に登録できます。read関数に与える受信バッファポインタを操作することにより、
    簡単にリングバッファへのバックグラウンド受信を実現できます。
    write関数もクリティカルセクション中で実行できますので、受信データ内容をテ
    ストすることによる再送要求発行などの処理を上記のリングバッファ操作コード
    の「手前」に実装することも可能です。

  3.4 非同期writeは遅い

    非同期送信は当ライブラリ・ドライバの運用形態の中で最もCPU負荷の高い動作で
    す。
    これは送信よりも受信が優先されないとオーバーランなどの受信エラーが発生し、
    トータルで性能が低下することに起因しています。また非同期通信の効率が同期
    通信のそれに比べて低いことも原理上避けられません。
    以上から、同期・非同期のread・writeの4つの組み合わせのうち、非同期writeが
    最もCPUに負担をかける運用形態となります。
    また、非同期writeはより低いボーレートでパフォーマンスが発揮される性質上、
    実際の運用において、57600bpsを超える通信では正常な動作は期待できません。

  3.5 最もオーバヘッドが軽い送信

    送信すべきデータを受信バッファサイズである8文字長のパケットに分割し、コー
    ド中に適宜分散して配置した同期writeで送信する。これが最もCPU負荷の小さな
    送信形態となります。もちろん各write関数は一定時間内に終了すべきでしょうか
    ら、全write関数にタイムアウトコールバック関数による最大待ち時間を設定し、
    制限時間が来たならば送信を中断します。中断時点での送信済み文字数はwrite関
    数の返り値として得
    られますので、次のwrite関数に与える送信データを示すポインタをこの値を元に
    修正します。

  3.6 １文字以外の受信文字数

    1文字以外の値を受信文字数として非同期read要求を発行した場合、その文字数に
    満たないデータが受信された状態をドライバが検出できません。この状態は送信
    側の動作次第でデッドロックにつながりますので、アプリケーションレベルでタ
    イムアウト処理を実装する必要が生じます。
