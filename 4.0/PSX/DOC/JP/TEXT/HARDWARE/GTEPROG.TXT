                                                               Hardware Guide

ＧＴＥプログラミングガイド
---------------------------


 1 形態

    ＧＴＥはＭＩＰＳアーキテクチャで定義されるところの「コプロセッサ２」とし
    て実装されたベクトル・行列演算器です。扱うデータ形式は固定小数点形式の実
    数です。
    

 2 レジスタ

    ＭＩＰＳアーキテクチャにおけるコプロセッサは、「データレジスタ」および「
    制御レジスタ」と呼ばれるレジスタ群を持つことができます。ＧＴＥは３２本の
    データレジスタと３２本の制御レジスタを持っています。これらはすべて３２ビ
    ットレジスタであり、ＣＰＵからのアクセスはレジスタを単位に行われます。し
    かし、いくつかのレジスタは複数の８または１６ビットフィールドに分割されて
    います。ＧＴＥが行うすべての演算において、ＧＴＥレジスタだけが参照・変更
    されます。
    各レジスタの詳細についてはドキュメント「ＧＴＥレジスタ仕様」を参照くださ
    い。
    

    レジスタアクセス命令：

      以下のＣＰＵ命令を実行することにより、ＧＴＥレジスタとＣＰＵレジスタ、
      またはＧＴＥレジスタとメインメモリ（スクラッチパッドを含む）との間でデ
      ータを転送することができます。
    
    +----------+------------------------+------------------------+
    |ＣＰＵ命令 ソース                   ディスティネーション    |
    +----------+------------------------+------------------------+
    |lwc2       メモリ・スクラッチパッド ＧＴＥデータレジスタ    |
    |swc2       ＧＴＥデータレジスタ     メモリ・スクラッチパッド|
    |mtc2       ＣＰＵ汎用レジスタ       ＧＴＥデータレジスタ    |
    |mfc2       ＧＴＥデータレジスタ     ＣＰＵ汎用レジスタ      |
    |ctc2       ＣＰＵ汎用レジスタ       ＧＴＥ制御レジスタ      |
    |cfc2       ＧＴＥ制御レジスタ       ＣＰＵ汎用レジスタ      |
    +----------+------------------------+------------------------+
    
      mtc2, mfc2, ctc2, cfc2 はレジスタ間転送ですが、オンキャッシュのメモリア
      クセスと同様に Delayed Loads されます。以下のような例では delay slot に
      nopを入れてください。
    
        例1：
        cfc2	v0,C2_FLAG
        and	v0,v0,v1	# No good
        
        例２：
        cfc2	v0,C2_FLAG
        nop			# delay slot
        and	v0,v0,v1

 3 コマンド

    GTEは座標変換・透視変換・光源計算などのグラフィックスプログラミングに不可
    欠な一連の演算をひとつのコマンドとして実行します。また、行列演算・外積・
    内挿などの汎用行列・ベクトル演算もコマンドとして提供します。いずれもＣＰ
    Ｕによる場合に比べて数倍以上高速な演算が行えます。
    ＧＴＥコマンドの詳細については、ドキュメント「ＧＴＥコマンドリファレンス」
    を参照ください。なお、ＧＴＥコマンドはDMPSX付属のファイル「inline.h」にマ
    クロ定義されています。
    

    ディレイスロット：

      ＣＰＵ命令のひとつであるコプロセッサ２コマンド実行命令「cop2」は、先行
      する他のＧＴＥに関する命令に対して２つのディレイスロットを要求します。
    
        例３：
        mtc2	v0,C2_VXY0
        nop			# delay slot
        nop			# delay slot
        RTPS
    

    コマンド実行サイクル：

      ＧＴＥの各コマンドは実行終了までに以下のサイクル数を必要とします。コプ
      ロセッサ２コマンド実行命令の実行後、所定のサイクル数を空けずにＧＴＥレ
      ジスタの読出命令(swc2,mfc2,cfc2)または後続のコプロセッサ２コマンド実行
      命令を実行すると、ＣＰＵはＧＴＥコマンドの実行が完了するまでストール(動
      作停止)します。
         
        例４：
        RTPS                  -+
        ## interlock           |   15 cycles
        cfc2	v0,C2_FLAG    -+
        
        例５：
        RTPS                  -+
        add	v1,v2,v3       |
        sub	v1,v2,v3       |   15 cycles
        ## interlock           |
        cfc2	v0,C2_FLAG    -+
    

    コーデイング上の制約：

         (1) ＧＴＥ命令(cop2)はイベントハンドラやコールバック関数中で実行して
             はならない。
         (2) ＧＴＥ命令(cop2)はジャンプやブランチ命令後のディレイスロットに入
             れてはならない。
         (3) ＧＴＥレジスタアクセス命令(lwc2,swc2,mtc2,mfc2,ctc2,cfc2)はジャン
             プやブランチ命令後の ディレイスロットに入れてはならない。
         (4) ＧＴＥレジスタロード命令(lwc2,mtc2,ctc2) はＧＴＥ命令(cop2)とＧＴ
             Ｅレジスタセーブ命令(swc2,mfc2,cfc2)の間、ＧＴＥ命令(cop2)とＧＴ
             Ｅ命令(cop2)の間では使用してはならない。
    
        例６：
        /* cop2-load-save (NG) */
        RTPS				/* cop2 */
        ...				/* cpu instructions */
        mtc2	v0,C2_VXY0		/* NG !!!!!! */ 
        ...				/* cpu instructions */
        cfc2	v0,C2_FLAG		/* save instruction */	
        
        例７：
        /* cop2-load-cop2 (NG) */
        RTPT				/* cop2 */
        ...				/* cpu instructions */
        mtc2	v0,C2_VXY0		/* NG !!!!!! */ 
        ...				/* cpu instructions */
        NCLIP				/* cop2 */
    
         (5) ロード対象ＧＴＥレジスタが実行途中のＧＴＥコマンドにより参照・書
             き換えられない場合には、ＧＴＥコマンド実行命令(cop2)と関係なくＧ
             ＴＥレジスタへのデータ転送命令を実行することができる。
    
        例８：
        /* cop2-load-save (OK) */
        RTPS				/* cop2 */
        ...				/* cpu instructions */
        mtc2	v0,C2_VXY1		/* OK !! */ 
        ...				/* cpu instructions */
        cfc2	v0,C2_FLAG		/* save instruction */
        
        例９：
        /* cop2-load-cop2 (OK) */
        RTPT				/* cop2 */
        ...				/* cpu instructions */
        mtc2	v0,C2_RGB		/* OK !! */ 
        ...				/* cpu instructions */
        NCLIP				/* cop2 */ 
    

 4 推奨される開発スタイル

    アセンブラコーディングでは上記の規則に反した不適正なプログラムでも一見正
    常に動作する場合があります。しかし、割り込み時に異常動作するなど非常に発
    見しにくいバグになり、危険ですので直接アセンブラでコーディングすることは
    極力お避けください。不適正なコードが生成されないよう、以下の順での開発を
    お勧めします。 
    
      Ｃ言語(libgte) -> Ｃ言語(DMPSX) -> アセンプラ言語(DMPSX）
