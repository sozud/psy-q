↑ 1 概要

CD-ROMライブラリ（libcd）では、PlayStationに搭載されたCD-ROMドライブを制御するサービスを提供しています。CD-ROMライブラリが提供するサービスには以下のものがあります。

  • CD-ROMドライブの制御
  • CDサウンドの制御
  • その他

1. 1 ライブラリファイル

CD-ROMライブラリのファイル名は「libcd.lib」です。
各サービスを呼び出すプログラムは、必ずこれをリンクする必要があります。

1. 2 インクルードヘッダ

CD-ROMライブラリのインクルードヘッダは「libcd.h」です。
各種のデータ構造、マクロはすべてこのファイルで定義されています。各サービスを呼び出すプログラムは必ずこれをインクルードする必要があります。

↑ 2 CD-ROMのセクタ

CD-ROM上にはCDオーディオディスクと同様に、スパイラル状にデジタルデータが記録されています。このデジタルデータは、セクタと呼ばれる処理単位で管理されます。１秒分のデジタルデータ領域は７５個のセクタに分割されます。各セクタはどのような目的で使用されるかによって以下のようなセクタタイプに分けられます。

表 2 セクタタイプ

セクタタイプ格納データ
オーディオセクタCD-DAオーディオデータ
ADPCMセクタADPCM圧縮オーディオセクタ
データセクタユーザーデータセクタ

2. 1 オーディオセクタ

オーディオセクタにはfs=44.1kHzデジタルステレオオーディオデータ（通常のCDオーディオデータ）が記録されています。オーディオセクタは、CdlPlayコマンドで再生させることができます。これをユーザーデータとして読み込むことはできません。

2. 2 データセクタ

データセクタにはユーザーデータが記録されています。データセクタの実効ユーザエリアはモードによって若干異なりますが、標準は2048バイトが使用されます。（mode-1フォーマット）

2. 3 ADPCMセクタ

正式には、リアルタイムセクタ、mode-2form-2セクタと呼ばれるセクタを指します。ここには、ADPCM圧縮音声データが格納されています。これはオーディオセクタ同様に音声として再生することができます。

2. 4 インターリーブ

ADPCMセクタには、通常音声データをオーディオセクタのデータと比べて1/4に圧縮されて記録されています。CD-ROMがセクタごとにシークを行なわないでADPCM再生するためには、ADPCMセクタを４セクタおきにディスク上に配置する必要があります。これをインターリーブとよびます。ADPCMセクタをインターリーブすることで、余ったセクタには他のデータを記録しておくことが可能となり、データを読み込みながらオーディオを再生することができます。
なお、ディスクを標準の２倍（倍速）で再生する場合はインターリーブ間隔は、８セクタおきでなくてはなりません。

↑ 3 アドレッシング

CD-ROMのアドレッシング（位置指定）は、CDオーディオとの互換性からトラック番号・インデクス番号・分・秒・セクタを用いて行なわれます。すなわちCD-ROMデータをオーディオデータとして見た時のトラック番号・インデクス番号、あるいは、ディスクの先頭から数えてその地点が何分何秒何セクタであるかで位置を確定します。
１秒は７５セクタ、１分は６０秒からなります。先頭セクタは、00分02秒00セクタから始まります。

3. 1 トラック

ディスクには各トラックの先頭にトラック信号が記録され、さらにトラック信号の位置のテーブルがディスクの先頭にTOC（Table Of Contents）として記録されています。オーディオセクタの再生開始位置はTOCとトラック信号を用いて検出することができます。

3. 2 絶対セクタ

データセクタは、分・秒・セクタでアドレシングされますが、位置計算を容易にするために先頭（00分02秒00セクタ）からの総セクタ数で数える指定方法もあります。これを絶対セクタ指定と呼びます。絶対セクタは分・秒・セクタの値から容易に計算できます。これを行なうためのCdIntToPos()、CdPosToInt()関数が用意されています。

3. 3 ファイルシステム

これら低レベルのアドレシング手段の他にも、9660ファイルシステムを通じてディスクの絶対値を取得する方法があります。ただし、これはディスクがIS0-9660ファイルシステムフォーマットで記録されている場合に限ります。
CD-ROMはリードオンリーのため、ディスク上のファイルは全て連続したセクタ領域になるように配置しておくことができます。従ってファイルを読み出すためにはそのファイルの先頭位置を確定するだけで良く、通常のFAT（File Allocation Table）に相当するものは必要ありません。ライブラリでは、ファイル名をインデクスとしてファイルの先頭ポジションを検索する関数CdSearchFile()が用意されています。

↑ 4 転送レート

CD-ROMはディスクを標準速度・倍速度のいずれかで回転できます。
標準速は、通常のCDプレイヤと同じ回転数で、倍速はその２倍になります。ディスクの回転が速いほどデータ転送速度は上がります。
CD-ROMの転送レートは、標準速度・倍速度の場合に応じてそれぞれ、150KB/sec、300KB/secになります。これは１秒間に標準速で７５セクタ、倍速で１５０セクタのデータが読めることを表します。

4. 1 セクタバッファ

CD-ROMの転送速度はホストシステムのバス速度（132MB/sec）に比べて極めて遅いため、CD-ROMシステムは内部にセクタバッファと呼ばれる１セクタ分のローカルメモリを内部に持っており、CD-ROMからのデータは、一旦セクタバッファに格納されてからまとめて転送されます。従ってCD-ROMからの転送は下図の手順を踏むことになります。

↑ 5 サウンド制御

CD-ROMサブシステムからは右（Ｒ）と左（Ｌ）２チャンネルのオーディオ信号が出力されています。ここには、CDオーディオ、および、ADPCMオーディオが出力されます。これらは、一旦SPUに入力され、続いてSPU内の音源からの信号と加算合成されて最終的なサウンドとして出力されます。CD-ROMからのオーディオ出力は4個のアッテネータ（減衰器）によって制御されます。

CD (L) → ATV0 → SPU (L)
CD (L) → ATV1 → SPU (R)
CD (R) → ATV2 → SPU (R)
CD (R) → ATV3 → SPU (L)

アッテネータの制御は、CdMix() 関数を通じて、CdlATV構造体を用いて指定します。

↑ 6 プリミティブコマンド

CD-ROMに対する最も低レベルの操作は、CD-ROMサブシステムに直接コマンドを発行することで行ないます。各コマンドの発行にはCdControl()関数を使用します。CdControl()関数は以下の引数を持ちます。
        
        CdControl( com, param, result )
        u_char	com;			/* コマンドコード */
        u_char	*param;			/* コマンド引数設定アドレス */
        u_char	*result;		/* コマンドの返り値格納アドレス */
例えば、CdControl()を使用してCDを1分00秒から再生する場合は、以下のように、CdlPlayプリミティブコマンド（コード0x03）を発行します。
        
        #include <libcd.h>
        
        CdlLOC	pos;
        u_char	result[ 8 ];
        
        pos.minute = 0x01;		/* 1 min */
        pos.second = 0x00;		/* 0 sec */
        pos.sector = 0x00;		/* 0 sector (void) */
        pos.track  = 0x00;		/* void */
        
        CdControl( CdlPlay, &pos, result );
param、resultの内容、ビットアサインはコマンドごとに異なります。CdControl()関数で定義される低レベルコマンドをプリミティブコマンドと呼びます。プリミティブコマンドには、それぞれ対応するコマンドコードが以下のように割り当てられています。

6. 4 コマンド概要

(1) CdlNop

何もしません。ステータスを獲得するために使用します。

(2) CdlSetloc

ターゲットポジションを設定します。これは位置の設定のみを行ない、実際の動作は行なわれません。ここで設定したターゲットポジションは次にCdlPlay、CdlReadN、CdlReadS、CdlSeekP、CdlSeekLを実行する時に使用されます。

(3) CdlPlay

ターゲットポジションへCD-ROMのヘッドをシークしてからCD-DAの再生を開始します。ターゲットポジションは、引数で設定します。引数にNULLを指定すると直前のCdlSetloc、CdlSeekPで指定された値が使用されます。

(4) CdlReadS/CdlReadN

ターゲットポジションへCD-ROMのヘッドをシークしてからデータセクタの内容を読み出して、ローカルバッファへ転送します。ターゲットポジションは、引数で設定します。引数にNULLを指定すると直前のCdlSetloc、CdlSeekLで指定された値が使用されます。
CdlReadSはエラー発生の際にリトライしません。これは主にストリーミング再生などのリアルタイム読み込みに使用されます。
CdlReadNはリードエラーが発生した場合可能な限り（最大８秒）リトライをおこないます。ただしこのリトライを行った場合でも失敗する可能性はあります。

(5) CdlSeekL/CdlSeekP

ターゲットポジションへCD-ROMのヘッドをシークしてからポーズ状態で待機します。CD-ROMはハードディスクなどと異なりシーク時間が長いため、目的のアドレスがあらかじめ確定している場合は、前もってヘッドをターゲットポジションへ移動しておくことでアクセスを高速にすることができます。
CdlSeekLはデータセクタへの論理シークを行ないます。データセクタの先頭にはセクタアドレスが記録されており、それを使用して正確なシークが可能です。これを論理シークと呼びます。論理シークはデータセクタに対してのみ有効です。
これに対してセクタヘッダを持たないオーディオセクタに対してはサブコードを使用したシーク（物理シーク）を行なわれます。物理シークは正確さに欠けるもののあらゆるタイプのセクタに対して有効です。

(6) CdlForward/CdlBackward

オーディオセクタを再生中に早送り・巻き戻しを開始します。

(7) CdlStandby/CdlStop/CdlPause

CdlStandbyはスピンドルモータを回転させた状態で待機します。
CdlStopはスピンドルモータを停止させ ヘッドをホームポジションへ戻します。ストップ状態にあるよりもスタンバイ状態にある方が、次のシーク・リード・プレイへ遷移を高速に行なうことができます。
CdlPauseはリード・プレイを一時中断し、スタンバイ状態でヘッドを中断した位置で待機させます。

(8) CdlMute/CdlDemute

CD-DA、ADPCM再生をミュート（消音）・ミュート解除を行ないます。

(9) CdlSetfilter

マルチチャネルADPCMの再生チャネルを指定します。再生できるチャネルはファイル番号とチャネル番号の２つでインデクスされます。デフォルトのファイル番号・チャネル番号は、(1,1)です。

(10) CdlSetMode

CD-ROMの基本的な動作モードを設定します。
モードの設定は、以下のビットの論理和をとった１バイトをCdlSetModeコマンドを用いて設定することで行ないます。また、現在のモードは、CdlGetlocLコマンドで獲得できます。

↑ 7 コマンド同期

プリミティブコマンドのうち、処理時間のかかるものは実際の処理の終了を待たずにリターンします。これらのコマンドをノンブロックコマンド（非同期コマンド）と呼びます。これに対して処理の終了を待ってリターンするものをブロックコマンド（同期コマンド）と呼びます。
ノンブロックコマンドは、CdControl()関数がリターンした後もバックグラウンドで処理を続行します。その間ホストシステムは並列して他の処理を行なうことができます。
ノンブロックコマンドの実際の処理の終了はCdSync()関数を使用するか後述するコールバック関数を使用します。以下の例は全てのコマンドの終了までブロックする関数です。
        
        CdControlB( u_char com, u_char* param, u_char* result )
        
        /* コマンドの発行 */
        if( CdControl( com. param, result ) == 0 )
        	return 0;
        /* コマンドが終了するまでブロックする */
        if( CdSync( 0, result ) == CdlComplete )
        	return 1;
        else
        	return 0;
なおノンブロックコマンドを発行した際のCdControl()関数の返り値は一時的なものであり、最終的なステータスはCdSync()関数の返り値かコールバック関数に渡される引数で確定します。

7. 1 コマンドの実行状態

プリミティブコマンドは以下の処理状態をもちます。

表 13 プリミティブコマンドの処理状態

処理状態内容
CdlNoIntrコマンド実行中
CdlComplete実行終了・待機中
CdlDiskErrorエラー発生


コマンドが発行されると実行状態はCdlCompleteからCdlNoIntrへ移行します。コマンドが正常終了して次のコマンドが受け付けられる状態になるとCdlComplete状態へ移行します。実行時にエラーが検出されるとCdlDiskError状態になります。
ブロックコマンド・ノンブロックコマンドは、関数のリターン時の処理状態によっても定義できます。ブロックコマンドではコマンド発行後CdlComplete/CdlDiskError状態になるのを待ってリターンするのに対してノンブロックコマンドは、CdlNoIntrのままリターンします。
これらのコマンド実行状態はCdSync()関数のリターン値で獲得できます。
        
        CdSync( u_char mode, u_char* result )
        u_char	mode;		/* モード 0:ブロック 1:ノンブロック */
        u_char	*result;	/* コマンドの返り値格納アドレス */
mode 引数によってブロックモード／ノンブロックモードが選択されます。

表 14 CdSync()の引数の値と内容

mode内容
0実行状態がCdlNoIntr以外に移行するまでリターンしない
1実行状態にかかわらずに直ちにリターンする


従って以下のコードは同じ結果になります。
        
        a)	CdControl( CdlSeekL, ( u_char* )pos, 0 );
        	CdSync( 0, result );
        
        b)	CdControl( CdlSeekL, ( u_char* )pos, 0 );
        	while( CdSync( 1, result ) != CdlNoIntr );
なお、CdSync()の返り値（result）は実行状態がCdlComplete/CdlDiskErrorになった時点で初めて確定します。処理状態がCdlNoIntrの場合、次のコマンドは受け付けられません。
コマンドの実行はキューイングされないため、新しいコマンドは前のコマンドが終了し、実行状態がCdlNoIntrに移行するのを待って実行されます。従って以下のコードは同じ結果になります。
        
        a)	CdControl( CdlSeekP, ( u_char* )pos, 0 );
        	CdControl( CdlPlay, 0, result );
        b)	CdControl( CdlSeekP, ( u_char* )pos, 0 );
        	CdSync( 0, 0 );
        	CdControl( CdlPlay, 0, result );

a)、b)の例ともシークの間は処理がブロックされます。これを避けるためには、直接位置指定をしてCdlPlayを発行するか、コールバック関数内でCdlPlayを起動するようにします。
        
        /* シークの間ブロックされる */
        CdControl( CdlSeekP, ( u_char* )pos, 0 );
        CdControl( CdlPlay, 0, result );
        /* シークの間ブロックされない */
        CdControl( CdlPlay, ( u_char* )pos, result );

7. 2 コマンド同期コールバック

コマンド実行状態がCdlNoIntrからCdlComplete/CdlDiskErrorに移行する際に呼ばれる関数（コールバック関数）を登録することができます。
コールバックの登録にはCdSyncCallback()関数を使用します。
コールバック関数には以下の形式の引数が渡されます。
        
        callback( u_char intr, u_char* result )
        u_char	intr;		/* その時点の実行状態 */
        u_char	*result;	/* その時点で最新の返り値  */

以下にコールバックを使用した例をあげます。
        
        main() {
        	void callback();
        	CdlLOC pos;	....
        	/* コールバック関数 callback() を登録 */
        	CdSyncCallback( callback );
        	....
        	/* コマンド発行 */
        	CdControl( CdlSeekP, ( u_char* )&pos, 0 );
        }
        
        /* コマンド終了時に以下の関数が呼ばれる */
        void callback( u_char intr, u_char* result )
        {
        	if( intr == CdlComplete )	/* ここで必ずステータスのチェックを行うこと */
        		CdControl( CdlPlay, 0, 0 );
        }

7. 3 CdControlFインタフェース

CdControl()は、コマンドの発行がサブシステムへ通知されるまでブロックします。このブロックしている時間はコマンドの実行時間と比較すると短いために通常は無視できます。ただし アプリケーションによってはこの時間もブロックしないでプログラムを動かしたいという要望があるかもしれません。そのためにCdControlF()があります。CdControlF()はコマンドの通知まで待たないため、コマンドを発行した直後にリターンします。そのためコマンドが受け付けられたかどうかの判定が簡単にできません。ポーリングでCdSync()を発行してエラー処理を行う必要があります。

↑ 8 データリード

CD-ROMは、倍速モードでもデータ転送速度が300KB/secとメインバス転送速度に比べて非常に遅いために内部にセクタデータバッファを持ち、セクタ単位にまとめてデータを読み出せるようになっています。
データセクタ読みだしコマンド（CdlReadN/CdlReadS）が発行されると、CD-ROMサブシステムはセクタデータを読みだし、一旦セクタバッファ上にデータを展開します。セクタバッファに展開されたデータの内容は次のセクタのデータが新しく上書きされるまで有効です。
セクタバッファ上に確定したデータは、CdGetSector()関数を使用して高速にメインメモリに転送することができます。

8. 1 リトライリードとノーリトライリード

データリードには、読み込み時にエラーが発生した時にセクタ単位でリトライをかけるタイプ（CdlReadN）と、エラーを報告するだけでリトライを行なわないタイプ（CdlReadS）があります。
CdlReadNを使用した読み込みは読み出されたデータが正しいことが保証されますが、エラー発生時に一旦前に戻って再度セクタの読み込み（リトライ）を行なうために、ADPCMの再生と同時に使用できません。
また、ストリーミングのように、データの品質よりも転送レートを一定に保ちたい場合にも適切ではありません。こうした場合には、エラー発生時にもリトライを行なわないCdlReadSを使用します。

8. 3 データレディ同期コールバック

CdSyncCallback()と同様にセクタバッファの状態がCdlNoIntrからCdlDataReady/CdlDiskErrorに移行する際に呼ばれる関数（コールバック 関数）を登録することができます。
コールバックの登録にはCdReadyCallback()関数を使用します。
ここで登録されたコールバック関数は、１セクタ分のデータが用意されるたびに起動します。後述するCdReadCallback()とは仕様が異なるの点にご注意下さい。

8. 4 セクタバッファ転送

セクタバッファ上には次々に新しいセクタデータが上書きされていきます。従ってセクタデータは、上書きされる前にセクタデータをメインメモリ上に転送する必要があります。これにはCdGetSector()関数が使用されます。セクタバッファのデータを直接フレームバッファやサウンドバッファに転送する場合も一旦メインメモリに転送してから各デバイスへ再転送を行ないます。
セクタバッファのサイズは１セクタ分です。セクタサイズは、CD-ROMのモードによって異なりますが、通常は2KByteが使用されます。この場合、一回のCdGetSector()関数でメインメモリに引き上げられるデータサイズの上限も2KByteになります。データは、複数回にわけて別々の場所に転送することもできます。ただしその場合も転送するデータサイズの合計は、セクタサイズに等しくなくてはなりません。
CD-ROMからnセクタ分のデータを読み出す例を以下にあげます。
        
        cd_read( CdlLOC* loc, u_long* buf, int nsec )
        /* loc:		ターゲットポジション */
        /* buf:		読み込みバッファ */
        /* nsec:	セクタ数 */
        {
        	u_char	param[ 4 ];
        	/* 倍速モードを指定 */
        	param[ 0 ] = CdlModeSpeed;
        	CdControl( CdlSetmode, param, 0 );
        	/* リトライリードコマンドを発行 */
        	CdControl( CdlReadN, ( u_char* )loc, 0 );
        	/* データが用意され次第メインメモリへ転送 */
        	while( n-- ) {
        		if( CdReady( 0, 0 ) != CdlDataReady )
        			return -1;
        		CdGetSector( buf, 2048 / 4 );
        		buf += 2048 / 4;
        	}
        }
なお、CdGetSector()はデータ転送の終了を確認してリターンしますので、転送が終了するまで処理はブロックされます。

8. 5 セクタ転送同期

セクタバッファからメインメモリへのデータの転送はCdGetSector()でおこないます。CdGetSector()はブロック関数であるため関数からリターンした時にはデータの転送は終了しています。よってデータ転送の終了を非同期に監視する必要はありません。

9. 2 データリード同期

CdRead()関数はノンブロック関数として動作します。CdRead()の実際の終了はCdReadSync()関数を使用します。CdReadSync()関数はノンブロックモード動作時には、未リードの残りセクタ数を返します。
以下の例はブロック型のCD-ROM読み込み関数です。
        
        CdReadB( CdlLOC* loc, u_long* buf, int nsector )
        /* loc		ターゲットポジション */
        /* buf		メモリアドレス */
        /* nsector	読みだしセクタ数 */
        {
        	int cnt;
        	u_char param[ 4 ];
        	/* 倍速モードを指定 */
        	param[ 0 ] = CdlModeSpeed;	
        	CdControl( CdlSetmode, param, 0 );
        	/* ターゲットポジションを設定 */
        	CdControl( CdlSetloc, ( u_char* )&loc, 0 );
        	/* リード開始 */
        	CdRead( nsector, buf, mode );

        	while( ( cnt = CdReadSync( 1, 0 ) ) > 0 );

9. 3 ストリーミング

CD-ROMからデータを連続的に読み込んでメインメモリへ転送する処理をストリーミングと呼びます。ストリーミングは、複数のセクタからなるデータの処理単位（１フレーム分の圧縮画像データなど）をメインメモリ上にまとめ、その先頭ポインタをアプリケーションに渡します。
ストリーミングは、St*()関数として別に詳細に解説されておりますのでそちらを参照ください。

↑ 14 Appendix

14. 1 ディスクアクセスに関する注意事項

基本的にはCD-ROM XAに準拠していれば再生できますが、仕様上データトラックはDAのトラックの前に配置しなくてはいけません（DAトラックはなくても構いません）。
間違った例としては、１トラックがデータで、２、３トラックがCD-DA、４トラックがデータという配置です。このような時は、１、４トラックをまとめて前の方に配置して１トラックとし２トラック以降をCD-DAというように配置して下さい。

曲間がないまたは極端に短いDISCの場合でauto pause機能を使用すると、auto pauseできないでそのままDISCの最後まで再生してしまうことがあります。これを防ぐためには、曲間を２秒以上空けなければなりません。例えばゲームのBGMにCD-DAを１曲リピートで使う場合は、auto pause onで曲間を２秒以上設けるか、常に現在位置をポーリングし、終了点が来たらTOPに戻すということをしなければなりません。

外周から３分以内のところへトラックジャンプを行った場合、ヘッドが外側へ飛び出すという不具合があります。これを防ぐ方法は外周３分以内をアクセスしないようにすることです。通常は外周３分にＮＵＬＬデータを焼きます。ただし 外周３分にアクセスしないのであればＮＵＬＬデータでなくともかまいません。たとえば３分以上連続するエンディングムービーをＮＵＬＬデータの代わりに焼いておき、エンディングムービーは必ず最初から再生するようにしておけば外周３分以内のアクセスは発生しません。

データトラック上を再生してそのままCD-DAトラックを再生した場合mute off機構が働きません。よって、このような使い方をする場合は、CD-DAトラックになった時にmute offしてください。

データREAD中にreport modeをonにしておくと、ピックアップの位置情報の割り込みとデータの転送開始の割り込みが区別できません。report modeをonにするのは、CD-DAを再生している時のみ使用してください。また レポートモードを有効にした時に送られる演奏時間に関しては以下の決まりがあります。CDのDISCの始めからの絶対時間と各トラック内での時間を示す相対時間を交互に送るようになっています。送られてきたデータが絶対時間か相対時間化の区別をつけるために、相対時間のセクタのデータの最上位に１が立っています。レポートモーﾄﾞでレポートを送るタイミングは 以下のようになっています。
  • ff,fr中は読めるデータが限られているのでチェックを通ったものは全て送る。
  • 絶対時間の十の桁のframeが偶数の時は絶対時間を送る。
  • 絶対時間の十の桁のframeが奇数の時は相対時間を送るが、この時frameのバイトの最上位ビットを立てておく。
  • frameは0から74までしかないので、ビットを立てることによる問題はない。
  • 普通通常再生中は位置データを読めるが、念のため十の桁が書き変わった時に送るようになっていて、絶対時間と相対時間の関係は上と同じになっている。
また、レベルも送られていて2byte中の15bitのデータとなっており、残り1bitはL/Rの識別になっています。

14. 2 外周３分問題

現在のCD-ROMサブシステムでは、CD-ROMの外周３分以内へシークする場合、シーク開始地点によっては、正しくシークが行なわれない場合があります。
この現象を回避するために以下のいずれかの方法をとる必要があります。

  1. 最外周３分（データの最後の３分）にダミーデータを入れておく（ダミーデータは使用しない）。
  2. BGMなどにCD-DAを使用する場合、最終曲を３分以上にする。この場合は、曲の途中から再生したり、曲の途中でリピートをかけない限り、最外周３分へのシークは発生しません。従ってCD-ROMサブシステムは正常に動作します。
  3. どうしても最外周３分をデータエリアとして使いたい場合は、外周３分以上は連続した１つのファイルとしてアクセスする（オープニング、エンディングのムービに使用するなど）。

14. 3 低レベル関数群を使用する場合の留意点

CdControl()インターフェースの低レベル関数の組合せでCD-ROMのリードアクセスを行なう場合、エラー処理やコールバック処理はアプリケーションで行なう必要があります。その際には、以下の点にご注意下さい。

(1) セクタの読み飛ばし

CD-ROMからは、倍速モードで300 sector/secのデータが読み出されます。従ってホストシステムが 1/300 sec以内に前のセクタのリード処理を終了していない場合、読み出されたデータが１セクタ分欠落してしまいます。この問題は、処理時間の長いコールバック処理を他で行なっている場合に特に発生しやすくなります。
そこで、セクタの欠落が懸念される箇所では、CdlModeSize1でセクタヘッダをアプリケーションでも読み出し、セクタの連続性を確認するようにして下さい。
その際は、CdlSetmodeコマンドでCdlModeSize1（セクタヘッダも読み出すモード）にあらかじめ設定しておきます。

        param[ 0 ] = CdlModeSpeed | CdlModeSize1;
        CdControlB( CdlSetmode, param, 0 );

そして、データをCdGetSector()で読み出すにあたって、まず先頭の12byte（3word）を読みます。ここにはセクタアドレスがCdlLOC形式で格納されています。これが直前に読みだしたセクタアドレスと連続しているかを調べればセクタの欠落を検知できます。
        
        ......
        CdGetSector( buf, 3 );
        if( CdPosToInt( ( CdlLOC* )buf ) != prev_pos + 1 )
        	return -1;
        else
        	prev_pos++;
        
        CdGetSector( bufp, 512 );
        bufp += 512;
        ......

(2) callbackの解析

セクタデータの準備が完了したかどうかは通常CdReady()関数かCdReadyCallback()に登録したコールバックで検出できます。libcdのコールバックは他のコールバックと異なり２つの引数を持つため、使用の場合は注意が必要です。
        
        CdReadyCallback( callback );
        ....
        
        void callback( u_char intr, u_char* result )
        {
        	....
        }
この例の場合、callbackはリード処理が失敗した場合でも呼び出されることにご注意下さい。
callback処理が成功したかどうかはintr引数によって判定できます。これを行なわないと正しくリードエラーを捕獲できません。 処理の詳細はcd/tutoサンプルプログラムをご参照下さい。
またresultには最後に発行されたコマンドの返り値が8byteの配列に収められています。result配列の実体（8byte）はシステム側で保持されます。
resultに格納される情報は発行されるコマンドによって異なります。

(3) callbackの削除

コールバックは処理が終了したら済みやかに切り離して下さい。
        
        CdReadyCallback( callback );
        /* CdRead() に相当する処理 */
        CdReadyCallback( 0 );
この例で最後にコールバックを切り離す処理が抜けた場合、この後の処理で他の要因からCdlDataReadyイベントが発生すると、思わぬタイミングで関数callback()が起動されてしまいます。特に関数callback()がメインメモリを書き換える処理を含んでいる場合、予測できない時にメモリの特定領域が破壊されるといったバグを引き起こします。

またCdSyncCallback()で登録されたコールバック中にCdControl()を発行する場合も注意が必要です。
        
        CdSyncCallback( callback );
        ...
        void callback( u_char intr, u_char* result )
        {
        	....
        	CdControl( CdlSeekL, ....);
        	...
        }
この例では、callback()内で発行されたCdlSeekLが完了する時に再びcallbackを起動し、コーディングによっては、それが再帰的にCdlSeekLを呼び出す無限ループを引き起こします。

(4) watch dog

こうした個別に局所的なエラー処理を組み込むと同時に、不可避のエラーに対応できるようにかならず CD-ROMサブシステムの状態を定期的（数VSyncごとなど）に見張る処理と、タイムアウトの処理をかならず組み込んで下さい。こうしたwatch dogの手法はシステムの状態をエラーの原因によらず一定時間後にはかならず正常に引き戻すことができます。

CD-DA/CD-XA演奏中の場合

シークの失敗や、不慮の蓋の開閉などで、CD-DA/CD-XAの演奏が何らかの理由で停止することが考えられます。この際は、定期的にCdlNopコマンドでCD-ROMの状態をポーリングします。CdlNopのresultバッファの最初の1 byteにサブシステムのステータスが格納されています。これを調べてCdlStatPlayビットがたっていない場合は、適切なトラックを再生し直すようにして下さい。

また、CdlSeekL、CdlGetlocLのロジカルアクセスは、CD-ROMのセクタヘッダを読んで位置を獲得するため、CD-DAトラックには使用できません。CD-XAトラックに対してはロジカルアクセスは有効ですが、それでもシーク中は失敗します。特に CdlGetlocLを発行する場合は、リード中（演奏中）であることを確認する必要があります。
        
        VSyncCallback( vcallback );
        ...
        
        static CdlLOC pos;
        void vcallback( void )
        {
        	int ret;
         
        	/* if normal, polling */
        	if( ( ret = CdReady( 1, result ) ) == CdlDataReady )
        		if( CdLastCom() == CdlGetlocL )
        			pos = *( CdlLOC* )result;
        		CdControlF( CdlGetlocL, 0 );
        	}
        
        	/* if error, retry */
        	else if( ret == CdlDiskError )
        		CdControlF( CdlReadS, ( u_char* )&pos );
        }
この例のようなwatch dogは動作しない場合があります。これはCdlGetlocLがシーク中に実行される可能性があり、それがCdlDiskErrorを引き起こすため、CdlSeekL, CdlGetlocLが無限に繰り返されます。 なおCdlGetlocLはresultの最初の3byteがCdlLOC形式のセクタポジションを与えます。

データリード中の場合

演奏再生時と同様の理由でCD-ROMのリードの途中でCdlDataReadyイベントが途切れる可能性があります。これも最後にCdlDataReadyが発生した時のタイムスタンプを保持しておき、これが一定時間（数秒程度）更新されない場合は、すべてのリード動作を最初からやりなおすなどの処理を組み込みむことで、確実に検出できます。
        
        void callback( u_char intr, u_char* result )
        {
        	.....
        	called_time = VSync( -1 );
        	....
        }
        main()
        {
        	.....
        	CdReadyCallback( callback );
        	....
        	while( 1 ) {
        		....
        		if( VSync( -1 ) > called_time + TIME_OUT )
        			break;
        	}
        }
CdlDataReadyコールバックを永遠に待ち続けて無限ループになる可能性がある箇所では、こうした一定時間後にはループから抜けられるような処理を組み込んでおきます。

14. 4 CD交換時の必須処理

CD交換を伴うタイトルについて、ゲーム進行中に本体リセットなしでCDの交換を行う場合は、市場でのトラブルを未然に防止するために、以下に述べる処理を必ず行ってください。

(1) CDの交換を行う前の処理

（必須）
CDの交換を行う前（CDの交換メッセージを出力する前）に、CDサブシステムを標準速モードに設定してください。
（オプション）
上記操作後、標準速モード設定後、CdlStopを使用してCDの回転を止めてください。

標準速モードに設定するプログラム例を以下に示します。
        	:
        com = 0;
        CdControlB( CdlSetmode, &com, result );
        	:

(2) CD交換の検出

CDの交換の終了検出は、(A)蓋の開閉の検出と(B)スピンドル回転の検出の２つを順にテストすることにより行ってください。いずれの検出テストも、CdlNopコマンドにより実施できます。

        CdControlB( CdlNop, 0, result );	/* char result[ 8 ]; */

(A) 蓋の開閉の検出は、result[ 0 ]のCdlStatShellOpenビットに反映されます。 CdlStatShellOpenビットは、蓋が開けて閉められたことを検出するもので、以下の状態を持ちます。
蓋が開いている場合： 常に１
蓋を閉めた場合： 最初の１回の検出は１、その後は０
よって、このビットが１→０に遷移すれば交換が行われたものと判断できます。
(B) CdlNop コマンドを使用し、result[ 0 ]のビット１（0x02）が１となるまで待機してください。

(3) 交換直後の処理

CDが交換され、蓋が閉められると、CDサブシステムはTOC情報を読み始めます。この動作期間中は、CdlNopおよびCdlGetTN以外のコマンドを発行しないでください。
TOCの読み込みの終了を検出するためには、CdlGetTNコマンドを使用します。このコマンドの実行が成功すれば、TOC読み込みが終了し通常のコマンド発行が可能な状態になっています。成功するまで繰り返しCdlGetTNコマンドを発行してください。

        CdControlB( CdlGetTN, 0, result );	/* char result[ 8 ]; */

(4) PlayStationディスクの確認

セットされたCDがPlayStationディスク（黒ディスク）であることを、論理アクセスコマンド（CdlReadS/NやCdlSeekLなど）を発行して確認してください。

PlayStationディスクとして認識されなかったCDに対して論理アクセスを行うと、コマンドエラーが発生します。コマンドエラーは、通常のCdlDiskErrorとは異なり、CdlDiskError発生と同時に、

result[ 0 ]のビット０（0x01）
result[ 1 ]のビット６（0x40）

が１になります。
コマンドエラーが検出された場合は、その後の論理アクセスが行えません。この場合は、間違ったCD（CD-DAなど）がセットされていたり、CDがしっかりセットされていないなどが考えられます。コマンドエラーのリカバリーは、蓋を開けてCDをセットし直すしか方法がありませんので、その旨メッセージを出力し、再び最初から手順を繰り返してください。
PlayStationディスクの確認は、ゲームの進行上、CD交換直後にデータのロードなど論理アクセスが存在する場合は、そのコマンドで行うことが出来ます。そうでない場合（DAトラックの再生などを行う場合）は、必ずダミーリードなどでディスクの確認を行ってください。

CD-DAや一般のCD-ROMがセットされていた場合、手順(3)までは正常に実行されます。よって、PlayStationディスクの確認は必ず行ってください。
デバッギングステーションでは、CD-Rおよび一般のCD-ROMもPlayStationディスクとして認識されますが、PlayStationでは黒ディスクのみPlayStationディスクとして認識されます。

(5) その他

上記手順の(1)～(3)までは、必ず標準速モードのままで行ってください。
上記手順の(1)～(3)までのコマンドの発行は、必ずCdControlBを使用して確実に終了を検出してください。また、上記の例では説明のため簡略化してありますが、各コマンドの実行結果の確認も確実に行ってください。

14. 5 CDサブシステムのモーター回転を変更する際の注意点

PlayStationのCDサブシステムでは、標準速／倍速の切り替えてから一部のコマンドを発行するまでに、一定時間の間隔を置く必要があります。この注意事項を守らないと、以下の現象が発生し、市場クレームに繋がりかねない事態を引き起こす可能性がありますため、徹底をお願いいたします。

（現象）
CDの転送速度を変更した直後にCDのヘッドを移動させるコマンド（CdlSeekL/P, CdlReadS/N）を発行すると、ヘッドが暴走し、異音が発生することがある。

これは、CDサブシステムの動作において、転送速度の変更後ヘッドの制御がうまくいかないタイミングが存在するために発生するものです。このタイミングは転送速度の変更後に存在します。
このタイミング中にヘッド移動に関するコマンドが発行されると、最悪の場合はヘッドが暴走し、メカニカルストッパーに衝突して停止します。この現象が発生した場合、ヘッドの制御はCDサブシステムによってリカバリーされますので、プログラムが止まるようなことはありません。また、ヘッドが暴走してストッパーに衝突した場合は、セーフティ機構が作動するため部品を破壊するようなことはありません。
ただし、セーフティ機構が作動する際に異音を発生しますので、市場でのクレームとなることが考えられます。

ヘッド移動に関する関数／コマンドは、現在以下の通りです。

        CdRead( int sectors, u_long* buf, int mode )
        CdRead2( long mode )
        CdSearchFile( CdlFILE* fp, char* name )
        CdReadFile( char* file, u_long* addr, int nbyte )
        CdReadExec( char* file )
        CdPlay( int mode, int* tracks, int offset )
        
        CdlSeekP
        CdlSeekL
        CdlReadS
        CdlReadN
        CdlPlay

転送速度を変更した後に上記の関数／コマンドを行う場合には、必ず以下の対策を行ってください。

（対策）
CDの転送速度を変更した後にCDのヘッド移動コマンドを発行する場合は、必ず３以上の垂直帰線（vsync）の間隔をあける。

例：
        	:
        com = CdlModeSpeed;
        CdControl( CdlSetmode, &com, 0 );
        	:
        	:
        /* ３以上の垂直帰線が経過する処理を行う */
        /* 例えば VSync( 3 ); */
        	:
        	:
        ret1 = CdControl( CdlSeekL, &pos, result );
        ret2 = CdControl( CdlReadN, &pos, result );
        	:

これにより、ヘッドの制御がうまくいかないタイミングを回避することが出来ます。なお、以下の関数において、引数で転送速度が変更されますと、同様の事態が発生いたします。よって、これらの関数において引数での転送速度の変更は行わず、（３以上の垂直帰線をはさんだ）手前で転送速度を変更してください。

        CdRead( int sectors, u_long* buf, int mode )
        CdRead2( long mode )

また、以下の関数実行後は、CDサブシステムの転送速度は等速になります。ご注意ください。

        CdInit( void )
        CdReset( int mode )
