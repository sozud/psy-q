GTEインラインマクロライブラリ(dmpsx)

GTEインラインマクロライブラリは、関数呼出しを使用せずにGTEを制御するためのサービスを提供しています。この章では、まずライブラリを利用するのに必要なプログラム環境DMPSXについて説明し、GTEインラインマクロライブラリを使用したプログラム方法を説明します。

↑ 1 DMPSX version 2.xからの変更点

  • GTEレジスタのロード／ストア命令を公開しました。
  • ３つのヘッダファイルを用意しました。
  • アセンブラプログラムに対応しました。
  • "inline.tbl"を廃止しました。

"DMPSX version 3.0"およびヘッダファイルは、旧DMPSXに使用することはできません。また、旧"inline.h"を"DMPSX version 3.0"で使用することもできません。
旧DMPSXで作成されたプログラムを"DMPSX version 3.0"に使用するためには、以下の"inline_o.h"もしくは"inline_c.h"を"inline.h"の代わりにインクルードするように変更してください。

↑ 2 DMPSX とは

DMPSXとは、GTEの処理に関するプログラムの実行速度を向上させることを目的とするプログラミング環境です。
専用のヘッダファイルをプログラムにインクルードし、ヘッダファイルに記述されているインライン関数（マクロ）を使用してGTEをコントロールすることで、関数呼出しのオーバーヘッドを除去することができます。
また、関数呼出しを使用しないことで、インストラクションキャッシュのコントロールが容易になり、高速に実行されるルーチンを開発することができます。
DMPSXで作成されたプログラムは、コンパイル方法が通常のプログラムと異なります。コンパイルをオブジェクト（*.obj）まで行い、このファイルを"dmpsx.exe"で処理したあと、他のオブジェクトファイルとリンクします。詳しくは後述の”コンパイル方法”をご参照ください。

↑ 3 ファイル構成

  • dmpsx.exe
    実行ファイルです。コンパイルされたオブジェクトファイルを処理します。
  • inline_o.h
    旧DMPSXと同じコードを生成するためのヘッダファイルです。
  • inline_c.h
    "inline_o.h"のレジスタロード／ストア命令を、inline asmの機能を使用して最適化したヘッダファイルです。
  • inline_a.h
    "inline_c.h"をアセンブラプログラム用に書き換えたヘッダファイルです。
  • gtereg.h
    アセンブラ用にGTEのレジスタのマクロ定義が行われています。
  • gtemac.h
    "libgte.lib"の関数と同じ機能を、DMPSXのインライン関数で実現するためのヘッダファイルです。

↑ 4 書式

4. 1 書式 

        DMPSX  object-file [ -o output-file ] [ -b ]

4. 2 オプション

-o

出力ファイル名を指定する。
省略時は、入力ファイルに上書きされる。

-b

.bakファイル（バックアップファイル）の生成を抑制する。

4. 3 使用例

DOS> dmpsx main.obj

↑ 5 概要

このプログラムは、以下に述べるGTEのインライン関数を実現します。ソースプログラム中に指定のヘッダファイルをインクルードし、コンパイル時にこのプログラムをオブジェクトファイルに使用することで、GTEコードがオブジェクトファイルに展開されます。これにより、通常の関数と同等のインターフェイスをもつインライン関数を使用することが可能になります。
（注）ここでいうインライン関数とは、C言語の'inline'関数とは効果は同じですが、違うものです。

5. 1 インライン関数

libgteの低レベル関数（RotTransPersなど）を使ってプログラムを書くと、インストラクションキャッシュミスを起こすことがあります。このような場合、インライン関数を使えばこれを避けることができ高速になります。（もとのプログラムがキャッシュミスを起こしていない場合には逆に遅くなる場合もあります。）
GTEインライン関数は次のような形式の名前を持っています。

        gte_******

GTEインライン関数は大きく分けて２種類のタイプがあります。一つは GTEを使うための基本関数でもう一つはlibgteの低レベル関数をそのまま置き換え可能な関数です。"gte_"に続く最初の文字が小文字の関数は基本関数で大文字の場合置き換え可能な関数です。

        gte_rtps		基本関数
        gte_RotTransPers	置き換え可能な関数

すべての基本関数といくつかの置き換え可能な関数はコンパイル時に直接オブジェクトコードになります。また、そのほかのほとんどの置き換え可能な関数は"gtemac.h"のなかで基本関数のマクロとして定義されています。

5. 2 置き換え可能な関数への変更

通常の関数コールで書かれたプログラムをインライン化するためには以下の作業を行なってください。

(1) 次のヘッダファイルをインクルードする。 

        "inline_o.h"もしくは"inline_c.h"
        "gtemac.h"

(2) インライン化したい関数が置き換え可能な関数のなかにあるか探す
（関数名はリファレンスを参照してください）。

(3) もしあれば、

１．関数名に"gte_"を付けてインライン関数名にする
        （例）RotTransPers() -> gte_RotTransPers()
２．その関数が返り値を持っている場合は返り値のポインタを引き数の最後に付け加える
        （例） otz=RotTransPers(...) -> gte_RotTransPers(...,&otz)
３．置き換えたインライン関数がGTEの内部定数、たとえばRotation Matrix, Transfer vector... をこわす場合、それらの定数をセーブ、ロードする
        （例）	OuterProduct12()	->	gte_ReadRotMatrix(&m)
        					gte_OuterProduct12()
        					gte_SetRotMatrix(&m)
        
        	CompMatrix()		->	gte_ReadRotMatrix(&m)
        					gte_CompMatrix()
        					gte_SetTransMatrix(&m)
        	破壊する定数がlibgte版と異なるのはこの２つだけです。

(4) 無い場合、

１．インライン関数を使って直接プログラム中に書く
        （例）	RotTransPers4()		->	gte_RotTransPers3()
        					gte_RotTransPers()

5. 3 基本関数によるインラインプログラミング

置き換え可能な関数が見つからない場合や、より最適化したい場合には基本関数を使って直接プログラミングしてください。
GTEは通常つぎの３つのステップで動作します。
  • 入力データのロード ... CPUメモリ/レジスタ -> GTEレジスタ
  • 実行 ... GTE functionの実行
  • 出力データのストア ... GTEレジスタ -> CPUメモリ/レジスタ
リファレンスのなかで
“レジスタロード関数”は入力データのロード、
“GTEコマンド”は実行、
“レジスタストア関数”出力データのストア
です。
例えばgte_RotTransPersは"gtemac.h"の中で次のように書かれています。

        gte_ldv0(r1);		/* type1:load 3D coordinate */
        gte_rtps();		/* type2:Rotate,Transfer,Perspect */
        gte_stsxy(r2);		/* type3:store 2D coordinate */
        gte_stdp(r3);		/* type3:store depth queue p */
        gte_stflg(r4);		/* type3:store flag */
        gte_stszotz(r5);	/* type3:store sz/4 as otz */

もし”デプスキューイング用p”と”フラグ”が不要であれば次のように短縮することができます。

        gte_ldv0(r1);		/* type1:load 3D coordinate */
        gte_rtps();		/* type2:Rotate,Transfer,Perspect */
        gte_stsxy(r2);		/* type3:store 2D coordinate */
        gte_stszotz(r5);	/* type3:store sz/4 as otz */

さらに、GTEコマンドとストア関数の間でCPUプロセスを実行すれば、これらのGTEプロセスとCPUプロセスはどちらかが終了するまで同時に実行されることになります。

        gte_ldv0(r1);		/* type1:load 3D coordinate */
        gte_rtps();		/* type2:Rotate,Transfer,Perspect */
        CPU process;		/* CPU process */
        gte_stsxy(r2);		/* type3:store 2D coordinate */
        gte_stszotz(r5);	/* type3:store sz/4 as otz */

ただし、GTEコマンドの実行時間はそれほど長くありませんのであまり多くのCPUプロセスを挟みこむことはプログラムを読みにくくするだけで無意味です。

（注意）
基本関数は以下の３タイプで構成されています。

タイプ１：“レジスタロード関数”
タイプ２：“GTEコマンド”
タイプ３：“レジスタストア関数”

以下のようにタイプ２とタイプ３の間にタイプ１の関数を使用すると動作を保証できませんので使用しないでください。

間違った使用例：
        gte_rtps();		/* type2:Rotate,Transfer,Perspect */
        gte_ldv0(r1);		/* type1:load 3D coordinate */
        gte_stsxy(r2);		/* type3:store 2D coordinate */

5. 4 アセンブラでの使用方法

アセンブラプログラムでDMPSXを使用する場合は、inline_a.hをヘッダファイルとして使用してください。inline_a.hには、タイプ２命令のみ定義されています。GTEのレジスタへのアクセスは、GTEの仕様書を参照して、直接アクセスしてください。GTEレジスタのマクロ定義は、gtereg.hで行われています。

inline_a.hの中のタイプ２命令のうち、以下の命令は引数を必要とします。

        MVMVA	sf,mx,v,cv,lm
        SQR	sf
        OP	sf
        GPF	sf
        GPL	sf

引数には整数を使用してください。それぞれのコマンドおよび引数の詳細は、GTEの仕様書を参照してください。

        dmpsx.exe
        inline_o.h

6. 2 インストール方法

  1. "dmpsx.exe" を "\psx\bin" など path が設定してあるディレクトリにコピーします。
  2. "inline_o.h"、"inline_c.h"、"inline_a.h"、"gtereg.h"と"gtemac.h"はコンパイラのインクルードディレクトリ（\psx\include など）にコピーします。

6. 3 コンパイル方法

コンパイル時には、DMPSXを使用しているファイルのコンパイルを "-c"オプションを使用して一旦オブジェクトまででストップし、"dmpsx.exe"で処理します。その後、他のファイルといっしょにリンクします。
例えば、

        ccpsx -O -Xo$80010000 use1.c use2.c a1.c a2.c -omain.cpe

というようにコンパイルされるプログラムの場合は（ use1.c use2.cがDMPSXを使用しているとして）、

        ccpsx -c -O use1.c -ouse1.obj
        dmpsx use1.obj
        ccpsx -c -O use2.c -ouse2.obj
        dmpsx use2.obj
        ccpsx -O -Xo$80010000 use1.obj use2.obj a1.c a2.c -omain.cpe

のように"makefile.mak"の内容を書き換えてください。

6. 4 nop付き／nopなしタイプ２命令

ヘッダファイルにマクロ定義されているタイプ２命令（演算）には、同じ機能でnop付きとnopなしの２種類が用意されています。GTEの仕様として、演算命令の前２スロットにはcop2命令を置くことは出来ません。よって、標準では、タイプ２命令のマクロはnopを２つ伴っています。もしプログラムの高速化が必要になり、nopを削除したい場合はnopなしのマクロを使用してください。その場合、タイプ２命令の前２スロットには、必ずCPU命令が入るようにプログラムを行ってください。

それぞれのヘッダファイルで宣言されているタイプ２命令のマクロは、nopの有無の区別を以下のように行っています。

(1) inline_c.hの場合

nopなしマクロは、マクロ名の終りに"_b"が付いています。
        （例）	nop 付き	gte_rtps()
        	nop なし	gte_rtps_b()

(2) inline_a.h の場合

nop付きマクロは、マクロ名が'n'で始まります。
        （例）	nop 付き	nRTPS
        	nop なし	RTPS

(3) inline_o.h の場合

nopなしマクロは用意されていません。

↑ 7 各インクルードファイルの説明

7. 1 inline_o.h

"inline_o.h"は、旧"inline.h"のタイプ１および３命令の内容を公開したヘッダファイルです。旧バージョンとの互換性を保つために用意されています。
"inline_o.h"では、旧"inline.h"と同じコードが生成されます。よって、旧"inline.h"と同じ冗長性を持っています。
特に、CプログラムのデータをDMPSXに渡す際に、各インライン関数に１～４ワードの冗長な命令が含まれます。

7. 2 inline_c.h

上記 "inline_o.h" の冗長性を削除したヘッダファイルです。通常のプログラム開発には、このファイルを使用してください。ヘッダファイルに含まれるインライン関数のうち、タイプ１命令（GTE レジスタロード命令）とタイプ３命令（GTEレジスタストア命令）は、今回のバージョンよりDMPSXとは無関係になります。よって、DMPSXを使用しないプログラムでも使用することができます。
タイプ２命令（GTEコマンド）は"dmpsx.exe" で変換してから実行する必要があります。"inline_c.h"は"inline_o.h"と比較して、関数名および機能は同じですが、より効率の良いコードを生成します。

7. 3 inline_a.h

アセンブラプログラム用ヘッダファイルです。タイプ２命令（GTEコマンド）のみ定義されています。GTEレジスタの仕様および各命令については、GTEの資料を参照してください。

7. 4 gtereg.h

アセンブラプログラム用に、GTEレジスタのマクロ定義が行われています。各レジスタのマクロ名は、レジスタ名の先頭に"C2_"が付けられたものとなっています。各レジスタの機能は、GTEの資料を参照してください。

7. 5 gtemac.h

このヘッダファイルは、他のファイルと異なり、DMPSXに必ずしも必要というわけではありません。ここには、"libgte.lib"で提供されている関数と同じ機能を持つマクロ関数が、DMPSXの基本関数の組合せの形で定義されています。よって、libgteで作成されたプログラムをDMPSXを使用して高速化する場合の第一歩として使用してください。

↑ 8 アセンブラプログラム用ヘッダファイルinline_a.hについて

inline_a.hは、アセンブラプログラムでGTEをコントロールするためのヘッダファイルです。inline_a.hにはタイプ２命令のみマクロ定義されています。タイプ１命令およびタイプ３命令については定義されていません。

inline_a.hでマクロ定義されているタイプ２命令には、GTEの仕様上必要なnopを付けたものと、ないものの２種類があります。GTEでは、タイプ２命令の前の２スロットにcop2命令をおくことは出来ません。inline_a.hで提供されるタイプ２命令のうち、名前の先頭に'n'がつくものは、この GTEの仕様にそって命令コードの前にnopが付けられています。
名前の先頭に'n'がつかない命令はnopが付けられていません。この命令を無造作に使用すると、誤動作を起こすコードを生成する可能性があります。そのため、dmpsx.exeでは命令コードの前２スロットにcop2命令が確認されるとエラーを出力し、処理を中断します。dmpsxでエラーが出力される場合は、対象の命令を'n'付きのものに置き換えるか、cop2以外の命令（CPU命令）が少なくとも２つGTEコードの前に入るようなプログラムを行ってください。

また、inline_a.hの一部のタイプ２命令は引数を使用します。これらの命令は引数でその動作をコントロールします。以下に、引数を使用する 命令を示します。引数の詳細および命令の動作についてはGTEの仕様書を参照してください。

        MVMVA	sf, mx, v, cv, lm
        SQR	sf
        OP	sf
        GPF	sf
        GPL	sf

つぎような汎用行列演算命令である。

        出力ベクトル = 係数行列 * 入力ベクトル + 定数ベクトル
