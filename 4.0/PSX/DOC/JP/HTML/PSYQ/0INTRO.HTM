↑ 1 Psy-Q とは

Psy-Q は、Psygnois および SN Systems が、その長年の経験を活かし開発した、PC/AT 互換機上で動作する、PlayStation アプリケーションのための強力な開発システムです。
PlayStation 開発環境の特長は、ハードウェアのほとんどの機能を網羅した充実したライブラリ群、Ｃ言語による開発にあります。Psy-Q は、PlayStation ライブラリと、開発ホストである PC/AT 及びターゲットボード（弊社製 PlayStation ボード DTL-H2000,DTL-H2500,DTL-H2700）との連携を図るとともに、開発に欠かせない環境を提供しています。
なお、DTL-H2500をご使用の場合は、本ドキュメントに併せて、PlayStationライブラリCD-ROMの \PSYQ\FLASH25\README.TXTをお読み下さい。DTL-H2700をご使用の場合は、本ドキュメントに併せて、DTL-H2700付属のユーティリティディスクを御参照下さい。

統合コンパイラを提供

GNU C、GNU C++をベースとした統合コンパイラ CCPSX を提供。プリプロセス、コンパイル、アセンブル、リンクを自動的に実行。

高速リンカ、ライブラリアン

非常に高速なリンカ、ライブラリアンを提供。オブジェクト生成までの待ち時間は少なく、ストレスを感じさせません。また、作成したオブジェクトをライブラリ化することにより、プログラミングの効率がグンとアップします。

強力なソースレベルデバッガ

ホップアップメニュー、マウスでの操作も可能な使いやすいインターフェイスを採用した強力なデバッガを提供。そのソースレベルデバッグ機能により、プログラマは、Ｃまたはアセンブラのソースコードを元に、トレース、ブレークポイントの設定等を行なうことができます。

高速 R3000 アセンブラ

付属の R3000 アセンブラは、１分間に 100 万行以上をアセンブルする能力があり、ターゲットマシンと直接通信することができます。

3. 1 ハードウェアのセットアップ

まず、各種のハードウェアを PC に装着します。なお、作業に際しては、必ず PC 本体の電源を落としておくようにしてください。その他詳細はターゲットボードの取扱説明書をご参照ください。

3. 2 ソフトウェアのセットアップ

セキュリティドンクル（D-Sub25ピン型のコネクタ）を、PCのパラレルポート（プリンターポート）に差し込んでください。
ハードウェアの装着が終了したら、続いてソフトウェアをインストールします。

(1) ディレクトリの作成

ハードディスクに、Psy-Q の各種ツールを格納するためのディレクトリを作成します。ここでは、各ディスクの内容に従って、以下のように作成することにします。

対象ディスクディレクトリ実行例
Psy-Q\PSYQC:>MD \PSYQ
GNU C\COMPILERC:>MD \COMPILER
GNU C++\COMPILER 同上
Ｃドキュメント\COMPILER\DOCC:>MD \COMPILER\DOC (※)
作業用ディレクトリ\TMPC:>MD \TMP

※"\COMPILER\DOC"は、"\COMPILER"のサブディレクトリですので、"\COMPILER"がない状態で作成できません。必ず、"\COMPILER"作成後に実行してください。

(2) ファイルのコピー

新たに作成したディレクトリに移動し、ここに、各ディスクの内容を DOS の"XCOPY"コマンド等ですべてコピーします。

Ｃドキュメント
\COMPILER\DOC

C:>XCOPY A:\*.* ／S

※ディスクがAドライブにあるものとしています。

(3) PATH の設定

AUTOEXEC.BAT を編集し、Psy-Q ソフトウェアを格納したディレクトリを PATH に追加します。なお、Ｃドキュメントディスクには実行ファイルが含まれていませんので、これを追加する必要はありません。

例

        PATH=C:\DOS;C:\BIN;C:\PSYQ;C:\COMPILER;

(4) システムドライバの登録

AUTOEXEC.BAT に次の行を追加し、PC の起動時にシステムドライバが自動的にロードされるようにします。なお、ここに記述したものは工場出荷時の設定に基づいた指定です。ボードの設定を変更した場合は、11ページを参考に、オプションを変更してください。

        DEXBIOS /a1340

(5) 環境変数の登録

AUTOEXEC.BAT に次の行を追加し、PC の起動時に"PSYQ"環境変数が設定されるようにします。環境変数の値としては、ソフトウェアを格納したディレクトリ名を指定します。

        SET PSYQ=C:\PSYQ
さらに、コンパイラを正しく動作させるために、以下の環境変数を設定します。なお、ここに記述したのはあくまで一例ですので、お使いのディレクトリ構成に合わせて指定してください。また、パスの区切り文字は"\"ではなく、"/"で指定してください。詳細については 18ページを参照してください。
        SET COMPILER_PATH=c:/compiler
        SET PSYQ_PATH=c:/psyq
        SET C_INCLUDE_PATH=c:/psx/include
        SET LIBRARY_PATH=c:/psx/lib
        SET TMPDIR=c:/tmp
        SET GO32TMP=c:/tmp

(6) AUTOEXEC.BAT の確認

AUTOEXEC.BAT の編集が終了したら、その内容を確認した上で、MS-DOS に戻ってください。

例

        @ECHO OFF
        PROMPT=$p$g
        PATH=C:\DOS;C:\BIN;C:\PSYQ;C:\COMPILER;C:\;
        SET PSYQ=C:\PSYQ
        SET COMPILER_PATH=c:/compiler
        SET PSYQ_PATH=c:/psyq
        SET C_INCLUDE_PATH=c:/psx/include
        SET LIBRARY_PATH=c:/psx/lib
        SET TMPDIR=c:/tmp

↑ 6 システムドライバ DEXBIOS.COM

DEXBIOS.COM は、PC に装着したターゲットボードと、PC/AT 本体、そして Psy-Q システムとの間を取り持つ常駐プログラムです。Psy-Qを利用するには、必ず、これを常駐させておく必要があります。
通常、AUTOEXEC.BAT 内で実行し、PC の起動時に自動的にロードされるようにします。

DEXBIOS.COMは、DTL-H2000及びH2700用のドライバです。H2500では、DEXBIOS.COMではなく専用のドライバH25BIOS.COM を使用する必要があります。詳しくは \PSYQ\FLASH25\README.TXTを御参照下さい。

6. 1 書式

DEXBIOS を起動するには、MS-DOS のプロンプトに対し、次のように入力します。

        DEXBIOS [/option]

オプションは"/"（スラッシュ）に続けて指定します。複数指定する場合はスペースで区切ります。

6. 2 オプション

DEXBIOS.COM には、以下のオプションを指定することができます。"/"（スラッシュ）に続けて指定します。複数指定する場合はスペースで区切ります。特に指定しなかったものについては、デフォルト値が用いられます。
ターゲットボードは、工場出荷時の状態で、他のボードやインターフェイスと最大限衝突しないように設定されていますので、通常、次のように指定します。

例 工場出荷時の設定に基づく指定

        DEXBIOS /a1340
が、ボードの設定を変更し、PC に装着した場合は、以下を参考に AUTOEXEC.BAT に追加した行のオプションを書き換えるようにしてください。

カードアドレス(/a)

"/a"に続き、カードアドレスを16進数で指定します。

例

        DEXBIOS /a308

ファイル転送バッファサイズ(/b)

"/b"に続き、ファイル転送バッファサイズを10進数指定してください。指定できるサイズは２～32（単位は KB）です。
このオプションは、PC 上のファイルにターゲットボードがアクセスするときに用いる転送バッファの大きさを指定するものです。サイズを大きくすると、アクセスがより速くなりますが、その分、メモリ消費量は増加します。通常は特に指定する必要はありません。

例

        DEXBIOS /b2

IRQ 番号(/i)

"/i"に続き、IRQ 番号を指定してください。IRQ 番号としては、10、11、12、15 が指定できます。なお、０を指定すると OFF となり、IRQ を使用せずに動作します。

例

        DEXBIOS /i15

備考

DEXBIOS をオプションなしで再度実行すると、常駐イメージが一旦メモリから削除されます（常駐解除されます）。これにより、PC をリブートすることなく、オプションを変更することができます。

↑ 7 ターゲットボードブートプログラム RESETPS

ターゲットボードは、PC/AT に電源を投入（あるいはリセット）すると、PlayStation 実機モードで立ち上がります。これは、CD-ROM ドライブからのブートシーケンスを実行するモードで、デモンストレーション等に便利な設計となっています。
ただし、開発に際しては、ターゲットボードをデバッグに適した状態に変更する必要があります。そこで Psy-Q では、これをサポートするプログラム RESETPS.EXE を用意しています。これにより、ディップスイッチなどのハードウェアを触ることなく、MS-DOS 上から簡単にモードを変更することができます。
なお、RESETPS を実行するには、DEXBIOS が常駐している必要があります。AUTOEXEC.BAT に記述する際は、必ず DEXBIOS の行の後に記述してください。

注意：

DEXBIOS は"RESETPS 1/"と同じリセットをかけます。よってRESETPS の使用は、暴走もしくは、起動したソフトを止める場合に限られます。

7. 1 書式

RESETPS を実行するには、MS-DOS のプロンプトに対して次のように入力してください。また、RESETPS を実行するには、DEXBIOS が常駐している必要があります。

        RESETPS <mode number> [/a<address>]

コマンド名に続き、実行モード番号を指定します。指定できる値とその内容は次の通りです。

モード番号動作
0
PlayStation 実機モード
CD-ROM からのブートシーケンスを実行します。
1
デバッグモード
開発に際してはこのモードを指定してください。
2
デバッグモニタモードが利用できるようになります。
(Psy-Q環境では特に使用しません)
3
カラーバー表示モード
ビデオ画面にカラーバーを表示します。


また、実行モード番号に続き、オプションとして、ターゲットボードのアドレス番号を指定することもできます。指定方法は DEXBIOS の"/a"オプションと同様です。
ただし、これは DEXBIOS が常駐していない場合にのみ指定する、特殊なオプションですので、通常は指定する必要はありません。

↑ 8 スタートアップルーチンについて

通常、実行プログラムにはスタートアップルーチンが組み込まれます。プログラムはスタートアップルーチンから実行され、様々な初期設定を行ってからmain関数へとジャンプします。
ここでは、LIBSN.LIB に含まれるスタートアップルーチンの動作と、PSX\LIBに含まれる各代替OBJ
        noheap.obj, 2mbyte.obj, 8mbyte.obj, none2.obj, none3.obj
の説明を行ないます。

ライブラリ Ver.3.1以前の LIBSN.LIB には一部問題があり、スタートアップルーチンの代わりにリンクする代替OBJが必要でした。それが 2mbyte.obj, 8mbyte.obj です。Ver.3.1以降では 2mbyte.obj, 8mbyte.obj は特に必要でありません。Ver.3.1以降では、２つの変数 _ramsize と _stacksize をプログラム中で以下のように定義することによって、SP初期値や起動時のヒープ領域を設定できます。ただし、２変数を定義する場合は、必ず２つとも定義して下さい。どちらか片方のみの定義だとリンク時にエラーが発生します。

            int _ramsize = 0x00200000;      /* RAM SIZE */
            int _stacksize = 0x00008000;    /* STACK SIZE */

上の定義では、

            SP初期値      0x801ffff8
            ヒープ領域    bssセクションの直後から 0x801f8000 までを確保

となります。
なお、スタートアップルーチン内でヒープ領域を設定する必要がない場合は、noheap.objを御使用ください。プログラム中で明示的にInitHeap()を行っていたり、もしくはmalloc()等のメモリ管理関数を全く使用していない場合などがこれにあたります。
また、Exec() や LoadExec() で起動する子プログラム用のスタートアップルーチンとして、none2.obj, none3.obj を配布しています。子プログラム用のスタートアップルーチンは、SPの設定を行ないません。
これは、子プログラムのSP初期値を、親プログラム側から LoadExec() の引数等によって設定できるようにする為です。none2.obj は、sbss,bss領域のクリアを行なわない為、ライブラリVer.3.7で削除されました。none3.objの方をお使い下さい。
以下、スタートアップルーチンのデフォルト動作と、各代替OBJをリンクした場合の動作を説明します。

8. 1 デフォルトの動作

(1) sbss, bss 領域をゼロクリアする。

(2) SP初期値をセットする。

( ( _ramsize - 8 ) | 0x80000000 ) の値がセットされる。プログラム中で _ramsize を定義していない場合は、_ramsize としてデフォルト値 0x00800000 が使用されるので、SP初期値は 0x807ffff8 となる。

(3) グローバルポインタ（GP）をセットする。

.sdata領域の最初のアドレスがセットされる。

(4) InitHeap()をする。

bss領域の直後のアドレスから、( _ramsize - _stacksize ) のアドレスまでを、ヒープ領域に設定する。
（この時、ヒープ領域の一部にメモリ管理情報が書き込まれます）尚、プログラム中で _stacksize を定義していない場合は、_stacksizeとしてデフォルト値 0x00008000 が使用される。

(5) main関数にジャンプする。

8. 2 noheap.obj をリンクした場合の動作

１のデフォルト動作とほぼ同じだが、(4)の InitHeap() を行なわない。

8. 3 2mbyte.obj をリンクした場合の動作

sbss, bss 領域をゼロクリアする。
SP初期値をセットする。_ramsize は 0x00200000 に固定。
GPをセットする。sdataセクションの最初のアドレスがセットされる。
InitHeap()をする。_stacksize は 0x00008000 に固定。
main関数にジャンプする。

8. 4 8mbyte.obj をリンクした場合の動作

sbss, bss 領域をゼロクリアする。
SP初期値をセットする。_ramsize は 0x00800000 に固定。
GPをセットする。sdataセクションの最初のアドレスがセットされる。
InitHeap()をする。_stacksize は 0x00008000 に固定。
main関数にジャンプする。

8. 5 none2.obj をリンクした場合の動作

GPをセットする。sdataセクションの最初のアドレスがセットされる。
main関数にジャンプする。
