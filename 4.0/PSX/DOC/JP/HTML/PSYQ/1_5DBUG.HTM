デバッガ DBUGPSX

Psy-Q には、作成したプログラムをデバッグするツールとして、強力なソースレベルデバッガ DBUGPSX が用意されています。
DBUGPSX を用いることにより、ソースコードを表示し、これを基に実行、トレース、ブレークポイントの設定／解除を行なうことができます。無論、従来のシンボリックデバッグ機能もすべて利用することができます。
なお、ソースレベルの情報が利用できない場合は、逆アセンブラ表示となります。

↑ 1 書式

DBUGPSX を実行するには、MS-DOS のプロンプトから次のように入力します。

        dbugpsx [/option] <filename> [filename]...

オプションは"/"（スラッシュ）に続けて指定します。複数指定する場合はスペースで区切ります。
オプションに続き、シンボルファイル名を指定します。シンボルファイルを指定することにより、ソースレベルデバッグを行なうことが可能となります。拡張子が省略された場合、".SYM"が用いられます。次の例では、test.sym を指定しています。
日本語モードより起動する場合は、必ず /r オプションで行数指定を行って下さい。ハングアップする場合があります。

例

        dbugpsx /r50 test
ファイルはスペースで区切り複数指定することができます。この場合、ファイルは左から順に読み込まれていきます。

例

        dbugpsx /r50 test1 test2

↑ 2 オプション

オプションは"/"（スラッシュ）に続けて指定します。複数指定する場合はスペースで区切ります。
オプションには以下のものがあります。

ファイルのロード(/e[<file>[,<file>]])

"/e"に続き、ロードする CPE ファイル file を指定します。ファイルはコンマで区切って複数指定することができます。また、同じ名前のSYMファイルを指定する場合には省略する事も
できます。

例

        dbugpsx /r50 /etest.cpe test

例

        dbugpsx /r50 /e test

オート実行をオフにする(/d)

デバッグ情報付きのSYMファイル(-gでコンパイルされたもの）を指定して起動した場合、デバッガは自動的に __SN_ENTRY_POINT(PC初期値）からmain()の先頭までの処理を実行します。"/d" オプションを指定すると、この処理は行われません。main()より前の部分をステップ実行したい場合等に便利です。

例

        DBUGPSX /d /r50 /e main

ターゲット停止(/h)

"/h"を指定すると、デバッガのスタート時にターゲットマシンを停止します。

コンフィグファイル名指定(/s<file>)

"/s"に続き、コンフィグファイル名 file を指定します。

式の評価(/v<exprtext>)

"/v"に続き、式 exprtext を指定すると、これを評価し、標準出力に出力します。

表示行数指定(/r<num>)

"/r"に続き、表示行数 num を指定します。

例

        dbugpsx /r50 test

大文字／小文字を区別しない(/c-)

"/c-"を指定すると、大文字と小文字を区別しません。

大文字／小文字を区別する(/c+)

"/c+"を指定すると、大文字と小文字を区別します。

更新間隔指定(/i<num>)

"/i"に続き、更新間隔（1/18 秒単位） num を指定します。

継続更新モードオン(/u+)

"/u+"を指定すると、継続更新モードをオンにします。

継続更新モードオフ(/u-)

"/u-"を指定すると、継続更新モードをオフにします。

パラメータ式の指定(/&<expr>[,<expr>])

"/&"に続き、デバッガに渡すパラメータ式 expr を指定します。式はコンマで区切って複数指定することができます。
"/&"を使ってデバッガに渡された式は、"&0"、"&1"などの形で参照することができます。０は最初の式、１は２番目の式を表します。

マウスの感度(/m<num>)

"/m"に続き、マウスの感度 num を指定します。num に指定できるのは１～４までで、デフォルトは３です。
DBUGPSX はマウスドライバを内蔵しています。これにより、特に 132 カラムモードでの、Microsoft マウスドライバに見られる欠点をカバーすることができます。

システムのマウスドライバを利用(/m+)

"/m+"を指定すると、システムのマウスドライバを利用します。Microsoft の最近のドライバ（バージョン８以降）であれば、マウスを DOS ウィンドウでも利用することができます。

DBUGPSX のマウスドライバを利用(/m-)

"/m-"を指定すると、DBUGPSX に内蔵されているマウスドライバを利用します。

日本語モード用画面スイッチ(/j)

画面を日本語モード用に切り替えます。

例

        DBUGPSX /j /r50 /e main

ヘルプ表示(/?)

"/?"を指定すると、ヘルプメッセージを表示します。

↑ 3 コンフィグファイル

DBUGPSX は、ロード時に、デバッガ環境に関する情報を含むコンフィグファイルにアクセスします。現在の設定は、デバッガの中からいつでも保存することができます。

3. 1 コンフィグファイル名

デバッガは、次の順でファイルを検索し、読み込みます。
また、コンフィグファイル名は "/s"オプションで指定することも可能です。

(1) DBUGPSX.C##を検索

まず、一般的なコンフィグファイルである"DBUGPSX.C##"を検索します。#の最初の数字は常に０、２番目は仮想スクリーンの番号（次頁「アクティブウインドウ」参照）です。通常、"DBUGPSX.C00"となります。

(2) DBUGPSX.DF#を検索

DBUGPSX.C##がカレントディレクトリにない場合、デフォルトのコンフィグファイルである"DBUGPSX.DF#"を検索します。

(3) SONY_PSX.CFG を検索

DBUGPSX.DF#も存在しない場合、デバッガのホームディレクトリから"SONY_PSX.CFG" を検索します。

3. 2 コンフィグファイルの内容

コンフィグファイルは以下の情報を含んでいます。
  • 読み出しメモリの範囲
  • 書き込みメモリの範囲
  • ビデオの種類及び使用法
  • ラベルのレベル
  • カラー及びモノクロ属性
  • タブの設定
  • 現在のウィンドウの種類及び表示位置
  • ブレークポイント
  • ヒストリの詳細

3. 3 デバッガ・コンフィギュレーション・ファイル dbugpsx.c##について

CTRL+Ｘを使ってデバッガを終了した場合には、デバッガ実行時に設定されていた環境が保存されることはありません。ALT+Ｘを使う場合にのみ、debugpsx.c00 というファイルに、終了時の環境が保存されます。このとき、ALT+0、ALT+1、ALT+２といったキー操作によってアクセスする仮想スクリーン（後述）ごとの設定内容は、それぞれスクリーン番号に対応する数字を末尾に持つ debugpsx.c##に保存されます。これらの内容は、次回の起動時に自動的に読み込まれます。

↑ 4 アクティブウィンドウ

デバッガの表示は、複数のアクティブウィンドウから成っています。ウィンドウの数、各ウィンドウの内容、及びウィンドウのサイズはすべて、ランタイム時に指定することができます。デフォルトの表示は、以下の２つのウィンドウから成ります。上部のウィンドウは通常、レジスタを表示し、下部のウィンドウは、現在ポインタがあるコードの逆アセンブルを表示します。
デバッガは、最大 10 個の仮想スクリーンを実行することができます。各スクリーンには、専用のコンフィグがあります（「３コンフィグファイル」参照）。ALT-<n> を押すと、別のスクリーンにアクセスすることができます。ｎは０～９までのスクリーン番号を表し、０はスクリーン 10 を表しています。例えば、スクリーン１にアクセスするには、ALT-1 を押します。

4. 1 ウィンドウの種類

ウィンドウには以下の種類があります。ウィンドウの種類は、[Window]メニューの"Set type"で指定します。

ファイルウィンドウ(ソースウィンドウ) (FILE)

ファイルウィンドウ(ソースウィンドウ)はソースファイルを表示するためのものです。このウィンドウを選択すると、入力ボックスが表示されますので、ここでファイル名を指定してください。ファイルが表示されます。ファイル名を指定しない場合、ウィンドウは空のままとなります。このウィンドウに対してEnterキーを押すと、いつでも、ファイル名指定のための入力ボックスが表示されます。
このウィンドウは、デバッグ中にソースコードをダイナミックに表示するためのものです。ソースコードは、これがプログラムカウンタ(PC)のスコープにある場合のみ、表示されます。
デバッグ情報付きのSYMファイル(-gでコンパイルされたもの）を指定して起動した場合、デバッガは自動的に __SN_ENTRY_POINT(PC初期値）からmain()の先頭までの処理を実行します。("/d" オプションを指定すると、この処理は行われません。)
このときウィンドウには"main"のソースコードが表示され、ソースコード上で、シングルステップ、ブレークポイントの設定/解除、ブレークポイント数の設定などが行なえます。
ソースレベルのデバッグ情報がないライブラリ内ルーチンやROM内ルーチンを呼び出した場合は、そのルーチン全体を実行してから、ソースレベル情報のあるユーザールーチンに戻ります。また、ライブラリ内ルーチンをトレースするには、逆アセンブルウィンドウを利用してください。

16進ウィンドウ(ダンプウィンドウ) (HEX)

16進ウィンドウ(ダンプウィンドウ)は、メモリ内容を指定されたアドレスから16進表示します。表示アドレスを変更するには、ALT-Gを押し、続いて入力ボックスにアドレスかラベル名を入力してください。

逆アセンブルウィンドウ (DIS)

逆アセンブルウィンドウは、ターゲットメモリの内容を、逆アセンブルしたコードとして表示します。表示アドレスを変更したい場合は、ALT-Gを利用してください。
上矢印または下矢印で、表示をスクロールさせることができます。プログラムカウンタ(PC)のアドレスに戻りたい場合は、TABを押してください。また、現在、カーソルがある位置をPC値としたい場合はSHIFT-TABを押してください。

レジスタウィンドウ (REG)

pollhost()が最後に呼び出されたときのR3000レジスタの内容を表示します。

Watchウィンドウ (WATCH)

このウィンドウで、指定した変数を監視することができます。

変数ウィンドウ (VAR)

現在のルーチンのスコープ内にある変数を一覧表示します。従って、別のルーチンに出入りする度に内容が変更されます。

メッセージウィンドウ (MSG)

ターゲットの出力するメッセージを表示します。また、PCwrite()関数で負のファイルハンドルを指定した場合に、データはこのウィンドウに転送・表示されます。但し、転送可能なのはASCIZ文字列のみで、バイナリデータはゴミとして表示されます。ファイルハンドルとウィンドウの番号には関連があり、次のようになっています。
  • fdが-1の場合、ウィンドウ01に表示されます
  • fdが-2の場合、ウィンドウ02に表示されます

4. 2 ウィンドウ間の移動

ウィンドウ間の移動方法には、次のものがあります。
  • F1 を押し、続いて上矢印または下矢印キーを押す
  • SHIFT を押したまま上矢印または下矢印キーを押す
  • マウスで目的のウィンドウをクリックする

4. 3 ウィンドウの種類の選択

現在選択しているウィンドウの種類を変更する方法には、次のものがあります。
  • [Window]メニューから"Set type"オプションを選択する（マウスで行なう）
  • SHIFT を押したまま F1 を押す
いずれの場合も、新たに種類選択ウィンドウが表示されますので、ここでマウスまたは矢印キー & ENTER キーで、新しい種類を選択してください。

4. 4 ウィンドウのサイズ変更

ウィンドウのサイズを変更するには、次のようにしてください。
また、CTRL-Z を押すと、選択したウィンドウをスクリーンいっぱいに拡大することができます。元の大きさに戻すには、再度 CTRL-Z を押してください。
  1. 目的のウィンドウにカーソルを持って行きます。
  2. F2 を押します。
  3. 上矢印または下矢印キーを使い、選択したウィンドウの端を、希望するサイズになるまで移動させてください。
  4. 作業が終了したら ENTER キーを押し、サイズを確定させます。

4. 5 ウィンドウの追加

新たなウィンドウを追加するには、次のようにしてください。
  1. 目的のウィンドウにカーソルを持って行きます。
  2. F3 を押します。
  3. ウィンドウを作成したい方向を指す矢印キーを押します。
  4. 矢印キーで示した位置に新しいウィンドウ（カーソルがあったウィンドウと同じ種類）が追加されます。

4. 6 ウィンドウの削除

ウィンドウを削除するには、次のようにしてください。
  1. 目的のウィンドウにカーソルを持って行きます。
  2. F4 を押します。
  3. 上矢印または下矢印キーで、削除するウィンドウの端を選択します。ENTER キーを押してください。

4. 7 ウィンドウ内でのカーソル移動

選択したウィンドウ内でカーソルを移動させるには、矢印キーを用います。使用できるキー及び動作は、ウィンドウの種類によって異なります。

レジスタウィンドウ

レジスタ値の間を移動するには、矢印キー（上下左右）を使用します。また、HOME キーを押すと、カーソルは、レジスタフィールドの左上に移動します。

ウォッチウィンドウ

隣り合う行及び文字間を移動するには、矢印キー（上下左右）を使用します。また、HOME キーを押すと、カーソルは、レジスタフィールドの左上に移動します。

逆アセンブルウィンドウ／テキストウィンドウ

強調表示されたバーに移動するには、上矢印及び下矢印キーを使用します。また、HOME キーを押すと、カーソルの下の行が、ウィンドウの最上段に移動します。

16 進ウィンドウ

隣り合う行、及びバイト／ワード間を移動するには、矢印キー（上下左右）を使用します。また、HOME キーを押すと、カーソルの下のバイトまたはワードが、ウィンドウの左上に移動します。

4. 8 ウィンドウのロック

次に示す方法で、ウィンドウをロックし、特定のメモリ領域を表示することができます。
  1. ALT-L を押します。
  2. 入力ボックスで、アドレス、あるいはアドレスに対して評価を行なう式を入力します。
  3. [Window]メニューから"Lock"オプションを選択します。
  4. CTRL-L を押し、ロックを ON/OFF します。

また、画面表示を、式"&0"にロックすることができます。これにより、コマンドラインで指定されたアドレスまたはラベルを指すウィンドウで、デバッガをスタートさせることができます。
なお、ロック式を設定し、CTRL-L で非アクティブ化した場合、デバッガは、最初に指定されたロックアドレスを表示してスタートアップしますが、ウィンドウのスタートは、通常どおり、カーソルキーなどで引き続き変更することができます。

↑ 5 一般的なマウスの使用法

マウスの一般的な使用法は次の通りです。
  • 左ボタンをクリックすると、デバッガのカーソルがマウスカーソルのある位置に移動します。マウスカーソルが別のウィンドウにある場合は、そのウィンドウがアクティブウィンドウになります。
  • レジスタウィンドウのレジスタを、右ボタンでクリックすると、式入力ボックスが開きます。
  • 16 進ウィンドウのメモリフィールドを、右ボタンでクリックすると、式入力ボックスが開きます。
  • 逆アセンブルウィンドウの行を、右ボタンでクリックすると、ブレークポイントがトグルします。
  • ウィンドウの端を、左ボタンでクリックし、新しい場所へドラッグすると、ウィンドウのサイズを変更することができます。
  • ウィンドウの境界線をウィンドウの端へドラッグすると、そのウィンドウが削除されます。

↑ 6 キーボードオプション

キーボードオプション（キーボードでの操作）には、さまざまなものがあります。ここではこれを機能別に表で記述していきます。
セッション中の多くの箇所で、デバッガは入力を求めます。これは、大抵の場合、評価式の形式を取ります。以下の例外を除いては、デバッガにおける式は、アセンブラと同じ規則に従います。
  • 式は、プロセッサレジスタを含むこともできます。
  • デバッガは、16 進数を採用しています。数字が 10 進であることを示すには、数字の前に"#"記号を付けます。
  • 間接アドレスは、"[]"で囲まれて表示されます。
  • デバッガは、間接データが渡されると、これをロングワードであると想定します。ただし、"[]"の後に"b"（バイトを示す）または"w"（ワードを示す）を付加し、同時に"."（ドット）の代わりに"@"を使ってこれを上書きすることができます。
また、ファイル名など、デバッガに対する入力はヒストリとして保存されます。これらのヒストリは、入力時に上下矢印キーで呼び出し、編集することができます。デバッガを終了すると、ヒストリは各クラス毎に最大４つまで保存され、次のデバッガ起動時に読み込まれます。保存はコンフィグファイルに対して行なわれます。

6. 8 補足事項

(1) ターゲットの出力メッセージについて

DEXBIOS Ver.1.22以前をご使用の場合

IRQ割り込みを利用する事により、MSGウィンドウへの出力を高速にする事ができます。それには以下の設定が必要です。
    1) DTL-H2000のIRQジャンパを設定する。詳しくはH2000の取扱説明書参照。（出荷時はIRQなしに設定されています）
    2) DEXBIOS起動時にオプション /i を設定する

例：address 0x1340, IRQ 10 に設定している場合

                 DOS> DEXBIOS /a1340 /i10

（注意）

IRQ割り込みを使用した場合、短い時間に大量のメッセージを出力しようとすると、デバッガ内部のバッファに入り切らずに、表示が抜け落ちてしまう場合があります。そのような場合は、DEXBIOSの /i 設定をせずにご使用下さい（IRQなしの状態になります）。

DEXBIOS Ver.1.23以降をご使用の場合

MESS1.COMは、メッセージハンドラをDOS上に常駐する事で、より多くのバッファを確保します。これによって高速、かつ表示抜けのないメッセージ出力が得られます。MESS1.COMはDEXBIOS Ver.1.23以降に対応しています。

Usage: MESS1 <buffer size>

デフォルトのバッファサイズは4Kです。最大 65534byte まで指定できます。

例

        > dexbios /i11
        > mess1 10000

(2) ハードウェアブレーク機能について

DBUGPSX Ver.4.30より、ハードウェアブレーク機能が使用できるようになっています。ある範囲のアドレスに対して read/write アクセスがあった時にブレークします。この機能を使用するには、DBUGPSX を起動する前に、あらかじめ NEWDEX.CPE が実行されていなければなりません。NEWDEX.CPEは、CPUのハードウェアブレーク機能を使用する為に必要なモジュールです。
尚、パッチモジュールとしてSNPATCHJ.CPE又はSNPATCHW.CPEをご使用の場合は、NEWDEX.CPEを実行するは必要ありません。

（起動例）

        DOS> run patchx
        DOS> run newdex
        DOS> dbugpsx /r50 /e main

（起動例）

        DOS> run snpatchj
        DOS> dbugpsx /r50 /e main

（使用法）

Alt-B でダイアログが表示され、パラメータが要求されます。（NEWDEX.CPEが実行されていない場合は「Hardware Break requires newer Psy-Q downloader」とエラーが出ます。）
指定するパラメータの詳細を以下に挙げます。

Read access: 指定アドレスをリードした時にブレークします。
Write access: 指定アドレスにライトした時にブレークします。

Assembly Syntax (use ASM):

指定された範囲のアドレスに対してブレークポイントをセットします。デバッガは、直前にアクセスしたアドレス(Access address)とBase address を比較し、一致していればブレークします。ただし、その比較の際、Address mask で 0 のビットは無視されます。この Address mask の値によって範囲の指定を行います。
式で表すと、以下のようになります。この式が真である場合にブレークします。
         (Base address) == ((Access address) & (Address mask))

例

Base address は16進入力、Address mask は16/10進入力。 
        Base address	80080000
        Address mask	$fffffffc (or -4)
では、0x80080000-0x80080003 の範囲が指定されます。
        Base address	80080000
        Address mask	$fffffff0 (or -10)
では、0x80080000-0x8008000f の範囲が指定されます。

C Syntax (use C):

指定のアドレスに対してブレークポイントをセットします。シンボル指定もできるので、任意の関数、グローバル変数をセットできます。ある関数中のローカル変数を指定する事もできますが、その場合は、既にその関数まで処理が移っている事と、-g オプションでコンパイルされている事が条件です。
