オプション、リスティング及びエラー

ここでは、ランタイム時のアセンブラオプションの決め方、リスティングの作成及びエラーの処理、並びにリンカへの情報の引き渡し方法について解説します。

↑ 1 オプション

オプションを制御するディレクティブとして以下のものがあります。

OPT


書式
OPT <option>[,option]...

解説
アセンブラオプションをアプリケーションコード内で使用可能または使用不能にすることができます。
option には、以下のものが指定できます。また、オプション名の後ろに"+"を付加するとそのオプションが ON になり、"-"を付加すると OFF になります。

↑ 2 オプションの詳細

2. 1 AE - 自動偶数配置

DC、DCB、DS 及び RS をハーフワード及びワードフォームを使用しているとき、このオプションを ON にすると、プログラムカウンタが、実行に先立って、続くワード境界に強制的に配置されます。デフォルトは ON です。

2. 2 AN - 他の数値形式を使用

このオプションを設定すると、16 進、10 進、または２進数を意味する"H"、"D"、あるいは"B"が末尾にある、Ziglog または Intel フォーマットの数値定数を利用することができます。詳しくは RADIX の項を参照してください。

2. 3 C - 大文字と小文字の区別

Ｃオプションが設定されていると、ラベル名の文字のケースが有効になります。例えば、"SHOWSTATS"、"ShowStats"、"showstats"はすべて（別のものとして）有効となります。

2. 4 D - ローカルラベルのスコープ解除

このオプションを ON にすると、EQU または SET 命令が検出されると、ローカルラベルのスコープが解除されます。

2. 5 E - エラーテキストの表示

このオプションを ON にすると、アセンブラエラーの原因となった行のテキスト、並びにホストファイル名及び行番号が表示されます。デフォルトは ON です。

2. 6 L<c> - ローカルラベル開始記号の指定

ASMPSX では、ローカルラベルは、先頭の"@"（アットマーク）によって識別されます。このオプションにより、任意の文字ｃを開始記号とすることができます。
例えば"L:"とするとローカルラベル開始記号はコロンになります。なお、"+"と"-"は特殊な意味を持ち、"L+"とすると開始記号はクエスチョンマークとなり、"L-"とすると開始記号はアットマークになります。

2. 7 W - 警告メッセージの表示

このオプションを OFF にすると、警告メッセージの表示が抑制されます。デフォルトは ON です。

2. 8 WS - ホワイトスペース挿入

このオプションを ON にすると、オペランドにホワイトスペース（スペースと TAB）を含めることができます。
例えば
        dw	1 + 2
は、WS が OFF の場合には１、WS が ON の場合には３となります（何れも単位はワード）。

2. 9 X - XREF が定義したセクションにあるか

このオプションを ON にすると、XREF が、定義されたセクションの中にあるものと想定します。これにより、セクションが WORD 属性で定義されているか、または WORD 属性をもつグループにある場合は、絶対ワードアドレスへの最適化が実行されます。

↑ 3 その他のディレクティブ


PUSHO、POPO


書式
PUSHO
POPO

解説
PUSHO 命令は、すべてのアセンブラオプションの現在値を保存します。POPO は、オプションを、以前の状態に復元します。
これらは、１つまたは複数のオプションに一時的な変更を行なう際に使用します。

参照
OPT

例 
	pusho
	opt	ws+,c+
SetAlts	=	height*time
SETALTS	dh	256* SetAlts
	popo

LIST、NOLIST


書式
NONLIST
LIST <indicator>

解説
NOLIST 命令は、リスト生成を OFF にします。LIST 命令は、リスト作成を ON にします。
indicator に指定できるのは"+"（プラス）または"-"（マイナス）です。

備考
ASMPSX の引数、または ASMPSX 環境変数によりリスティングファイルが指定された場合、ファイルは最初のパス中に作成されます。
アセンブラは、元々０に設定されている、リスティングの現行ステータス変数を維持します。リストの出力は、この変数が０または正のときのみ行なわれます。リスティングディレクティブは、リスティング変数に次のような影響を及ぼします。
NONLIST は、変数を-１に設定します
パラメータをもたない LIST は、変数を０にします
LIST + は、変数に１を加えます
LIST - は、変数から１を引きます

例

ディレクティブ変数値リスティングの作成
nolist-1No
list - -2No
list 0Yes
list --1No
list --2No
list +-1No
list + 0Yes

  • 下記の環境下では、アセンブラは、自動的にリスティングの作成を抑制します。
  • マクロの展開中
  • 条件判断の失敗のため、コードがアセンブルされない場合
これらの動作は、それぞれ下記の指定により無視することができます。
  • ASMPSX で"/m"オプションを指定し、マクロの展開をリストするよう指示する
  • ASMPSX で"/c"オプションを指定し、条件判断により無視されたコードをリストするよう指示する

INFORM、FAIL


書式
INFORM <severity>,<text>[,expressions]
FAIL

解説
INFORM は、オプションとして式 expressions の内容で置き換えられるパラメータを含む、テキスト text に入っているエラーメッセージを表示します。その後のアセンブラの動作は、重大度 severity の状態に基づいて規定されます。
severity に指定できる値とその内容は次の通りです。

値内容
0アセンブラは、単にテキストを表示します。
1アセンブラは、テキストを表示し、警告を発します。
2アセンブラは、テキストを表示し、エラーを起こします。
3
アセンブラは、テキストを表示し、致命的なエラーを起こし、アセンブル
を中止します。


FAIL は、定義済みステートメントであり、他のアセンブラとの互換性を保つために採用されています。これは、"Assembly Failed"メッセージを表示し、アセンブルを中止します。
これらのディレクティブにより、アセンブラが認識できないエラー状態が検出された場合でも、適切なメッセージを表示することができます。

備考
text には、"%d"、"%h"、"%s"パラメータを含めることができます。これらは続く式 expression に記述された 10 進、16 進または文字列値で置き換えられます。

例 
TableSize	equ	TableEnd-TableStart
MaxTable	equ	512
	if	TableSize>MaxTable
	inform	0,"Table starts at %h and &
		is%h bytes long",&
		TableStart,TableSize
	inform	3,"Table Limit Violation"
	endif

XDEF, XREF、PUBLIC


書式
XDEF <symbol>[,symbol]
XREF <symbol>[,symbol]
PUBLIC on
PUBLIC off

解説
別のサブプログラムで定義されたシンボルを参照するために、複数のサブプログラムをリンクしている場合は、XDEF、XREF、及び PUBLIC をコマンドを使用します。
XDEF は、symbol を外部シンボルとして定義します。すなわち、symbol を他のプログラムからも参照可能とします。
XREF は、symbol を外部シンボルとして扱います。すなわち、symbol が他のプログラムで定義されているものとして扱います。
PUBLIC は、オペランドに on を指定すると、off が指定されるまで、以降のシンボルをすべて外部シンボルとして扱います。

備考
アセンブラは、XREF されたシンボルを含む式を、完全に評価することはできませんが、リンカがこれを解決します。

例
次に示すのは、XDEF、XREF を使った例です。

例１

xdef	Scores,Scorers
	xref	PointsTable
	xdef	PointsTable
	xref	Scores,Scorers
また、PUBLIC を用いた例は以下のようになります。

例２

	public	on
Origin	=	MainChar
Force	dh	speed*origin
Rebound	dh	45*angle
	public	off

GLOBAL


書式
GLOBAL <symbol>[,symbol]

解説
GLOBAL ディテクティブは、シンボル symbol を XDEF、XREF のいずれにも定義することができます。
シンボルが GLOBAL として定義され、後にラベルとして定義された場合は、XDEF として扱われます。シンボルが一切定義されない場合は XREF として扱われます。

参照
XREF、XDEF、PUBLIC

備考
このディレクティブは、ヘッダファイルで利用すると便利です。すなわち、別々にアセンブルされるサブプログラムで、すべてのグローバルシンボルを定義する１つのヘッダファイルを共有することができるからです。
後でサブプログラムで定義されるシンボルは XDEF され、他のシンボルは XREF 扱いとなります。
