RSDフォーマット

↑1 概要

RSDフォーマットはPlayStationアーティストツール群で取り扱うモデリングデータのフォーマットです。RSDフォーマットは４種類のファイルで１つのモデルを記述します。そのため、４つのファイルを合わせて、「RSD」または「RSDデータ」ということがあります。

  • RSDファイル
    PLY/MAT/GRPファイル、テクスチャファイルおよび拡張ファイルの対応関係を記述
  • PLYファイル
    ポリゴンの頂点の位置情報を記述
  • MATファイル
    ポリゴンのマテリアル情報を記述
  • GRPファイル
    ポリゴンのグルーピング情報を記述

また、今回のバージョンよりHMDに対応するために新たに4種類の拡張ファイルと1種類のサブ拡張ファイルが加えられました。

拡張ファイル
  • MSHファイル
    ポリゴンの連結情報を記述
  • PVTファイル
    回転中心のオフセット情報を記述
  • CODファイル
    各VERTEXの持つCOORDINATE情報を記述
  • MOTファイル
    アニメーション情報を記述

サブ拡張ファイル
  • OGPファイル
    VERTEXのグルーピング情報を記述

すべてのファイルの関連情報はRSDファイル内に記述されているため、RSDファイルを指定するだけでオブジェクトを構成するファイルを知ることが可能です。(OGPファイルに関してはサブ拡張ファイルなので、
CODファイル中でのみ指定することが可能です。)

各ファイルは同一ディレクトリに存在する場合はファイル名のみで指定することができます。異なるディレクトリに存在するものに関しては相対パス(あるいは絶対パス）を示す必要があります。(TIMファイルに関しても同様です。)

RSDは全てテキストファイルであり、各データは改行文字(LFまたはCR/LF)で区切られた行単位で処理されます。任意の場所に#で始まるコメント行を挿入することができます。

↑2 RSDファイル

RSDファイルはオブジェクトを構成するPLY/MAT/GRPの各ファイル、テクスチャファイルおよび拡張ファイルの組合せ情報を持ちます。今回のバージョンから拡張ファイルを使用することで１組のRSDファイルで複数のオブジェクトを記述できるようになり、キャラクター単位でのデータの扱いが可能となりました。

↑3 PLYファイル

PLYファイルはポリゴン等の頂点位置を記述したファイルです。PLYファイルで扱う座標系は拡張ファイルを使用しなければPlayStation拡張ライブラリ(libgs)での座標系と同一で、X軸の向き(増加方向)が画面右、同様にY軸が下、Z軸が画面奥を表します。拡張ファイル使用時はPVTファイル内に記述される回転移動量を考慮し、HMD変換時にCODファイルに記述される各頂点毎のPlayStation拡張ライブラリ(libgs)での座標系に書き換えられます。
また、ポリゴンが片面ポリゴンである場合、ポリゴンの向き(表裏)はPOLYGON記述子における各頂点の記述順によって決定されます。ポリゴンの各頂点の記述順序が、空間中で時計回り(CW)になる面をポリゴンの表面とします。

パラメータ部にはポリゴンの各頂点に対応する頂点(VERTEX)、法線(NORMAL)が記述されています。頂点(0-3)、法線(0-3)の値はそれぞれのデータ群の中の先頭から何番目のデータであるかを示す整数値です(先頭を0とする)。

4角形ポリゴンの場合の各頂点の記述順は最初の3頂点が1つの3角形を構成し、第2,3,4頂点でもう1つの3角形を構成するように記述します。

[フラグ]

ポリゴンのマテリアル属性を表す１６進整数でプレフィックス '0x'はつきません。各bitの意味は次の通りです。

bit0 光源計算モード
    0：光源計算あり
    1：固定色

    光源計算ありの場合は光源とポリゴンの向きによって描画色を決定しますが、固定色の場合は向きに関わらず一定の色になります。

bit1 Back face
    0：片面ポリゴン
    1：両面ポリゴン

bit2 半透明フラグ
    0:半透明処理OFF
    1:半透明処理ON

    半透明処理ONの場合、テクスチャなしポリゴンは常に半透明テクスチャつきポリゴンはテクスチャデータのSTPビットによって半透明/不透明/透明をコントロールします。

bit3～5 半透明レート
    000:50% back + 50% polygon
    001:100% back + 100% polygon
    010:100% back - 100% polygon
    011:100% back + 25% polygon
    1XX:reserved

    現在のライブラリではポリゴン単位で半透明レートを変化させることはできません。

bit6 reserved (must be 0)

bit7 プリセット型HMD作成スイッチ(HMD作成時のみ)
    0:OFF
    1:ON

[シェーディング]

シェーディングモードを表す１文字のキャラクタです。
    "F"：フラット
    "G"：グーロー(スムーズ)

RSD拡張ファイルで、PLYファイル中のVERTEXにCOORDINATEの属性をつけることができます。これにより、複数MATRIXをもつHMDデータをRSDフォーマットより生成できるようになります。

(1) 全体構成

図 30 CODファイルの全体構成

(2) ID

CODファイルフォーマットのバージョンを表す文字列で"@CODnnnnnn"(nnnnnnは番号)という形式です。現在のバージョン1.0では"@COD970401" です。

(3) OGPファイル名

OGPファイルの名前を表し、OGP=OGPファイル名と記述されます。OGPファイルを使用しない場合はOGP=NULLと記述されます。

(4) COORDINATE数

後続のCOORDINATEの個数が記述されます。

(5) COORDINATE

COORDINATEの構成を定義します。複数行で構成されています。

[1～3行]

マトリックス係数値を指定します。数値は10進数で記述されます。

m[0][0] m[0][1] m[0][2]
m[1][0] m[1][1] m[1][2]
m[2][0] m[2][1] m[2][2]

[4行]

平行移動量を指定します。数値は10進数で記述されます。

t[0] t[1] t[2]

[5行]

マトリックス係数値を生成した回転ベクトル成分を指定します。10進数で記述されます。

vx vy vz

[6行]

親COORDINATEのインデックスを指定します。インデックスは記入順に0から始まります。親がワールド座標系の場合は自分自身のインデックスを記述します。

super

(6) COORDINATEに属するVERTEX又は、オブジェクトグループ

オブジェクト名のところでOGPファイルを指定した場合はCOORDINATEに属するオブジェクトグループが指定され、OGPファイルを指定しなかった場合はCOORDINATEに属するVERTEXが指定されます。

オブジェクトグループを指定する場合

オブジェクトグループはOGPファイル内で指定されるオブジェクトグループ名で表されます。オブジェクトグループはオブジェクトグループ数で指定した数分、横に続けて指定されます。改行はしてもしなくても構いません。


VERTEXを指定する場合

VERTEXはPLYファイル内で指定されるVERTEXのインデックスで表されます。VERTEXはVERTEX数で指定した数分、横に続けて指定されます。改行はしてもしなくても構いません。


(注)同一CODファイル内で上記の2つの指定法が混在することはありません。OGPファイルを指定した場合はすべてオブジェクトグループで指定し、そうでない場合はすべてVERTEXにより指定されます。

↑10 MOTファイル

RSD拡張ファイルで、アニメーション情報が記述されます。

(1) 全体構成

図 34 MOTファイルの全体構成

(2) ID

MOTファイルフォーマットのバージョンを表す文字列で"@MOTnnnnnn"(nnnnnnは番号)という形式です。現在のバージョン1.0では"@MOT970401" です。

(3) アニメーションタイプ

アニメーションの方法が記述されます。現状で対応しているものはCOORDINATEを変化させるタイプのみです。
    (COORDINATEの場合)
COORDINATE

(4) INDEX数

以下に記述される、INDEX & シーケンス数 & WORK TOPとシーケンスヘッダ情報を1組とした要素数が記述されます。以下、ここで指定された数分、(5)(6)の並びが繰り返されます。

INDEX数

(5) INDEX & シーケンス数 & WORK TOP

変化させる元データのインデックスと、シーケンスグループの数及び、WORKシーケンスのTOPポイント名が記述されます。元データのインデックスとは、例えば、アニメーションタイプがCOORDINATEならばCODファイル中で指定されるCOORDINATEのインデックスのことです。シーケンスグループの数とは以下に記述される、アニメーションパターンの数のことです。WORKシーケンスが存在しない場合、WORK TOPにはシーケンスのポイント名に使われていない適当な文字列が記述されます。


(6) シーケンスヘッダ情報

以下に示されるアニメーションパターンのヘッダ情報が記述されます。以下、予約語毎に記述方法を示します。


    START アニメーションシーケンスのスタートポイントを示す予約語です。
    スタートポイント名 シーケンスコントロール情報部に示されるスタートポイント名が記述されます。スタートポイント名は256文字以内の文字列で表現されます。
    ストリームID 16進数で記述されます。必ず0x??(7bit分)という形で記述して下さい。他のシーケンス因子とのストリームIDの一致を認識するためのビットパターンです。


    KEY2 キーフレームのトップポイントを示す予約語です。2つまで指定することが可能です。
    SEQ TOP1,2 シーケンスコントロール情報部に示されるキーフレームのトップポイント名が記述されます。TOP1に記述されたものはHMD変換時にシーケンスヘッダ情報として、下位16bitに記述され、TOP2に記述されたものは上位16bitに記述されます。指定すべきポイントが存在しない場合は、ポイント名として使用されていない適当な文字列が記述されます。ポイント名は256文字以内の文字列で表現されます。

(7) シーケンスコントロール情報

アニメーションの実際の動きが記述されます。構成は予約語の種類により異なります。また、位置情報として、任意の256文字以内のスタートポイントを間に挿入することができます。スタートポイントは挿入された次の行のアニメーション位置を示すことになります。以下に予約語毎に記述方法を示します。


    SEQ 予約語。これを用いることでシーケンスを表現しす。
    フレーム数 このキーフレームまでのフレーム数。
    アニメーションパケットタイプ アニメーションの補完タイプ。(詳しくはパラメータ情報で説明)
    アニメーションパケットタイプインデックス アニメーションパケット部で示されるアニメーシ ョンパケットのインデックス。


    GOTO 予約語。これを用いることでシーケンスの流れをジャンプさせることができます。
    ジャンプポイント名 ジャンプするシーケンス位置を256文字以内の文字列により示します。
    ストリームID 16進数で表記され、必ず0x??（7bit分）という形になります。他のシーケンス因子とのストリームIDの一致を認識するためのビットパターンです。


    END 予約語。これを用いることでシーケンスの流れを止めることができます。
    ストリームID 16進数で表記され、必ず0x?? （7bit分）という形になります。他のシーケンス因子とのストリームIDの一致を認識するためのビットパターンです。

(8) パラメータ情報

移動量などのパラメータ値が記述されます。パラメータのパケットタイプはHMD内で定められているものと同じです。パケットタイプはTYPEという予約語の後に続けて記述されます。パケットタイプの記述例を以下に示します。
TYPE ps0r0t0

    p パラメータの意。現在はこのタイプ以外ありません。
    s?r?t? ?の値によりパラメータのパケットタイプが異なります。0がくる場合はその部分のパラメータが存在しないことになります。

    現在パケットタイプは12種類がサポートされています。以下にそのパケットタイプと記述方法を示します。
    Scale 比:1 = 4096
    Rotation 単位:Degree, 360°= 4096

    (ps0r0t0) Dumy Matrix
    Dx Dy

    (ps0r0t1) Translation Linear
Tx Ty Tz

    (ps0r0t9) Translation(short) Linear
    Tx Ty Tz

    (ps9r0t9) Scale(one) Translation(short) Linear
    Tx Ty Tz Scale

    (ps1r0t0) Scale Linear
    Sx Sy Sz

    (ps0r1t0) Rotation linear
    Rx Ry Rz

    (ps9r1t0) Scale(one) Rotation Linear
    Rx Ry Rz Scale

    (ps0r1t1) Rotation Translation Linear
    Tx Ty Tz Rx Ry Rz

    (ps9r1t1) Scale(one) Rotaion Translation Linear
    Tx Ty Tz Rx Ry Rz Scale

    (ps1r1t1) Scale Rotation Translation Linear

    (ps0r1t9) Rotation Translation(short) Linear

    (ps1r1t9) Scale Rotation Translation(short) Linear
