rsdlink

↑1 概要

アーティスト向け３Ｄモデリングデータファイル(RSDファイル)を、libgsで扱える３Ｄモデリングデータファイル(TMDファイル)に変換します。
DOS版とSGI版があります。ここでは、1996/Apr/1付けの Version 3.7 に関する内容を記述しています。

↑2 使い方

rsdlink [options] rsd-names ...

rsdlink [options] rsd-names [options] rsd-names [options] ....

rsdlink [options] arg-files ...

rsdlink [options] prj-file


引数として指定した複数のRSDデータをリンクして１つのTMDファイルを作成します。各RSDデータ毎に倍率と平行移動量を設定することができます(例１参照)。
引数のRSD名がパスを含まない場合、まず現在のディレクトリ(.\)を探し、次に .\RSD ディレクトリを探します。
引数が多くなる場合など、引数をファイル(*.arg)に書いて与えることが可能です。RSDファイル名の".rsd"は省略可能ですが、引数ファイル名の".arg"は省略できません(例２参照)。
同様にプロジェクトファイル(*.prj)を直接与えることができます。この場合は、プロジェクトファイル中のRSDをすべて引数で与えた場合と同じになります。同時に-id オプションが指定されたとみなします。".prj"は省略できません。

↑3 オプション

-o file-name

出力ファイル名を指定します。デフォルトは"a.tmd"です。

-s factorまたは -sc factor

次の引数以降(*)のRSDデータを拡大縮小します。
倍率は２のn乗に丸められます。デフォルトは1.0です。TMDフォーマットでは座標値は16bit整数であるため、この座標系におさまるように、適当な倍率を設定しなければなりません。

-t x y z

次の引数以降(*)のRSDデータの座標値を平行移動します。デフォルトは(0 0 0)です。

-id PRJ-file

モデリングデータを管理するプロジェクトファイル(model.prj)を指定すると、TMDファイル中に生成される各オブジェクトに対してオブジェクトID番号の配列を作成します。結果はC言語のヘッダファイルとして現在のディレクトリに作成されます。出力ファイル名はTMDファイル名の拡張子を".h"にしたものです(例３参照)。

-info

変換中のオブジェクトの種類や頂点座標値、テクスチャ情報などの非常に詳細な情報を標準出力に出力します(例５参照)。

-v

ポリゴン数など変換に関する詳細な情報を標準出力に出力します。また、各RSD毎に、PS-X座標系におけるおおよその大きさ("Range : 頂点(x, y, z)の最小値-最大値")も出力されますので、ターゲットボックスで表示する前に、位置や大きさを確認することができます(例４参照)。

(*)注意 -s および -t は、再度指定されない限りそれ以降に現れるRSDすべてに対して有効です。

↑4 前バージョン(ver.3.65)からの主な改良点

  • より多くのRSDをリンクできるようになりました。これまでは500RSD程度を上限としていましたが、現在はメモリの許す限りリンク可能です。DOS版の場合、コンベンショナルメモリの空き容量によりますが、2000RSD程度まで可能です。
  • RSDファイル中に記述されたファイルが見つからない場合、まずファイル名をすべて大文字に変換して探します。それでも見つからない場合、すべて小文字に変換して探します(SGI版のみ)。

↑5 制約

現バージョンは以下の制約を持っています。

  • １つのRSDデータのポリゴン数が非常に多いとき、リンクできないことがあります。ポリゴン数の上限値は、頂点数や法線数、空きメモリの容量によっても変わりますが、約5000ポリゴンとお考えください(DOS版のみ)。但し、この制限は「１つのRSD」に対してのみ存在し、リンクするRSDの数、生成されるTMD全体のポリゴン数には実用上制限はありません。
  • プロジェクトファイル中に現れないRSDをリンクすると、ヘッダファイルには"-1"が割り当てられます。
  • プロジェクトファイルを指定する場合、同じRSDを２度以上指定すると、一つ目のRSDに対してのみID値が割り当てられ、２つ目以降は"-1"になります。
  • 入力RSDファイルは１行1024バイト以下でなければなりません。

↑6 注意

  • アニメーションツールおよびmktodが出力するTODファイルを利用したプログラムを作成する場合、平行移動(-t)や拡大縮小(-s)オプションは使用しないで下さい。TODファイルにはRSDオブジェクトに対する移動量や倍率が格納されているため、RSDからTMDに変換する際に移動や拡大縮小を行なうと、整合がとれなくなります。
  • 基本的に平行移動や拡大縮小は、dxf2rsd(-sc -t)やrsdform(-s -t)を利用して、RSD形式で行なうことをお勧めします。より正確で扱いやすいデータになります。
  • rsdlinkはファイル入出力を小さな単位で行います。そのため、ネットワーク上のファイルを入出力ファイルに指定すると、非常に時間がかかる場合があります。大きなRSDデータをリンクする際には、できるだけローカルディスク上で行ってください。

↑7 補足

  • .rsdファイルに記述されたテクスチャファイル(TIMファイル）は、RSDファイルと同じディレクトリ(.\)、または..\TIMディレクトリになければなりません。rsdlinkはこの順にTIMファイルを探します。
  • RSDがrsdlinkによってどのタイプのTMDに変換されるのかを、以下の表に記します。「マテリアル」や「光源計算」の有無などの項目は、RSDのMATファイルに記述されています(但し、「ポリゴンタイプ」はPLYファイルに数字で指定されています)。0x....はTMDパケットのヘッダです。なお、表では、半透明でない片面ポリゴンの場合のみ記しています。半透明や両面ポリゴンの場合は、ヘッダの値が変わりますが、パケットとしては同じものになります。詳細は、RSDフォーマットおよびTMDフォーマットのドキュメントを御覧下さい。

↑8 使用例

例1 基本的な使い方

        > rsdlink -v -o boxes.tmd box1 -s 2.0 -t 100 100 100 box1 box2 -t 200 -200 200 box3
この場合、以下の４つのオブジェクトが１つのTMDファイル(boxes.tmd)になります。
        
        box1		等倍のもの
        box1'		box1を２倍して(100 100 100)移動させたもの
        box2		box2を２倍して(100 100 100)移動させたもの
        box3		box3を２倍して(200 -200 200)移動させたもの

例2 引数をファイルにまとめる方法

次のように引数をファイルにまとめておくことでも同様の指定が可能です。
        > type test.arg
        box1
        -s 2.0 -t 100 100 100 box1 box2
        -t 200 -200 200 box3
        > rsdlink -v -o boxes.tmd test.arg

例3 プロジェクトファイルの読み込みとID配列の作成

プロジェクトファイル("model.prj")はレイアウトツールが生成する、オブジェクトのIDテーブルです。
        > type model.prj
        @PRJ940701
        # Next available ID
        7
        # IDObject Name
        1	head.rsd
        2	body.rsd
        3	l_arm.rsd
        4	r_arm.rsd
        5	l_leg.rsd
        6	r_leg.rsd
        
        上のようなファイルがあるとき、
        
        > rsdlink -o robo.tmd model.prj
        
        または、
        
        > rsdlink -o robo.tmd -id model.prj body head l_arm r_arm l_leg	r_leg
を実行すると、robo.tmdが生成されるとともに、下記の内容のrobo.hが生成されます。各オブジェクトについて、TMD内に現れる順に、そのIDが配列の要素として記入されます。アプリケーションプログラムからTMD内の各オブジェクトにアクセスする際にご利用になれます。
        
        > type robo.h
        /*
         *	TMD ID List for "robo.tmd"
         *
         *	 Created by rsdlink(v3.7) at 10:10 03/16/96
         *
         *	(C) 1994-1996 Sony Computer Entertainment Inc. All Rights Reserved.
         */
        int robo_list[] = {
        	1,	/* body */
        	0,	/* head */
        	2,	/* l_arm */
        	3,	/* r_arm */
        	4,	/* l_leg */
        	5,	/* r_leg */
        };

例5 -infoオプション使用時の出力例

-infoオプションにより、実際にどのような内容のTMDデータに変換されたかを確認することができます。
        
        > rsdlink -info box
        
                Input RSDs      : 1 object(s)		TMD中のオブジェクト数
                        RSD[ 0] = "box"			各RSD名
                Total primitives:    12			合計プリミティブ数
                Total vertices  :     8			合計頂点数
                Total normals   :    12			合計法線数
         -----------------< box >-----------------
        = [  0] FLAT TEX 3-POLY(0x24000507) LIGHT: ON = 
                Vert-0: (  -150,   -150,   -150) (#2)
                Vert-1: (   150,   -150,   -150) (#6)
                Vert-2: (  -150,    150,   -150) (#0)
                Norm-0: (     0,      0,  -4096) (#0)
                UV 0-2: (  0   0) ( 47   0) (  0  47)
                Pixel mode  : 4bit CLUT : (x y)=(  0 480)
                Texture Page: 10  Texture No. :  0 
        = [  1] FLAT TEX 3-POLY(0x24000507) LIGHT: ON =
        		：
各プリミティブ毎に、
        
        = [  0] FLAT TEX 3-POLY(0x24000507) LIGHT: ON =
のように、[ポリゴン番号]、 フラット／グーロー(FLAT/GOURAUD)、テクスチャの有無(TEX/NO TEX)、半透明処理のON/OFF(TRANS)、両面/片面(TWO-SIDED)、グラデーョン(GRADATION)、プリミティブの種類(3-POLY, 4-POLY, LINE, SPRITE）、プリミティブヘッダの16進表示(0x...)、光源計算のON/OFF(LIGHT: ON/OFF)が表示されます。
引続き、そのプリミティブを構成している各頂点の座標値が
        
        Vert-0: (  -150,   -150,   -150) (#2)
のように表示されます。(#...)はPLYファイルで用いられている頂点番号です。
法線も同様に表示されます。
        
        Norm-0: (     0,      0,  -4096) (#0)
(RSDでは、通常、法線は大きさ1に正規化されていますが(この場合、(0, 0, -1.0))、TMDでは浮動小数点は4096を1とした値に換算されるため、上記のようになります。)
その後、テクスチャのUV座標や色などのマテリアル情報が表示されます。
