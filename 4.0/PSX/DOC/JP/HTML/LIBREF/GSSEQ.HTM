GsSEQ

ＨＭＤアニメーションシーケンスポインタ

構造 

typedef struct {
	unsigned long 	rewrite_idx;
	unsigned short 	size,num;
	unsigned short 	ii;
	unsigned short 	aframe;
	unsigned char 	sid;
	char		speed;
	unsigned short	srcii;
	short		rframe;
	unsigned short	tframe;
	unsigned short	ci,ti;
	unsigned short	start;
	unsigned char	start_sid;
	unsigned char	pad;
} GsSEQ;
メンバ 
rewrite_idx	アニメーションにより更新されるセクションおよびオフセットが格納される、上
		位８ビットがプリミティブヘッダ内のオフセットでありセクションの更新され
		るセクションの先頭アドレスを特定する。下位２４ビットは、そのセクション内
		の相対オフセットである。（ワード単位）
size		次のシーケンスポインタが格納されている領域までのサイズ
num		このシーケンスポインタに格納されているシーケンスの数
ii		補完後のパラメータを記憶させる領域を示すインデックス
		（パラメータセクション内の相対オフセット）
aframe		シーケンスの総フレーム
 		フレームアップデートポインタにより自動的にデクリメントされる。
		０でシーケンスは停止。シーケンスのENDアトリビュートでも０になる。
		0xffffを設定することでデクリメントを禁止できる。エンドレス再生の場合に
		用いる。
sid		現在再生中のシーケンスの現状のシーケンスID
		シーケンスIDとは０から１２７までの値をとりシーケンスのジャンプやENDの
		動作を行う際、マッチングが取られる。SIDを利用してシーケンスの流れを制御
		可能。シーケンスコントロール記述子でジャンプ記述を行う際マッチ用のSIDと
		飛び先のSIDを定義する。マッチ用SIDを０にすることですべてのSIDとマッ
		チさせることが可能。
speed		シーケンスの再生速度を制御する。0x10で標準速再生。0x7fで８倍速、0x01
		で1/16倍速となる。最上位ビットは逆転再生のためのビットである。実装は
		rframeからspeedを１フレーム毎に引き算しそれを新たなRFRAMEの値にす
		ることで行われる。
srcii		iiに指定すべきデータを保持する。これはあらかじめデータに埋め込まれてい
		るパラメータセーブ用の領域をインデックスで保持している。
rframe		キーフレーム間の内挿係数 0でSRC FRAME,rframe==tframeで DST FRAME
		となる。12bit固定小数点で表される。
tframe		キーフレーム間の距離を表す。12bit固定小数点で表される。シーケンスコント
		ロール記述子にあるtframeは８ビットでありGsSEQのtframeに更新される
		時に４ビット左にシフトされる。
ci		ソースキーフレームを保持するパラメータへのインデックス
		（パラメータセクション内のワードオフセット）
ti		デスティネーションキーフレームを保持するパラメータインデックス
		（パラメーターセクション内のワードオフセット）
start		シーケンスの開始インデックスを保持している。
		シーケンスを開始するためにはstartをtiにコピーしrframeに０をいれる。
start_sid	シーケンス開始時のSIDを保持している。
		シーケンスを開始する時にstart_sidをsidにコピーする。
traveling	キーフレームの切り替え時に０にクリアされる。
		このメンバはプログラマがいろいろな目的のために使用することができる。
解説
GsSEQはフレームアップデートドライバの内部状態を保持する。このメンバを実行時に書き換えることによってアニメーションを動的にコントロールすることができる。
GsSEQはＨＭＤデータ内に存在し、GsLinkAnim()によってＨＭＤデータの実体を指すようになる。
メンバの中でフレームアップデートドライバによって自動的に更新されるものと、参照のみ行われる物に区別される。参照のみ行われるメンバは、rewrite_idx,size,num,ii,speed,srcii,start,start_sidである。
それ以外はフレームアップデートドライバの中で書き換えられる。
